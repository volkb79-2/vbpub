# Nyxloom installed CLI reference

This is the canonical contract for the four entrypoints shipped in the Nyxloom wheel. `CliRegistry` declarations in `src/nyxloom/cli_registry.py` are the source of truth for parser behavior, generated help, and dispatch. Update this document in the same change as any command or option change.

## Current command and option contract

### Command ownership

| Executable | User and data target | Daemon / registration boundary |
|---|---|---|
| `nyxloom` | Project authoring: `init`, `onboard`, project-local `lint`, and managed `backlog` files in the current project checkout. | Works without project registration or a running daemon. |
| `nyxloom-harness` | Searches, discovers, and extracts Claude Code, Codex, OpenCode, and Reasonix session files or stores. | Reads the selected harness source; does not initialize Nyxloom host state or require registration/daemon availability. |
| `nyxloomctl` | Local host operator, administrator, or developer: registry, workflow state, local daemon operation, routes/models, credentials, migrations, and diagnostics. | Calls local Nyxloom modules and state; it is not an HTTP client for remote admin. Most commands work without the daemon. |
| `nyxloomd` | Service manager starting the resident daemon in the existing container. | Bare invocation starts the foreground daemon. `--help` and `--version` exit before service initialization; unknown arguments are rejected. |

The dashboard remains the existing HTTP/SSE client. `nyxloom lint` checks the current project or explicit handoff paths; `nyxloomctl lint` scans every registered project. Neither path requires the daemon.

### Invocation, output, and shared options

| Surface | Accepted form and actual behavior | Side effects / compatibility |
|---|---|---|
| Root help | `nyxloom --help`, `nyxloom-harness --help`, `nyxloomctl --help`; a bare invocation prints complete help and exits 0. | No project or host-state writes. `-h` is intentionally unsupported. |
| Nested help | `help`, `help VERB`, or `VERB --help` at each registry depth, including `backlog new --help` and `project add --help`. | Generated from the same registry as parsing; exits 0 without initializing persistent logging. |
| Version | `--version` or `version` for each human CLI. | Both print the same Nyxloom distribution identity with the executable's truthful command name; display only. |
| Parse failure | Unknown commands/options, malformed arity, bad choices/types, and prohibited combinations exit 2 and show relevant generated help. | No handler dispatch, project write, or persistent host log. |
| Global placement | Common options work before the command or after the complete leaf path. Command-specific options belong after the complete leaf path. | There is no second parse or compatibility-forwarding path. |
| Confirmation | Nyxloom reports which actions mutate, but does not enable generic `--yes`. | Existing explicit command, actor/role, transition, `--apply`, confidence, and store safeguards authorize the operations. |
| `--log-level LEVEL` | `error`, `warn`, `info`, or `debug`; explicit choice overrides `NYXLOOM_LOG_LEVEL`. | Diagnostic output control; no domain-state change. |
| `--quiet` | Warnings and errors only. | Mutually exclusive with `--log-level`, `--debug`, and `--verbose`. |
| `--debug` / `--verbose` | Enable debug diagnostics. | Same verbosity control; mutually exclusive with other verbosity controls. |
| `--debug-raw` | Show raw data on diagnostic paths that support it, without redaction. | Diagnostic-only; may expose sensitive diagnostic values. |
| `--traceback` | Show tracebacks for unexpected command failures. | Preserves the former explicit traceback behavior; separate from verbosity. |
| `--color` / `--no-color` | Force or suppress terminal color where the command renders color. | Mutually exclusive; automatic behavior respects the output TTY and `NO_COLOR`. |

`--json` is command-scoped; it appears only where that command has a defined machine-readable output. Progress controls and `--yes` are not advertised by these Nyxloom commands.

| `nyxloomctl finding list [--project-id ID] [--kind KIND]` | List findings from one selected store or registered projects. | Read-only. Explicit project ID addresses that store key even if the project is not registered. |

### Command migration map

| Old installed path | Current path | Compatibility and behavior |
|---|---|---|
| `nyxloom init`, `nyxloom onboard`, `nyxloom backlog *` | Same `nyxloom` paths. | Kept as project-local authoring. `backlog new --interactive [TITLE]` and `backlog edit ENTRY_ID` are added. |
| `nyxloom lint [paths]` with no paths | `nyxloom lint` for the current checkout; `nyxloomctl lint` for all registered projects. | The old all-project scope moves; local lint no longer depends on registry state. Explicit handoff paths remain local. |
| `nyxloom extract*` | `nyxloom-harness extract*` | Old paths are removed without forwarding aliases. |
| `nyxloom project`, `status`, `doctor`, `resync`, `render`, `tick`, `migrate-store`, `auth`, workflow/intake/finding/model/route commands | `nyxloomctl` with the same command paths after the executable name. | Old paths are removed without forwarding aliases; commands remain local operations. |
| `nyxloom daemon [--foreground]` | `nyxloomctl daemon`; service manager uses `nyxloomd`. | `--foreground` is removed because daemon mode already runs in foreground. The container invokes the installed binary directly. |
| `nyxloom gate` | Removed. | It had no child action; project gates use each project's declared `run-gate.py`/Assay lane. |
| `-h` | Use `--help` or `help [VERB]`. | `-h` is rejected, following cli-extended's public grammar. |
| `--debug` as traceback request | `--debug`/`--verbose` sets verbosity; `--traceback` requests unexpected-failure tracebacks. | Scripts that used the old meaning should change the flag explicitly. |
| `nyxloom backlog list` when INDEX.md is absent | Same path. | Now renders in memory and stays read-only; use `backlog index` to write the index. |

### Option declaration matrix

The executable name is included in every valid command path. Each row is a command-local declaration, accepted after that complete leaf path (and before or after its positionals); it is not a root option or an option delegated to sibling commands. Shared help, logging, color, traceback, and version controls are in the invocation table above and may precede or follow the complete command. The final column states the state and external-effect boundary when that option is used; command-level effects are also summarized in the inventory above. `None` means no override is passed to the handler; the omitted-value cell states the resulting command behavior. For selection controls, the profile defaults are explicit below. Value-taking options may be repeated and use the last value unless marked repeatable; flags are idempotent when repeated; append options accumulate values.

#### `nyxloom-harness extract` option groups and the `successor` preset

`extract --help` shows every option in exactly one of five groups, in this order (pinned by `tests/test_cli_extract_groups.py`):

1. **Source & range**: `--opencode-session`, `--format`, `--epochs`, `--since`, `--since-file`, `--until`, `--max-compactions`, `--max-time-minutes`, and the follow controls (`--follow`, `--interval`, `--bell`, `--on-attention`, `--notify-project`, `--attention-min-chars`).
2. **Content selection**: `--profile`, `--answer-length`, `--max-checkpoints`, `--max-words`, `--include-thinking`, `--show-api-errors`, `--show-compaction-content`, `--tool-calls`, `--tool-errors`, `--show-tool-calls` and `--show-tool-call-intent` (deprecated aliases), `--strip-stale-wakeups`, `--redact-pattern`.
3. **Rendering & compression**: `--strip-cd-prefix`, `--no-strip-cd-prefix`, `--path-aliases`, `--edit-calls`, `--read-calls`, `--effect-calls`, `--timestamps`, `--timestamp-gap-minutes`, `--blank-lines`, `--gap-marker`, `--min-gap-records`, `--show-gap-source`, `--show-timestamps`, `--timestamp-format`, `--extract-metadata`.
4. **Derived sections**: `--ledger`, `--effect-pattern`, `--no-default-effect-patterns`, `--stop-state`, `--preset`, `--successor-brief`, `--order`, `--brief-max-chars`, `--task`, `--task-file`.
5. **Output**: `--json`, `--render-markdown`, `--highlight`.

`--preset successor` is a named bundle. It expands to `--profile all --tool-calls intent-or-call --tool-errors show --edit-calls collapse --read-calls collapse --effect-calls always --timestamps gaps --path-aliases auto --strip-cd-prefix --ledger`. An option the caller passes explicitly overrides the bundle (`--no-strip-cd-prefix` turns the cd strip off). `--successor-brief` implies the preset and adds the brief document (original brief, stop state, `--order`). The preset is Claude Code only, and cannot be combined with `--json` or `--follow`.

### Shared-option effects and cross-option rules

| Option or combination | Validity and behavior |
|---|---|
| `--log-level`, `--quiet`, `--debug`/`--verbose` | One verbosity control per invocation. `--log-level` choices are closed; `NYXLOOM_LOG_LEVEL` is the fallback source. |
| `--debug-raw`, `--traceback` | Diagnostic controls. Raw debug is supported only where a handler emits those values; traceback changes unexpected exception presentation, not handled refusals. |
| `--color` + `--no-color` | Mutually exclusive; color is applied only by output paths that render it. |
| `--since` + `--since-file` | Mutually exclusive on cursor-capable extraction paths. Markers are adapter-specific. |
| `--render-markdown` + `--highlight` | Mutually exclusive output modes. `--highlight` preserves source markup; rendering consumes it. |
| `--show-tool-call-intent` without `--show-tool-calls` | Refused; intent is a detail of visible tool calls. |
| Text-only extraction controls + `--json` | Task banners, ledger, and incompatible text rendering controls are refused in JSON mode; output stays machine-readable. |
| `--follow` controls | `--interval`, `--bell`, `--on-attention`, `--notify-project`, and `--attention-min-chars` require follow. Interval must be positive. Fixed-end/epoch/task controls are refused where they contradict a growing stream. |
| `extract-lossless --redact-pattern` | Unsupported and rejected because lossless output is verbatim. Compact/debug extraction retain redaction. |
| `doctor --write` | Requires `--rebuild`; either rebuild flag conflicts with `--liveness`. |
| `resync --apply-content-merges` | Requires `--apply`; the latter remains the explicit transition authorization. |
| `capability-map refresh --dry-run --emit-findings` | Rejected because it asks a read-only preview to write findings. |
| `finding record --field KEY=VALUE` | Requires a non-empty key and `=`; malformed values are rejected with command help before the handler runs. |
| `backlog new TITLE` and `--interactive` | TITLE is required in scriptable mode and optional in interactive mode. Existing field flags seed prompts; empty optional prompt answers clear fields. |
| `backlog edit` | Requires interactive TTYs and the optional extra. Candidate schema validation, cancellation, and prompt failures leave entry and index unchanged. |
| `--yes` | Not accepted. Mutating labels describe effects; Nyxloom's existing safeguards remain the consent boundary. |

## CLI ownership boundaries

The installed package currently exposes one console script,
`nyxloom = nyxloom.cli:main`. `nyxloom daemon` starts the resident daemon
through that same entry point; there is no separate `nyxloomd` console script
in `pyproject.toml`. The primary CLI dispatches to local Python handlers and
host state. It is not currently an HTTP client of the daemon.

These are separate choices: logical command grouping, separate user-facing
console scripts, a service-specific `nyxloomd` entrypoint, and separate
distributions. Adding scripts to the existing wheel does not reduce that
wheel's dependencies. Separate distributions add versioning/release
coordination and require code/dependency ownership changes. The initial
parser-adoption decision applies to the current primary `nyxloom` entry point.
The approved target has three user-facing console scripts in the same wheel:
`nyxloom` (local trove authoring), `nyxloom-harness` (AI-harness workflows),
and `nyxloomctl` (all local host-control, administration, and developer
diagnostics). `nyxloom` and `nyxloom-harness` must work with the daemon
unavailable. The dashboard remains the current HTTP/SSE client; remote
`nyxloomctl` transport/operations require a separate design. D-009 approves a
service-only `nyxloomd` console script for the existing daemon container.
These target entrypoints are not implemented in this audit. D-013 approves
removing the old host-control spellings from `nyxloom`; the adoption must
publish an old-to-new command migration table and must not keep forwarding
aliases in a second registry.

## Command-design review and backlog recommendations

The table distinguishes shipped behavior from the operator-approved adoption
target. Decisions D-001 through D-016 now record the approved grammar,
command boundaries, compatibility break for moved commands, optional shared
prompt API/extra, daemon launch surfaces, managed backlog create/edit as the
first interactive authoring workflow, exact create/edit spellings, and the
project-local versus host-wide lint boundary. None has been implemented in the
runtime yet.

### Journeys checked

- **Project author:** `init` or `onboard` scaffolds a project, `project add`
  registers it, `lint` checks handoffs/configuration, and `backlog` maintains
  project work. Init and onboard have distinct setup depths; registration is
  a separate explicit step. NL-19's context-pack workflow overlaps author and
  carver preparation but remains in `tools/pack.py` with unresolved root and
  score inputs.
- **Operator and recovery:** `status`/`doctor` diagnose, `resync` plans or
  applies task state, `pause`/`resume` guard operation, and `tick` or `daemon`
  drive reconciliation. The verbs separate observation, repair, control, and
  scheduling. Unknown project filters and ignored safety options are the
  defects proposed in D-003/D-004.
- **Manual controller:** `project list`, `status`, `merge`, `reject`, `decide`,
  and `backlog` support inspection and recording controller work. NL-18
  identifies a gap: a task created outside daemon dispatch has no command to
  enter the state model, so it is absent from those read paths.
- **Automation:** selected commands expose JSON (`extract`, `extract-report`,
  `extract-sessions`, and `events`); other commands are text only. Parser
  errors use 2 while handler failures commonly use 1 or 2, so a follow-up must
  preserve command-specific exits and pin JSON schemas. No interactive prompt
  is a general authorization contract; operation-specific safeguards remain
  the consent boundary.
- **Inspection:** `routes`, `free-models`, `capability-map`, findings, events,
  leases, digests, and session extraction cover configuration, model/catalog,
  workflow, and transcript views. Capability JSON is not a global format;
  session reports and event output have distinct schemas. NL-20's process
  history would overlap run-gate/cgprofile and extract-report.
- **Release operator:** the installed Nyxloom CLI has no release/publish verb;
  the repository's CMRU workflow releases the Nyxloom wheel. Do not fold
  build/publish or OCI lifecycle into the project-operator CLI as a side effect
  of parser adoption. NL-15/NL-16 remain release-boundary decisions.

## cli-extended boundary and package plan

The root repository marks libraries/cli-extended independently packageable.
Nyxloom pyproject discovers packages under src/ and currently does not include
or depend on cli_extended; nyxloom/cmru.toml releases only the Nyxloom wheel.
Thus cli-extended is not in the current wheel. The approved target bundles
its import package into the Nyxloom wheel, without a separate library release
or runtime distribution dependency.

| Library contract | Current mismatch | Follow-up requirement |
|---|---|---|
| Help | -h/--help at parser levels, custom grouped top help, no help VERB, nested parser errors omit complete help. | Registry-generated --help, help [verb], bare invocation, and command-local errors. Remove -h as approved in D-001. |
| Version | Flag prints nyxloom VERSION; verb prints VERSION. Both bootstrap logging first. | Use CliIdentity.from_distribution("nyxloom"), same line for both, and side-effect-free display paths. This follows approved full alignment. |
| Global options | --debug currently means traceback-on-exception, not verbosity; NYXLOOM_LOG_LEVEL is env-only. --version is an argparse action. Both root options must precede verb. | D-006 is approved: adopt cli-extended --log-level/--debug verbosity, preserve current traceback behavior under --traceback, and give the explicit option precedence over the environment. |
| Aliases/nesting | Option aliases work; no Nyxloom verb aliases. Top help group map is handwritten separately. | One registry owns nested paths/help/dispatch; do not reparse or maintain parallel command lists. |
| Mutation/confirmation | mutating=True enables --yes and states confirmation is required. Nyxloom mutations already rely on explicit verbs, state checks, --apply/confidence opt-ins, role checks, or store protections. | Library API must separate “mutates state” from “requires interactive confirmation/--yes”. Existing safeguards are approved consent; do not misdeclare or add a second prompt. |
| JSON/progress | Nyxloom JSON is command-specific; it has no general progress output. cli-extended VerbSpec defaults include_json and include_progress to true. | Set both false where no real schema/progress contract exists; enable only defined machine-readable or progress surfaces. |
| Color | ANSI/Markdown belongs mainly to session extraction. Other commands are plain output. | Keep per-action output policy and NO_COLOR behavior; document CliOutput.color_enabled(stream) boundary. |
| Shared options by action | --log-level applies to all commands; JSON currently applies only to extract, extract-report, extract-sessions, and events; color only to extract renderers; progress has no current implementation; confirmation has no generic prompt call. | Add logging verbosity globally. Do not inherit JSON/progress/--yes on unrelated actions. Keep command-specific output schemas and existing state safeguards. |
| Errors/cancellation | Parser uses exit 2; handler failures are usually 1/2; --debug changes exception presentation. Cancellation is not a uniform command contract. | Map current refusals deliberately; cancellation should use 130 without swallowing application errors. |
| Identity/package | Source sentinel can be 0.0.0+unknown; wheel metadata is authoritative. | Bundle library in Nyxloom wheel and use Nyxloom metadata. |

The follow-up installed-wheel oracle must build Nyxloom's wheel, install it in
an isolated environment outside this checkout, make the checkout unavailable
on sys.path, then run nyxloom --help, nyxloom version, representative nested
help, and import cli_extended. Assert cli_extended.__file__ is inside the
installed wheel and identity is Nyxloom distribution metadata. This audit
does not change packaging.

## Dispositions

| Surface | Recommendation | Current-to-target change and compatibility |
|---|---|---|
