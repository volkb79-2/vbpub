## Decided

| id | Decision | Reason |
|---|---|---|
| A-001 | Name is **`assay`**; distribution stays estate-local wheels | PyPI `assay` is a third-party empty reservation (v0.0, zero files, homepage misprinted as python-skyfield). The estate publishes nothing to PyPI and already ships `topos` against a *real* 5-release collision. If a public index name is ever needed, publish under a different distribution name and keep `assay` as the import name. |
| A-002 | Build as a **new standalone project**; nyxloom untouched | Removes the sequencing conflict that deferred P90 behind nyxloom's core redesign. nyxloom's own migration is P90c, later. |
| A-003 | **v1 includes mutation** | Owner's call over the recommendation to defer it. |
| A-004 | **Mutation is sequenced last** in the carved series | Mitigates A-003's risk structurally: the adapter protocol is settled by coverage and canary first, so the most language-idiosyncratic component must fit the protocol rather than reshape it. |
| A-005 | **Zero runtime dependencies** — stdlib only | Makes the standalone claim near-unfalsifiable and the scratch-venv O1 test trivially offline. assay consumes coverage.py's *output*; it never imports coverage.py or pytest. |
| A-006 | Coverage parsing lives in a **parser registry keyed by format**, not in the adapter | Format and language are independent axes: lcov is emitted by five languages, TypeScript emits three formats. Binding them copies the lcov parser into every adapter — the four-copies divergence one layer down. |
| A-007 | Lane **declares** the coverage format; assay **sniffs** the artifact and **refuses on mismatch** | §4.2a prefers DERIVE then READ. The format is a fact of the lane's own argv, so it is read; sniffing is the cross-check that catches a lane whose argv changed and was not updated. |
| A-008 | `FileCoverage.excluded` is `frozenset | None`; `None` means the **format cannot express exclusions** | Otherwise a Go lane reports "0 changed lines excluded — verified" when the format simply cannot say. NO-MEASUREMENT discipline one level down. |
| A-009 | `LanguageAdapter` protocol defined in v1; **Python + Go adapters**, Go proven by committed fixtures | Keeps `ast` and `.py` globs out of the core (P90 O3's negative), so a third adapter is additive. Go is the honest second because its profile is block-based, not line-based. |
| A-010 | `inject_import_break` / `inject_uncovered_line` are **pure** — `(text) → (text, description)` | nyxloom's versions write the file themselves; pure adapters are testable with no filesystem. A straight improvement on the extracted code. |
| A-011 | `generate_mutants` may return `UNSUPPORTED` → **`INCONCLUSIVE_NO_MUTANTS`, never green** | TESTING-METHODOLOGY already names this outcome for zero selected mutants; an adapter that cannot mutate inherits it rather than inventing one. |
| A-012 | **Delete** nyxloom's `_derive_test_command` (`src/<mod>.py → tests/test_<mod>.py`) | §4.2a anti-pattern #2 — the consumer inventing on absence. It is a naming convention, not a language fact. The lane declares the argv. The only place v1 deliberately does not take the union. |
| A-013 | Adapters **may shell out**, but must declare it in `external_tools`; a missing tool is NO_MEASUREMENT for that check | Go's `has_executable_code` genuinely needs a parser. Declaring makes prerequisites checkable up front instead of failing mid-run. |
| A-014 | Lane file is **`assay.toml`** at project root | ciu reads nothing today — `ciu test` is explicitly a sketch that "does not exist today". Naming for an absent consumer repeats the "implies capability it does not have" failure. Neutrality is preserved in the schema (`[…where]`), not the filename. |
| A-015 | Lane file structure **is D7's three-question split**: top level = WHAT, `[…judge]` = HOW, `[…where]` = WHERE | Makes tool independence visible in the file's shape. A project adopting only one tool writes only its table. |
| A-016 | `source_roots` is **required, no default**; a nonexistent root is `BAD_LANE_CONFIG` at load | All four copies ship §4.2a anti-pattern #1, and a typo'd root matches nothing → 0/0 PASS forever, a laundering gate none of them guards. |
| A-017 | **Declared rigor is enforced**: R1 requires coverage config, R2 requires mutation config, R3 requires canary config, or the lane fails to load | A lane claiming a rigor level it cannot exercise is the lane-table-implies-capability failure in data form. |
| A-018 | `allow_excluded` is a **required** per-lane field | Resolves a genuine policy contradiction in the union: topos's failure text tells users to *add* `# pragma: no cover`; nyxloom and dstdns fail the gate for it. Each project must state its position at adoption. |
| A-019 | Lane `env` is **declared-only**, with an explicit `env_passthrough` allowlist | "Augment the ambient environment" is incoherent at S3, where the container already does not inherit it — the same lane file would mean different things at different scopes. The base is a fact of WHERE. |
| A-020 | `budget` exceeded is its **own outcome** (`BUDGET_EXCEEDED`, exit 4), not NO_MEASUREMENT | Different diagnosis, different remedy, different retry policy: NO_MEASUREMENT is deterministic and must never be auto-retried; a budget overrun is load-dependent and may be. |
| A-021 | **Six exit codes**: 0 PASS / 1 FAIL / 2 ERROR / 3 NO_MEASUREMENT / 4 BUDGET_EXCEEDED / 5 INCONCLUSIVE | Each already exists as a concept in the estate; none invented. 2–5 are all not-a-pass and all block a merge. |
| A-022 | A **required `reason_code`** enum names the cause on every non-PASS outcome | Gives cause-level specificity without proliferating exit codes. Answers "DIRTY_TREE vs BASE_IS_HEAD vs EMPTY_COVERAGE" without renaming the outcome class. |
| A-023 | Rollup precedence `ERROR > NO_MEASUREMENT > BUDGET_EXCEEDED > FAIL > INCONCLUSIVE`; PASS only if every declared claim passed | ERROR and NO_MEASUREMENT invalidate everything computed beneath them; a truncated run's FAIL may be partial. |
| A-024 | Artifact carries **one `claims[]` entry per declared rigor level**, not a flat verdict | "Record the evidence actually obtained rather than reducing quality to one coverage percentage." Also gives Tier 2/3 evidence somewhere to live. |
| A-025 | **No percentage is emitted when no measurement happened** — the coverage block is omitted, not zeroed | Emitting `pct: 100.0` beside NO_MEASUREMENT rebuilds the original ambiguity inside the artifact for any consumer that reads `pct` and ignores `outcome`. |
| A-026 | A **legitimate 0/0 pass emits the numbers plus a `considered` count** | srdm's fix: an empty denominator must explain itself in prose rather than being textually identical to a broken measurement. |
| A-027 | Verdict artifact is **emitted on every outcome, including ERROR** | Precedent: the remote-mutation-audit worker emits `summary.json` "even when a baseline, mutant, or teardown fails". Without it, "assay errored" and "assay never ran" are indistinguishable. |
| A-028 | Artifact is written **only when an explicit path is given** (`--verdict-json PATH`, or `-` for stdout) | No invented paths, no uninvited writes into a repo. The exit code always works standalone, so a consumer without the flag still gates correctly. |
| A-029 | Consumers read a **JSON Schema shipped as data**; nothing links against assay | D7's "judged-result contract, so `ciu test` can surface a verdict without linking against it". nyxloom's `GateResult` is a strict subset — six keys. |
| A-030 | **assay and ciu stay separate tools**; `ciu test` (if ever built) wraps assay via the verdict artifact | The boundary is topological, not preferential: assay runs **inside** the test container next to the coverage artifact; ciu runs **outside** issuing `docker run`. Merging ships an orchestrator into every test image or splits back in half at runtime. Ergonomics are identical either way. |
| A-031 | assay ships its **own CLI** (`assay run/verify/mutate/lanes`) | Forced by P90 O1 (a CLI invocation is the oracle), by all four existing copies, and by self-hosting, which cannot route through ciu without circular adoption. |
| A-032 | Evidence is carried in **three tiers**: COMPUTED / ADJUDICATED / ATTESTED | Keeps §0 intact while letting the whole evidence catalogue be expressed. Tier 2's judgement is the tool's; Tier 3 is never verified by assay. |
| A-033 | **Tier 3 (attested) slot, commit-binding and staleness check ship in v1** | The slot must exist from day one or retrofitting means a schema bump across every adopted consumer. Staleness is the cheap half and the half that gives an attestation teeth: assay cannot judge a review, but it can prove one is stale. |
| A-034 | **Tier 2 (adjudicated) slot ships in v1 with zero integrations** | Same schema-shape reasoning; costs almost nothing to reserve. A missing or crashed scanner must be ERROR or NO_MEASUREMENT, never PASS. |
| A-035 | Two guards **beyond the four-way union** ship in v1: `EMPTY_COVERAGE` and load-time `source_roots` validation | A zero-file coverage artifact currently renders 0% → FAIL, a *wrong diagnosis* ("add tests" meaning "your `--cov` path is broken"). A typo'd source root passes forever. Both were found by applying the §4.2a test to the existing copies. |
| A-036 | Runner flags **may be appended by the caller** and are recorded as `argv_declared` / `argv_appended` / `argv_effective`; `argv_modified: true` is set, and the lane must carry `allow_argv_append` | Owner's call, with transparency as the condition. assay still **never derives** flags — deriving them is impact-based selection, which is the caller's domain. |
| A-037 | Adoption order **topos → ciu → dstdns**; netcup-api-filter, cmru, mdt later | topos is the only migration with a baseline: old and new gate run on the same commits and must agree, so union fidelity becomes mechanical rather than a review question. |
| A-038 | **Adoption declares and verifies; it does not remediate** | Changed-line coverage is a ratchet, not an audit — netcup can adopt `fail_under = 100` at 30.17% global coverage. Conflating adoption with test-writing turns each consumer into an open-ended project instead of a bounded swap. |
| A-039 | Canary results at adoption are **diagnostic output**, and feed separate per-project remediation packages | A LAUNDERS finding measures a project's floor; fixing it is a different job with a different owner. |
| A-040 | **One gated lane, `tester-unified`**; the standalone claim is proven by a scratch-venv test *inside* it | "Greens from the interactive cockpit are explicitly not a ship signal." A bare-pytest lane manufactures exactly that pathway. Bare `pytest` stays a documented developer convenience, explicitly not evidence. |
| A-041 | The **independent oracle is pytest over expected-verdict fixtures**, not assay | Breaks the self-hosting circularity: a universal-PASS bug fails every fixture assertion at once. `assay verify` is a second, explicitly non-independent layer. |
| A-042 | Fixtures are **hello-world Python and Go projects** with committed pre-generated coverage artifacts; git-state fixtures materialised in `tmp_path` | Parsing profiles and injecting into Go source are pure text operations, so the suite needs no Go toolchain — mandatory, since this devcontainer has none. A regeneration script is documented for a host that has Go. |
| A-043 | **Go stays out of the devcontainer.** Promote srdm's `gate/Dockerfile` `unit` target to `vbpub/tester-unified-go` | The cockpit having no Go toolchain means it "cannot even pretend" to produce a ship signal — a property adding Go would destroy. The `unit` target is generic (pinned `golang:1.25`, run-uid identity, prewarmed std cache, `GOTOOLCHAIN=local`, caches outside the bind mount); the `e2e` target (systemd-in-Docker) is srdm-specific and layers on top. `tester-unified` untouched, as its own reasoning demands. |
| A-044 | A **`tools/go` wrapper** against `tester-unified-go` gives local ergonomics at the image's pinned version | Recovers the entire agent-productivity argument for a devcontainer toolchain, without the cockpit hazard, and makes the version explicit at the call site rather than ambient. |
| A-045 | A **matrix lane is two lanes**, not a `matrix` field | netcup's `[gates.unit]` loops one argv over two images. They have different WHERE and can render different verdicts; a loop that hides which image failed is the opacity being removed. |
| A-046 | **A lane file declares what exists, not a target architecture** | dstdns's five-lane table is aspirational; only two lanes are real. Writing the other three would make the file claim capability the project does not have. |
| A-047 | Docs split follows ciu: `nyxloom-trove/decisions.md` (record) + `docs/DESIGN-GUIDE.md` (reasoning) | The split already exists in ciu (`docs/DESIGN-NOTES.md` + trove decisions) and is the estate pattern. |
