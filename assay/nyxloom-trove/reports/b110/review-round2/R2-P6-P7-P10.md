**New findings**
- **P6R2-1 MAJOR (:146-147, :153-158). A child spawned after the handler's sweep is never killed.**
  - A worker samples `deadline.remaining()` (mutation.py:2708) just before the signal arrives. It then reaches Popen and `register_live_group` after the handler has already swept the registry.
  - Nothing kills that child. The main thread blocks on its future, `--kill-after` SIGKILLs assay (no verdict), and the child lives on in its own session, which `timeout`'s group signal no longer reaches.
  - The deferred flag covers only "lock held by another thread", and it fires only on the next `unregister`.
  - **Fix:** `register_live_group` adds the group under the lock, then kills it at once if `termination_requested()`. Because the handler sets the flag before it sweeps, every child is either swept or kills itself. `execute_plan` should also check for termination before calling the runner. Add oracle O13(d): termination set, then a real sleeper group is registered → it is killed.
- **P6R2-2 MAJOR (:153-158). The `default_process_runner` rewrite has lifecycle gaps.**
  - (a) The `proc.communicate()` after the kill has no timeout. Any descendant that left the group (setsid, for example a suite's own `start_new_session` child that inherited stdout) holds the pipe open, and the wait never ends. Today `subprocess.run` does `kill()`/`wait()` on POSIX and never drains.
  - (b) There is no killpg in `finally`. On normal exit, KeyboardInterrupt in commands without the handler, or SIGHUP, descendants survive and no group signal can reach them. This is exactly the leak liveness.py:1402 `_cleanup_process_group` exists to prevent.
  - **Fix:** mirror `run`: killpg, then `wait()`, then re-raise with the partial bytes (`_decode_timeout_stream` already handles bytes). Always do a best-effort killpg in `finally` before unregistering. Handle SIGHUP too. Add an in-process timeout-branch oracle; the 100% floor needs it anyway.
- **P6R2-3 MAJOR (:346, :369). O12 would SIGTERM the test run's own process group.**
  - O7's spawn has no `start_new_session=True`, so `os.killpg(os.getpgid(assay.pid), SIGTERM)` hits pytest and its xdist siblings. Inside a B105 candidate it kills the candidate suite itself.
  - **Fix:** spawn with `start_new_session=True`, assert `getpgid(assay.pid) != getpgid(0)`, and killpg that group in cleanup.
  - Also pin `jobs=1` and `operators=["python:compare-swap"]`: `return x <= 0` also yields a falsy-swap spinner, which makes "the candidate's ID" ambiguous.
- **P6R2-4 MAJOR (:142-147, :373-375). O13 can kill unrelated process groups.**
  - (b1)/(b2) require "registered groups killed", but the registry calls real `os.killpg` with no seam. Synthetic pgids would SIGKILL whatever group owns that number in the devcontainer, the hazard liveness.py:1328-1330 warns about.
  - The handler and installer are left as degrees of freedom (:293), yet O13 calls them directly.
  - **Fix:**
    - add an injectable `liveness` killer seam, or use real sleeper children;
    - pin the handler and installer names;
    - catch `OSError` (not only `ProcessLookupError`) so the handler never raises;
    - make the helper threads `daemon=True`.
- **P6R2-5 MINOR (:232, O8).** With `--kill-after`, GNU `timeout` exits 137, or 125-127 when it fails itself (`man timeout`). Only 124 is handled. Treat any status ≥124 from `timeout` as "failsafe fired, no verdict".
- **P6R2-6 MINOR (:235-238). The forwarding probe does not model the real process tree.**
  - The real lane runs outer `timeout` → bash → inner `timeout` (in its own pgid) → assay (run-gate.toml:36).
  - GNU `timeout` signals only its child pid and its own group, so bash gets TERM and the inner `timeout` gets nothing. Assay dies only when the container ends (run-gate uses `docker run --init`, run_gate.py:4732).
  - The probe `timeout 3 timeout 60 …` will "confirm" forwarding that does not happen here. **Fix:** probe `timeout 3 bash -c 'timeout 60 …'` and document container teardown as the real mechanism.
- **P6R2-7 MINOR (:325 vs :117).** O2's `x.json` fixture is not a `<64hex>.json` record. Use a real unbound record.
- **P6R2-8 MINOR (:171, :175).** Raising right after `execute_plan`, or from inside it on termination, skips closing the reservations. They are armed at mutation.py:2690/2699 and closed only at 2802/2804. Require the close before the raise.
- **P6R2-9 MINOR (:141).** Only a *returned* result is converted. An `AssayError` raised inside `_execute_plan_inner` during termination escapes unconverted. Wrap every exception path: if termination is requested, raise LANE_TIMEOUT from it.
- **P6R2-10 MINOR (:119, :221).**
  - The gate skips `init` whenever the fixed-name file exists, so a restart must also move `.assay/campaign-deadline-b105-<c12>.json`. Otherwise every run exits 4.
  - Echo a marker when `init` is refused.
  - Require the `plan_sha256` keys to equal `lanes`.

**Can a wrong or stale entry still give a false PASS?**

- Yes through a forged receipt, which P10R2-2 makes cheap to launder.
- Otherwise no. Ordinal shifts become `fingerprint-mismatch`; identical statements become `ambiguous`; edits in scope become `stale-review`; a ledger edit changes the sha.
