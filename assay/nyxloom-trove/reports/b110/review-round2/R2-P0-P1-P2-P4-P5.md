**The `cpu_seconds` deviation**
- There is no double counting within one sample. The existing walker reads each process's stat before listing its children (`liveness.py:607-622`). So a child reaped mid-walk is lost, never counted twice.
- A child that is live at sample k and reaped by sample k+1 moves from its own utime to its parent's cutime. Each sample counts it once, and samples are never summed.
- Each sample is a lower bound, but the series is not monotone. It dips on a mid-walk reap, on reparenting out of the tree, and on children auto-reaped under SIGCHLD=SIG_IGN, which never reach cutime.

  - "Exactly once" at :192 overstates the guarantee.
  - The Σ RSS at :196 overcounts shared and copy-on-write pages. Call it a "1 Hz lower bound on peak Σ RSS", not a bound on true peak memory.
- **P0R2-4 MINOR (:254-257).**
  - Pairing by occurrence mispairs when an earlier duplicate has a setup record but no call (setup error or skip).
  - Fix: pair each call record with the nearest preceding unconsumed setup record and the next teardown record for the same nodeid.

**The C4 sweep**
- The design is sound. It compares kernel ctime with kernel ctime, not `time.time_ns`, and `>=` absorbs coarse or whole-second granularity.
- It catches:
  - in-place writes, including mmap writes, whose first write fault updates ctime;
  - unlink-and-recreate (ctime);
  - rename-replacement (inode);
  - assume-unchanged and skip-worktree games in the child index.
- Racy entries are not an issue: mtime 946684800 is far below the index mtime.
- Files the command creates, and skip-worktree omissions, stay with `dirty_paths`, unchanged.
- The probe's BLOCKED exit is well-defined (:222, :467).

  - The preflight (:460) and P2's O5b will fail, and `b105-coverage-exclusions.json` is not in P5's Touch list. That is a guaranteed stop.
  - Calling `snapshot_content_drift` from mutation.py also needs an import edit at :120 or :124. Scope allows only :1859, and any new line above `mutation.py:148` shifts that file's pinned lines too.

  - Problem: "the manifest's regular-file entries … blob OID" reads naturally as `self._manifest.entries`, which carries the base OID. The replaced file's new OID exists only in the local `entries` (`isolation.py:806-848`).
  - In small repos every file shares the watermark tick, so every mutant child would be falsely DIRTY_TREE.
  - The tempting "fix" of excluding the replaced path leaves the most-edited file unchecked.
  - Also, `_build` returns only the commit; the `Snapshot` is built in `_materialize` (`isolation.py:709-714`), which is not in Touch.

    - add `_materialize` to Touch;

- **P5R2-3 MAJOR (R4b :300).**

  - R5d's "pre-attach a watermark equal to the post-edit ctime" cannot be known before the edit happens.
  - Fix: in both caller-level oracles, set `--assume-unchanged` on the file first, as R5b does, so `status` is deterministically blind. Then use the real baseline.
- **P5R2-5 MINOR.**
  - Tracked symlinks are outside the sweep. A same-second unlink-and-symlink with an equal-length target, a reused inode and `lutimes` restoring the mtime is invisible to both `status` and the sweep. Fix: compare `os.readlink` against the manifest target.
