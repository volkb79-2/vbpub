## New findings

**P5R3-1 MAJOR: the sweep feeds `hash-object --stdin-paths` a line-oriented path list (:119, :186).**
- **Problem:** `--stdin-paths` reads one path per line. It strips a trailing CR, and it C-unquotes any line that starts with `"`.
- **Evidence:** this codebase explicitly supports tracked names containing a newline or backslash:
  - `isolation.py:800-808` says a newline-delimited form "would either split a single declared path … or mis-parse it via git's own C-quoting";
  - `tests/test_isolation.py:1720-1758` replaces `odé\nline\slash.txt`.
- **Consequence:** in a small repo, every file is a suspect (:118). Every post-command dirt check then fails with `GIT_FAILED`, a false ERROR on a supported case. If the split halves happen to exist as files, the output OIDs line up with the wrong paths. No oracle covers this.
- **Fix:**
  - Write every path as a C-quoted line: `"` + the raw UTF-8, with `\\`, `\"` and bytes below 0x20 or equal to 0x7f escaped as `\ooo`.
  - Require exactly `len(suspects)` OID lines back, otherwise `GIT_FAILED`.
  - Name the route. `Snapshot` carries no git executable and `git.py` is scope-locked, so use `git._run_raw(snapshot.root, "hash-object", "--no-filters", "--stdin-paths", input_bytes=…, remaining=…)` (`git.py:656-705`), which already bounds stdin and applies `_FIXED_CONFIG`.
  - Add **R5g** on the odd-path fixture: with `watermark_ns=0` the sweep returns `()`, and after an in-place edit it reports the path.

**P5R3-2 MAJOR: index-bit games still hide deletions, type changes and mode changes, although the brief says the sweep handles them (:95, :114, table row :203).**
- **Problem:** Step 2 leaves missing and type-changed paths to `dirty_paths`. But git skips the lstat entirely for CE_VALID (assume-unchanged) and skip-worktree entries (`run_diff_files`, `refresh_cache_ent`).
- **Consequence:** a consumer that runs `update-index --assume-unchanged f` and then deletes f, turns f into a directory, or runs `chmod +x` on it, is invisible to both checks.
- **Context:** this hole already exists in `dirty_paths`, so it is not a regression. But plan D8 says "scope the claim accordingly", and :95 claims the opposite.
- **Fix (costs nothing extra; the lstat is already done):** in step 2, also report any baseline path that is missing, has changed type, or whose executable bit differs from the entry mode (and likewise for symlinks). Extend R5b with deletion and chmod cases where `dirty_paths` stays blind. If the controller would rather not change this, restrict :95/:203 to content edits and record the residual in A-472.
