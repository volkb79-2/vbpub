## New findings

**P3B3-1 MAJOR: one timeout path is not routed through `R2BaselineTimeoutError` (P3b:392-395, :408).**
- **Problem:** C21 names only two triggers: the unit returning `BUDGET_EXCEEDED/LANE_TIMEOUT`, and `deadline.remaining()` raising. But step 2's `prepared.materialize(timeout=…)` runs its own snapshot-preparation timer (`isolation.py:699`). When that timer expires, `git._p22_timeout` (git.py:1168; raised at :1210/:1310/:1349) raises `AssayError(BUDGET_EXCEEDED, LANE_TIMEOUT)`, and neither named trigger catches it. It falls to `except AssayError` at :4542 and produces the unverifiable R2-only shape that C21 forbids.
- **Fix:** wrap steps 2–4 in one `try`. Map any `AssayError` with `reason_code is LANE_TIMEOUT`, and any unit result with that pair, to `R2BaselineTimeoutError`. Add an oracle that patches the second `materialize` call to raise `_p22_timeout`.

**P3B3-2 MAJOR: the C21 oracle cannot be built as written (P3b:524, :402-408).**
- **Problem:** a `ProcessRunner` is `(argv, *, env, cwd, timeout) -> subprocess.CompletedProcess` (runner.py:321-323). It never sees the progress phase, and it cannot return a `CommandResult`. `BUDGET_EXCEEDED/LANE_TIMEOUT` comes only from a raised `subprocess.TimeoutExpired` (runner.py:1255-1263). Also, `_execute_snapshot_unit` takes `deadline=`, not `timeout=` (:2804), and `progress_phase=` already exists (:2835).
- **Fix:**
  - Have the fake raise `TimeoutExpired` for the call whose env carries `ASSAY_MUTATION_WITNESS_MANIFEST_FILE`; only the R2 baseline sets it.
  - Pass `deadline=deadline, progress_phase="r2-baseline"`.
  - The fake hands every other call, including R0, to the real runner, so R0 still starts a real pytest process. Place the test by P1's tier rules.

**P10R3-1 MAJOR: the judge-identity binding can be skipped without anyone noticing (P10:340-346; OC9 :398).**
- **Problem:** step 3.2 compares `receipt.judge_sha256` against "this run's judge identity". But `run_mutation` computes that identity only `if state_root is not None` (mutation.py:2353-2364), and only after the shard step (:2327-2343). `state_root` is set only by `--resume` or `--shard` (runner.py:4522), and `--shard` is refused together with `--equivalence-audit`. So in `assay run --cold-witness --equivalence-audit R` without `--resume`, the identity does not exist yet at C23 step 3. The natural implementation, `if judge is not None and …`, then silently skips the primary OC9 binding. The gate always passes `--resume`, so this bites only non-gate runs.
- **Fix:** under `--equivalence-audit`, compute the identity unconditionally and before placement (it does not depend on selection), and never skip the comparison. Alternatively, refuse `--equivalence-audit` without `--state-dir`. Add an O8 dynamic-binding case with no `--resume`.
