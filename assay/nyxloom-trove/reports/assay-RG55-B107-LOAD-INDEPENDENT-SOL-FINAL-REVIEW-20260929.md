2. **The behavioral chain remains asserted without those deadlines.** `LivenessRunner._monitor` advances eligible idle time only across clear resource-counter intervals; pressure, counter reset, unavailable readings, and truncated traces cannot certify a hang. A complete quiet CPU window plus no progress raises typed `LivenessHungExpired`; an independent configured wall budget raises plain `subprocess.TimeoutExpired` with `configured-budget-expired` evidence. The monitor tests drive those branches with injected clock, process, CPU, event, and resource observations, including pressure followed by a real quiet window, pressure-only and unknown-resource incompleteness, growing CPU, process-tree CPU drops, and session-finish grace. A real child with the default process-tree CPU reader and a virtual clock checks launch/kill integration; normal completion checks process-group cleanup, including a real descendant.
3. **Runner, mutation, and retained evidence still discriminate.** `runner._execute_plan_inner` maps the subclass to `BUDGET_EXCEEDED/CANDIDATE_HUNG` and the plain timeout to `BUDGET_EXCEEDED/LANE_TIMEOUT`; focused tests assert both types and reason codes. Both mutation classifiers send only the former to `hung`, leaving the latter `budget_exceeded`; `judge_mutation` and `verify` tests assert the incomplete outcome. The injected `run_mutation` test checks that a hung candidate's complete evidence reaches both state records and progress events. Cache tests accept a complete trace and reject absent, inconsistent, pressured-as-eligible, progress-bearing, truncated, or insufficient-CPU-window traces. The surviving real CLI test still checks pytest liveness activation and a configure-time mutant failure that must be `killed`, not a false survivor; its 50-second candidate budget is a generous failsafe around an immediate failure, not a comparison with the liveness threshold.
