## Blocking findings

**R4-1 — high — root-created lock file prevents the non-root caller from launching a DAMON-requesting helper.** The daemon runs as root (no `USER` override in `scripts/cgroup-profiler/Dockerfile`; `ciu.compose.yml.j2` has no `user` override) and its first pool acquisition creates `/run/cgprofile/damon.lock` as root-owned through `_DamonRegistryLock.acquire()` (`lib/damon.py:137-150`). Host setup makes `/run/cgprofile` `0770 root:docker`; the normal cockpit user here is `uid=1003(vscode)`, a member of `docker`, not the file owner. Before a helper is even started, `_launch_helper(..., damon=True)` calls `prepare_registry_lock_file()` (`cgprofile.py:585-600`), which unconditionally calls `os.fchown(fd, -1, directory.st_gid)` and `os.fchmod(fd, 0o660)` on the *existing* root-owned file (`lib/damon.py:185-220`). Membership in `docker` permits opening a `0660 root:docker` file, but not changing that file's group or mode: Linux requires ownership or the relevant privilege. `prepare_registry_lock_file()` turns the resulting `EPERM` into `DamonSessionError`; `_start_run()` invokes it before spawning the helper and before waiting for READY (`cgprofile.py:740-780`). Consequently `cgprofile run --damon --mode helper` with the daemon-first creation order never launches the wrapped command, and `attach` never begins ordinary sampling, although DAMON is optional. This violates R-36h and the new `README.md:71-82` / `docs/CONSUMERS.md:42-59` promise. The tests use a tmp-path lock owned by the test uid (`tests/test_damon.py:220-229,275-293`) or mock `prepare_registry_lock_file()` entirely (`tests/test_cgprofile.py:1325-1370`); none construct the root-owned, docker-group-readable preexisting file and exercise the *caller* prelaunch path. Validate an already-correct shared file without attempting owner-only mutations, and make any unusable optional lock degrade DAMON without withholding the command. Pin an oracle for both creation orders and the real caller boundary.

**R4-2 — high, release-blocking — the human-facing version narrative directs an unchosen 1.1.0 release.** Controller `run-gate-project/nyxloom-trove/reports/run-gate-WAVE-RG55-CONTROLLER-LOG.md:6567-6575` (RW-434) settles the combined P1+P6 tree as the **first 1.0.0** release; 1.1.0 requires genuine post-1.0.0 work. The README, consumer guide, and design guide also give `1.1.0` as the daemon-version JSON example (`README.md:182-195`; `docs/CONSUMERS.md:182-197`; `docs/DESIGN-GUIDE.md:360-373`). A standalone hypothetical version example might be harmless, but in combination with the pasteable release and deploy commands and the false authority history, this is a current operational instruction to choose the wrong release. Correct all three human-facing documents before merge/release; reconcile the unreleased `CHANGES.md:48` version-sweep note with the settled boundary. `pyproject.toml`'s source-checkout `0.1.0` and wire contract major `1` are different facts and are not this finding.

## N1/N2 verification and limits

- **N1's deterministic foreign-slot deletion is closed within the stated coordination boundary.** Both pool and bare session refuse a nonzero `nr_kdamonds` before mutation (`lib/damon.py:558-573,794-846`), and the pool reserves full capacity with one write from zero (`:502-556`). The fake now removes and recreates *all* kdamond directories on each count write (`tests/test_damon.py:57-84,167-180`); stopped and running foreign-marker tests assert no loss (`:572-611`). Pinned state-node inode comparisons quarantine same-count replacements before reuse, stop or shrink (`lib/damon.py:291-331,436-490,605-645`; `tests/test_damon.py:1099-1122`). These tests exercise observable state and configuration, not just call counts. The check before a count write is not atomic against a non-cooperating privileged writer: that writer could create a foreign slot after the zero-baseline read, which the cgprofile write would delete. The docs explicitly disclose the advisory-lock boundary and require excluding unrelated privileged DAMON configurators (`docs/DESIGN-GUIDE.md:238-258`, `docs/CONSUMERS.md:202-218`). With no kernel ownership lease, I treat that operator-controlled exclusion as an acceptance limitation, not a further code-level N1 blocker. It still needs live validation under that precondition.
- **N2's in-collector runtime failure is closed.** `cgprofile.py:450-514` gives DAMON its own `ExitStack`; on a collection exception it disables DAMON, closes only that stack, logs cleanup errors, then continues the sampler to manifest and DONE. The 22-tick test (`tests/test_cgprofile.py:1191-1245`) makes collection fail on sample zero, verifies later ordinary samples including tick 20, one close, no further DAMON calls, and finished manifest/DONE with and without a cleanup exception. Entry failure remains optional. R4-1 is a separate *pre-collector* failure introduced by the lock-file setup.
