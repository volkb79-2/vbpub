# debian-install-v2 CLI specification

Canonical command-line contract of `debian-install-v2.py`. The generated
grammar inventory between the markers below is owned by
`cli-extended surface sync`; everything else is product-owned. The user-facing
guides are [`README.md`](../README.md), [`CONSUMERS.md`](CONSUMERS.md) and
[`DESIGN-GUIDE.md`](DESIGN-GUIDE.md); the reviewed semantic decisions and their
linked tests are in [`cli-review.toml`](cli-review.toml), and review findings in
[`cli-review-findings.toml`](cli-review-findings.toml).

## Caller surfaces

| Surface | Caller | Contract |
| --- | --- | --- |
| `debian-install-v2.py` | operator, systemd stage-two unit | the registered CLI below; needs `cli_extended` from a wheel beside the script or an installed one |
| `bootstrap-remote.py` | cloud-init / operator one-liner | stdlib-only fetcher; environment variables, not a CLI; installs the released `cli_extended` wheel beside the entrypoint |
| `python -m debian_install_v2.bootstrap` | tests and developers | same registered CLI as the entrypoint |
| `inuse-partition-editor.py` | installer internals, operators | standalone stdlib script, not a `cli_extended` consumer |

## Semantic table

| Verb | Use case | Selection and omission | Effects | Dry run / confirmation | Exit status |
| --- | --- | --- | --- | --- | --- |
| `wizard` | write a validated install settings file interactively | `--output` is required; `--from-config` seeds the answers | writes one mode-0600 JSON file; needs an interactive terminal and Questionary | confirmation of overwrite is part of the wizard; no dry run | 0 written, 130 cancelled, 2 refused |
| `install` | stage one of a fresh install (root disk, swap, stage-two service) | exactly one of `--config` / `--config-json` | repartitions the root disk, writes swap, units and state, may reboot | `--dry-run` records the planned host actions as JSON and executes nothing; otherwise a default-no confirmation (`--yes` skips only that prompt) | 0 done or declined, 2 invalid settings, 1 failure |
| `resume` | stage two after reboot, normally systemd-invoked | state directory from `VBPUB_STATE_DIR` (absolute path required) | applies the remaining host changes | `--dry-run` as for `install`; otherwise confirmation | 0 done or declined, 2 missing or invalid state |
| `status` | show recorded installation status | exactly one settings source | read-only | none needed | 0, 2 invalid settings |
| `verify` | live checks of the disk transaction and health gates | exactly one settings source | read-only on the host; writes no state | none (a dry run is not meaningful and is refused) | 0 healthy, 1 a check failed |
| `plan` | show the root-disk and swap plan for the target host | exactly one settings source | reads the host; changes nothing | none needed | 0, 2 invalid settings |
| `disable-stage2` | disable the stage-two unit and mark it complete | exactly one settings source | stops and disables the unit, records the completion marker | `--dry-run`, otherwise confirmation | 0, 2 invalid settings |
| `build-customscript` | render settings plus a cloud-init bootstrap command | exactly one settings source; a custom `--repo-url` needs `--bootstrap-url` | none; prints JSON that may contain the Telegram token | none needed; refuses to print a redacted token bundle unless `--debug-raw` | 0, 2 invalid input |
