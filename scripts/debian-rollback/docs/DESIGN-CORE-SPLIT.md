# Design note: dr-state core and backend split (P-rollback-10)

Status: decided 2026-11-24 for P-rollback-20..24. Inputs: PLAN-rollback B1-B15, the 2026-11-24 design review (finding
IDs below), `poc/dr-state` and its suites on main `313ae9dcb`, and the ZFS facts from `330bdb835` (read only to check
fit). B1-B15 are not reopened. "Measure" marks an unknown that needs evidence; it is not a guess.

## 1. Runtime form and module layout (H2, M2, B1)

- **D1 Language (B1).** Stdlib-only Python 3, no third-party imports. **Minimum Python 3.13**, the `python3` of
  Debian 13 (trixie), the only target (D9). The launcher exits 70 with a clear message on an older interpreter.
- **D2 Location (M2).** The runtime lives outside every OS state and all states share it: `/usr/local/sbin/dr-state`
  (launcher) and `/usr/local/lib/dr-state/dr_state/` (package). On btrfs `/usr/local` is `@usr-local`. On ZFS it must
  be a dataset outside every BE (a requirement for P-rollback-12/43). This is a documented rule: no `.deb` into `/usr`.
  The interpreter belongs to each state, so installers add `python3` (full stdlib) to the debootstrap `--include`.
- **D3 Launcher.** `#!/usr/bin/python3 -I`. It inserts `<own dir>/../lib/dr-state` into `sys.path` and calls
  `dr_state.cli.main()`. The same rule works installed and from the repository tree (section 10).
- **D4 Modules.**

```text
dr_state/__init__.py   FORMAT = 1, version        dr_state/lock.py       flock, atomic_write (temp+fsync+rename+dir fsync)
dr_state/cli.py        argparse, verbs, --sysroot, --json, exception -> exit code
dr_state/core.py       verbs as functions over a Context(paths, storage, boot, runner, clock, env)
dr_state/ids.py        grammar, StateId, slug, entry-file mapping, boot-count strip, version sort
dr_state/metadata.py   sidecars, counter floor, format files    dr_state/errors.py   exception types (section 4)
dr_state/apt.py        Pre-Install-Pkgs plan parser, window      dr_state/paths.py    every path, under one sysroot
dr_state/retention.py  prune selection, capacity formula, degraded-menu selection
dr_state/hashcache.py  kernel hash cache (M5)                    dr_state/check.py    check invariants (H4)
dr_state/storage/{__init__,btrfs,zfs}.py   Storage protocol + backends
dr_state/boot/{__init__,grub,sdboot,zbm}.py  Boot protocol + backends
```

- **D5 One subprocess boundary.** Every external program (`btrfs`, `zfs`, `zpool`, `grub-editenv`, `grub-mkimage`,
  `bootctl`, `dpkg-query`, `findmnt`) runs through `Runner.run(argv, *, input=None) -> Completed`: argv only, never a
  shell, found on `PATH`. A non-zero exit raises `StorageError`/`BootError` carrying argv and stderr.
- **D6 Backend selection.** Storage comes from the root filesystem type (`findmnt -n -o FSTYPE --target /` under the
  sysroot: `btrfs` or `zfs`). Boot comes from the ESP marker only (M1, section 3.4).

## 2. State names (H1, M8, B3)

- **D7 One grammar, only in `ids.parse()` (H1).**
  `^@os-(?P<seq>[0-9]{6})-(?P<date>[0-9]{8})-(?P<time>[0-9]{6})Z-(?P<slug>[a-z0-9_-]{1,64})$`, plus `seq != 000000`
  and a date/time that round-trips as a real UTC instant. The bound of 64 makes B3's `+` concrete. It keeps every
  entry file name far below FAT's 255 bytes and equals what the generator emits. `parse()` returns a `StateId` or
  `None`. No other module matches state names.
- **D8 Generator.** `ids.slug(source, reason)`: `apt` gives `apt`, `install` gives `install`. A manual reason is
  lower-cased, each run outside `[a-z0-9_-]` becomes `-`, the result is prefixed `manual-` and cut to 64, and it never
  ends in `-` or `_`. The verbatim reason stays in the sidecar.
- **D9 Unmanaged (H1).** Storage reports every `@os-*` object. A name that fails `parse()` is `unmanaged`: listed
  (`list`, `--json`), never published, never pruned, refused as a `delete`/`set-default`/`boot-once` target (exit 3),
  and refused as a snapshot source. A running unmanaged state makes `snapshot` and the apt hook exit 3, which keeps
  "the hook refuses on unsupported disks" without the old counter gate.
- **D10 Deleted legacy (H1).** No `.conf`-state handling, no `@os-pre-*`/`@os-0001` readers, no 12-hex kernel ids
  (only `<kver>-<64 hex>`), no bash scratch shapes, no suffix-less `loader.conf` migration, and no FAT case-fold
  collision scan (canonical names are lower case; ownership is checked on the exact path, B-3).
- **D11 Entry file and id.** The entry file is `StateId.bare + ".conf"` (`bare` = the name without `@`).
  systemd-boot's entry id is that file name, `.conf` included. `default` lines and `bootctl set-oneshot` always use it.
- **D12 Ownership and boot counting (M8).** An entry is ours if and only if its first line (CR stripped) is
  `# generated by dr-state sdboot; do not edit`; the file name never decides ownership. To map an owned file to a
  state: strip a case-insensitive `.conf`, then one trailing `\+[0-9]+(-[0-9]+)?`, prepend `@`, `parse()`. `+` is
  outside the grammar, so the strip is unambiguous. Selector values map the same way, and systemd-boot also strips the
  counter from entry ids, so `default os-X.conf` stays correct under counting. An owned file that maps to no managed
  state is stale; `publish` removes it unless it is the default or the pending one-shot target. `publish` rewrites a
  state's existing owned file in place (keeping a counter-suffixed name); if several map to one state, it keeps the
  first in byte order. Phase 2 itself is not built.

## 3. Interfaces (H2)

### 3.1 Shared types

```python
@dataclass(frozen=True)
class StateId:                 # built only by ids.parse(); managed by construction
    name: str                  # "@os-000002-20261118-120100Z-apt"
    sequence: int; created: datetime; slug: str   # created is UTC
    bare: str                  # "os-000002-…-apt": entry stem, ZFS leaf and snapshot name
Kind = Literal["live", "checkpoint"]
@dataclass(frozen=True)
class Stored:                  # one @os-* object as storage sees it (managed or not)
    name: str; kind: Kind | None; origin: str | None   # kind None: storage cannot tell (btrfs)
@dataclass(frozen=True)
class KernelPair:              # host paths valid inside Storage.session()
    version: str; vmlinuz: Path; initrd: Path
    fs_vmlinuz: str; fs_initrd: str   # path as a loader's fs driver sees it ("/@os-…/boot/vmlinuz-…"), "" if none
@dataclass(frozen=True)
class Space: size: int; free: int
```

### 3.2 Storage

```python
class Storage(Protocol):
    name: str                                   # "btrfs" | "zfs"
    control_dir: Path                           # outside every state; btrfs: <top>/.dr-state
    def session(self) -> ContextManager[None]   # scope of temporary mounts; unmounts on exit
    def list(self) -> list[Stored]
    def running(self) -> str | None             # booted state's name; None when unknown
    def snapshot(self, source: StateId, target: StateId) -> None
    def activate(self, state: StateId) -> None  # make state a bootable live object named by its ID
    def delete(self, state: StateId) -> None
    def kernels(self, state: str) -> list[KernelPair]   # complete non-empty pairs, newest first
    def parent(self, state: StateId) -> StateId | None
    def root_args(self, state: StateId) -> str  # btrfs: "root=UUID=<fs> rootflags=subvol=@os-…"
    def space(self) -> Space
    def reclaimable(self, state: StateId) -> int | None  # bytes freed by delete; None = unknown
```

B2's five methods are kept; six are added now so ZFS needs no later interface change. `running` is storage-specific
(btrfs reads `rootflags=subvol=` from `<sysroot>/proc/cmdline`, ZFS uses findmnt) and is now detected in one place
instead of four (H2). `activate` is ZFS clone+promote and a btrfs no-op. `session`, `root_args` and `space` are
storage facts; `reclaimable` feeds retention. The core uses `DR_STATE` only when `running()` is `None`.
`DR_STATE=none` still skips `snapshot` and makes `prune`/`delete` refuse: product behaviour, not a test seam.

Invariants: **S1** `snapshot` is atomic; on an exception no object named `target` remains. **S2** `delete` acts on one
managed object and raises `Refused`, listing them, when there are dependents (ZFS clones, checkpoints held by a live
dataset) or unexpected children. **S3** `list` reports each name once, only `@os-*`-shaped names. **S4** `kernels`
returns only pairs whose `vmlinuz-<v>` and `initrd.img-<v>` are both non-empty, newest first in GNU `sort -V` order
(a unit test pins it against `sort -V`). **S5** `running` never guesses; `activate` is idempotent.

### 3.3 Boot

```python
@dataclass(frozen=True)
class BootTarget:
    state: StateId; title: str; kernel: KernelPair   # title "Debian @os-… (kernel <v>)"
    root_args: str; locator: str                     # locator: btrfs "/@os-…"; zfs "<pool>/ROOT/os-…"
@dataclass(frozen=True)
class Inspection:
    published: frozenset[str]; stale_owned: tuple[str, ...]; violations: tuple[Violation, ...]
class Boot(Protocol):
    name: str                       # "grub" | "systemd-boot" | "zfsbootmenu" = ESP marker value
    supports_oneshot: bool
    def install(self) -> None       # install time only; writes the ESP marker and format file
    def capacity(self) -> int | None                              # bytes for our payload; None = unbounded
    def payload(self, target: BootTarget) -> list[tuple[str, int]]  # (dedupe key, bytes)
    def publish(self, targets: Sequence[BootTarget], default: StateId) -> None
    def default(self) -> str | None
    def oneshot(self) -> str | None                               # None when unset or unsupported
    def set_oneshot(self, state: StateId) -> None                 # Unsupported when not supports_oneshot
    def protected(self) -> frozenset[str]                         # every state the loader may boot without us
    def inspect(self) -> Inspection
```

`publish` publishes exactly `targets`. The core chose them (section 6), so fit logic exists once, and `default` is
always among `targets`.

Selector rule, shared by `default()`, `oneshot()` and `protected()`: a selector that resolves to an existing managed
state yields that state, and one naming an existing foreign entry yields nothing of ours. Anything else raises
`BootConfigError`: unreadable or malformed, a duplicate grubenv key, suffix-less, a glob, or a missing state. This
keeps today's fail-closed `delete` rule and now applies it to GRUB `prune` too, removing the H2 asymmetry.

Invariants: **B-1** Publish then delete: entries, pairs and the default are written before any stale file is
removed, so a failure at any step leaves a default that resolves to an existing entry. **B-2** Every file goes through
`atomic_write`; scratch has one shape, `.dr-state.tmp.*`, only in our directories, and `publish` removes leftovers
first. **B-3** A file without the marker is never written, renamed or deleted; an exact-path clash raises `Refused`.
**B-4** A pending one-shot target's entry is never removed. **B-5** sdboot pairs are
`<kver>-<sha256(sha256(vmlinuz)+sha256(initrd))>`; a copy is verified against the source hashes before its rename; a
pair is removed only after publication and only when no owned or foreign entry references it (VFAT case-folding and
CRLF tolerated). **B-6** A repeated identical `publish` changes nothing and reads no kernel bytes (M5). **B-7** GRUB
`set-default` republishes like sdboot instead of only editing grubenv (H2).

### 3.4 ESP marker (M1, B6)

`<esp>/EFI/dr/bootloader` holds exactly `grub`, `systemd-boot` or `zfsbootmenu`. `install-grub` now writes it too. A
missing, empty or unknown marker makes every write raise `Refused`; read-only verbs still run and report boot
`unknown`. `/etc/dr-state.conf`, `BOOTLOADER=` and the conflict logic are deleted, and the installer stops writing the
file. GRUB PoC disks without a marker are unsupported (B15 takes evidence from fresh disks).

### 3.5 ZFS fits unchanged (B8)

| Method | ZFS + ZBM behaviour |
|---|---|
| `list` | Datasets `<pool>/ROOT/os-*` are `live`; snapshots `<BE>@os-*` are `checkpoint`. A snapshot whose leaf equals a live dataset's leaf is that dataset's origin after promote and is not reported. |
| `snapshot` | `zfs snapshot -o org.dr-state:parent=<source> <source-ds>@<target.bare>`: atomic, O(1). No send/receive, staging, registry or orphans. |
| `activate` | `zfs clone -o canmount=noauto -o mountpoint=/ -o org.zfsbootmenu:commandline=<source's local value> <holder>@<bare> <pool>/ROOT/<bare>`, then `zfs promote`. Name = ID. Clones do not copy local properties, so they are set. |
| `delete` | Checkpoint: `zfs destroy <holder>@<bare>`, `Refused` if it has clones. Live: `Refused` while it holds managed checkpoints, clones or children; else `zfs destroy` without `-r`. |
| `kernels` | Running BE: `/boot`. Other BE: read-only temporary mount inside `session()`. Checkpoint: `<holder mountpoint>/.zfs/snapshot/<bare>/boot` (U5). |
| `parent` / `running` | The checkpoint's `org.dr-state:parent` (it survives promote), or the BE's origin / `findmnt -n -o SOURCE --target /` mapped to `@<leaf>`. |
| `reclaimable` | The snapshot's `used`, or the BE's `usedbydataset`: exact. |
| Boot `publish` | Writes no menu files: ZBM discovers BEs. Sets `zpool set bootfs=<default locator>` when it differs. Checkpoints stay reachable in ZBM's snapshot menu; they are not entries. |
| `default` / `protected` | The BE named by `bootfs` / `{that BE}`. |
| `oneshot` / `set_oneshot` | `None` / `Unsupported` (exit 4); `supports_oneshot = False`. `capacity`/`payload`: `None` / `[]`. |

The core calls `storage.activate(X)` before `boot.publish(..., default=X)`. `set-default` on a checkpoint is therefore
clone+promote, then `bootfs`. Unknown U4: the dataset name ZBM gives a BE the operator clones from its own snapshot
menu. The rule is fixed now: a non-`os-*` name is unmanaged. `set-default <ID>`, run inside that BE, renames it to
`<pool>/ROOT/<origin bare>` (mechanism measured in P-rollback-12) and then proceeds. Until then `snapshot` refuses
there (D9).

## 4. Errors, exit codes, lock (H2)

| Exception (`errors.py`) | Exit | Meaning |
|---|---:|---|
| `UsageError` | 2 | Bad arguments. |
| `Refused`, `FormatError`, `BootConfigError` (in destructive verbs) | 3 | A safety rule refused; nothing changed. |
| `Unsupported` | 4 | The backend lacks the operation (ZBM `boot-once`). |
| `CheckFailed` | 5 | `check` found an error-level violation. |
| `LockTimeout` | 6 | Another writer held the lock for 60 s. |
| `StorageError`, `BootError`, `CapacityError` | 1 | An operation failed after its own cleanup. |
| any other exception | 70 | Bug: a one-line message; a traceback only with `DR_STATE_DEBUG=1`. |

Writers take `flock(LOCK_EX)` on `<sysroot>/run/dr-state.lock` and wait up to 60 s, as today. `check` takes `LOCK_SH`,
so it never sees a writer's scratch. `list` and `show` take no lock.

## 5. Counter floor (M6, B4)

- **D13** `floor = max(counter, max sequence of managed names from Storage.list(), max sequence in sidecars)`. The
  allocator never returns a sequence at or below the floor. It reserves `floor + 1` durably, then snapshots.
- **D14** A missing, malformed, symlinked or too-low counter is repaired under the lock, with a warning, by atomically
  replacing the path itself (never a symlink target). Allocation then continues, and the counter never blocks apt.
  B4's "refuse only below the floor" is read as "refuse to allocate below it, then repair", which matches the
  P-rollback-22 acceptance. Reaching 999999 raises `Refused`.
- **D15 Documented repeat.** If the counter is lost and the highest state is deleted with its sidecar, the floor is
  below the historical maximum and the next state repeats that sequence. Its full ID still differs (the timestamp),
  and order among existing states stays monotonic. Accepted (B4).

## 6. Snapshot versus publication, hook, retention (H5, M3, L2, B5, B7)

- **D16 Snapshot success (H5).** `snapshot` succeeds once `storage.snapshot` has returned and the sidecar is durable.
  If the sidecar write fails, the object is deleted and the exit is 1. Publication afterwards is best-effort:
  `StorageError` from `kernels`, `BootError` and `CapacityError` become a warning with exit 0 (sequence consumed).
- **D17 Degraded menu (H5).** Every publication uses one selection. Candidates are the managed states with a kernel
  pair, minus a state being deleted. Order: (1) the default: the requested state, else the configured default if it
  is a candidate, else the running state if it is one, else the first candidate in sort order (today's rule); (2) the
  running state; (3) the pending one-shot target; (4) the other candidates, highest sequence first. Items 1-2 are
  mandatory. Items 3-4 are added greedily: kept if `need()` (D19) still fits, else skipped, and the walk goes on to
  older states, which may share a pair. If the mandatory set does not fit, `CapacityError` leaves the old menu: a
  warning in `snapshot` and the hooks, exit 1 in `gen-menu`/`set-default`. Menu sort order does not change. `list`
  and `check` show unpublished states.
- **D18 One snapshot hook (M3, B7): `DPkg::Pre-Install-Pkgs` alone.** It runs once per apt commit and carries the plan
  (Version 2, `InfoFD 3`). The Pre-Invoke snapshot and its `|| exit 100` are deleted. Post-Invoke `gen-menu || true`
  and the `zz-dr-state` kernel hooks stay; they only republish.
  - Exit codes: apt aborts on non-zero: 1 (no checkpoint), 3 (unmanaged running state, newer format), 6 (lock), 70,
    and a failed interpreter exec. Exit 0 covers success, a degraded menu, a window dedupe and `DR_STATE=none`. A
    missing or unparseable plan still snapshots (`apt_actions = "package plan unavailable"`). The documented escape
    for a broken interpreter is `DR_STATE=none apt-get …`.
  - Proof for removal-only runs, before P-rollback-22 builds on it: in a capped Debian 13 container (APT hook dispatch
    is userspace only), a logging Version-2 `Pre-Install-Pkgs` hook logs exactly one call containing `**REMOVE**` for
    each of `apt-get remove -y <pkg>`, `apt-get purge -y <pkg>` and `apt-get autoremove -y`. P-rollback-40 repeats it
    as scenario `apt-removal-only` on an ISO-built disk with `DR_SNAPSHOT_MIN_INTERVAL=0`: one new checkpoint whose
    `apt_actions` names the removal. Fixed fallback if it fails: Pre-Invoke snapshots and writes the ID to
    `/run/dr-state/pending`, Pre-Install-Pkgs annotates it, Post-Invoke clears it.
- **D19 One capacity formula, every backend (L2, F13).** `need(S) = Σ bytes over the distinct payload keys of S +
  margin`, with `margin = largest pair in S + 8 MiB`; the largest pair covers one in-place pair replacement. sdboot
  payload is `(pair id, vmlinuz + initrd bytes)` plus `(entry id, 4096)`; GRUB and ZBM have none. sdboot
  `capacity = statvfs free + bytes of owned entries + pair directories no foreign entry references`. The cluster,
  directory-record and staging models (`:622-703`, `:874-916`) are deleted. The 8 MiB is checked by P-rollback-40's
  ESP-exhaustion scenario (U7).
- **D20 Retention (B5).** Victims are the managed states that are not running, not in `boot.protected()` and not
  pinned, oldest sequence first. They are removed until all hold: (a) unpinned managed count ≤ N (default 10 on every
  backend; `--keep N` overrides); (b) `need(remaining candidates) ≤ boot.capacity()`; (c) `space.free +
  Σ reclaimable(victims) ≥ max(2 GiB, 5 % of space.size)`. With `reclaimable` `None` (btrfs without qgroups), (c)
  only warns until U2 is measured. If the victims run out first, `prune` warns that the rule cannot be met. `prune`
  applies the policy; `snapshot` never deletes. Automation is operator question Q1 (section 12).
- **D21 Window (M3, M4).** The dedupe window stays policy only: `DR_SNAPSHOT_MIN_INTERVAL`, default 900 s, 0 disables
  it. It is keyed on sidecar `source == "apt"` and `storage.parent(c) == running`, never on a slug. Inside the window,
  plan lines are appended to the newest such checkpoint.

## 7. Metadata and hash cache (M4, M5)

- **D22 Sidecar schema 2 (M4).** `<control_dir>/metadata/<name>.meta` keeps the schema-1 encoding (`schema=N`, then
  `key=base64(value)` lines) and adds `kind` (`live`|`checkpoint`) and `pinned` (`0`|`1`).
  A schema-1 sidecar reads as `kind=checkpoint, pinned=(source == install)`, so nothing migrates. `initialize-state`
  writes `kind=live, pinned=1`; `snapshot` writes `kind=checkpoint`; any locked verb sets the running state's sidecar
  to `kind=live`. Effective kind: storage's when not `None` (ZFS), else the sidecar's, always `live` when running;
  `list` shows live states as "contents changed since capture". New verbs `pin STATE`, `unpin STATE` and
  `snapshot --pin`. Retention never selects a pinned state; `delete` ignores `pinned`. The slug-`install` rule goes.
- **D23 Hash cache (M5).** `<control_dir>/cache/kernel-hashes.json`, mode 0600, atomic, written only under the writer
  lock.
  Record: `{"v": 1, "files": {"<dev>:<ino>": {"size", "mtime_ns", "ctime_ns", "sha256"}}}`, keyed on
  `(dev, ino, size, mtime_ns)`, with `ctime_ns` as an extra validator: btrfs snapshots share inode numbers and
  subvolume `st_dev` values can be renumbered across mounts, and an in-place rewrite changes ctime. An entry is
  invalid when any field differs. Entries a full publication did not use are dropped. An unreadable or other-version
  file counts as empty, never as an error. ESP pairs are trusted by content-addressed name plus both sizes. A fresh
  copy is hashed once before its rename (B-5), and `check --verify-esp` rehashes every pair.

## 8. `check` and JSON (H4, B12)

- **D24 `check` (H4).** Read-only under `LOCK_SH`. Boot-specific rules come from `Boot.inspect()`, the rest from
  `check.py`.
  - **Errors (exit 5):** C2 an owned entry references a missing or empty pair file (GRUB: a missing kernel file);
    C3 the default does not resolve to a published managed state (suffix-less, glob, stale, unknown); C4 a pending
    one-shot names no owned entry; C5 `.dr-state.tmp.*` scratch left in an ESP or control directory; C6 the ESP
    marker or a format file is missing, invalid or newer; C7 the counter is missing or below the floor.
  - **Warnings (exit 0):** C1 a stale owned entry; C8 a managed state without a sidecar; C9 a managed state with a
    kernel but no entry (degraded; ZBM checkpoints exempt); C11 a sidecar whose `state` differs from its file name,
    or a sidecar without a state; C12 ZFS BE properties (`canmount=noauto` local, `mountpoint=/`, P-rollback-42).
    **Info:** C10 unmanaged objects.
- **D25 Versioned JSON (H4, B12).** Fields can be added freely. A removal or rename bumps the major version. `null`
  means unknown.

```json
{"schema": "dr-state.list/1", "format": 1, "storage": "btrfs", "boot": "systemd-boot",
 "running": "@os-…", "default": "@os-…", "oneshot": null,
 "states": [{"name": "@os-…", "sequence": 2, "created_utc": "2026-11-18T12:01:00Z", "slug": "apt",
   "kind": "checkpoint", "pinned": false, "contents_changed_since_capture": false, "source": "apt", "reason": "apt",
   "note": "", "parent": "@os-…", "metadata": "recorded", "kernel": "6.12.117+deb13-amd64", "entry": "os-….conf",
   "published": true, "running": false, "default": false, "oneshot": false}],
 "unmanaged": [{"name": "@os-0001", "kind": null}]}
```

`show S --json` returns `{"schema": "dr-state.show/1", "state": {<list fields>, "os": {...}, "packages": [...],
"apt_actions": [...]}}`. `check --json` returns `{"schema": "dr-state.check/1", "ok": bool, "violations": [{"code":
"C3", "severity": "error", "subject": "...", "detail": "..."}]}`. Guest scenarios (B12, P-rollback-26) assert on
these, on `bootctl --json`, `/proc/cmdline`, boot_id and packages, never on file shapes.

## 9. Global format versions (M2, B1)

- **D26** `<control_dir>/format` and `<esp>/EFI/dr/format` each hold one integer. An absent file means format 1, which
  is exactly today's layout, so nothing migrates; the first locked verb writes `1`. A malformed value, or one greater
  than `dr_state.FORMAT`, refuses every write (`FormatError`, exit 3); reads continue with a warning. A future bump is
  applied by the newer tool under the lock.

## 10. Payload as files (M10)

- **D27** `scripts/debian-rollback/files/` is the target image. Installers and the ISO builder copy it verbatim with
  modes, and the guest driver reads it. It holds `usr/local/sbin/dr-state` (launcher),
  `usr/local/lib/dr-state/dr_state/` (the only source tree; unit tests import it there),
  `etc/apt/apt.conf.d/80dr-state` (the one APT hook plus Post-Invoke) and
  `etc/kernel/{postinst.d,postrm.d}/zz-dr-state`. The runtime lands in P-rollback-20; the hooks leave the heredocs in
  P-rollback-25. `install-btrfs.sh` stops calling
  `dr-state _state-name`: it prints the initial name with `printf`, and `initialize-state` stays the only validator,
  so the Live system needs no Python. The dev-only hot-patch helpers in dr-serial ship the whole `files/usr/local` tree
  and are refused with `DR_ACCEPTANCE=1` (P-rollback-25).

## 11. Parity strategy (L1, R3)

- **D28 Injection (L1).** `DR_STATE_TEST_*`, `TEST_MODE` path rewriting and every `_xxx` verb are deleted, and three
  mechanisms replace them:
  1. **`--sysroot DIR`**, a documented global option. Every absolute path resolves under `DIR`: `/.top`, `/boot/efi`,
     `/run`, `/etc/os-release`, `/etc/fstab`, `/proc/cmdline`, `/proc/sys/kernel/osrelease` (kernel at snapshot, same
     value as `uname -r`), `/sys/firmware/efi/efivars`. dr-state mounts nothing there and skips mountpoint checks (the
     operator assembled the tree; this also serves a mounted target). Programs still come from `PATH`.

## 12. Boot path, order, unknowns (R4)

- **D32 No Python on the boot path (R4).** GRUB reads `grub.cfg`/`grubenv`, systemd-boot reads `loader.conf`, the
  entries and the pairs, and ZBM reads pool properties. No dr-state unit runs at boot. Recovery is the boot menu: an
  older entry, or a BE or snapshot in ZBM. `set-default` and `delete` then run in the recovered state, on its intact
  `python3` and the shared runtime. If the runtime itself is broken, the menu still boots, and ROLLBACK-RECOVERY
  documents the manual one-liners (`grub-editenv … set saved_entry=`, editing `loader.conf`, `zpool set bootfs=`).
