## Observed mechanism

The current stop path calls `_finalize_session_locked()` while holding the server registry lock. That helper signals the sampler, waits with a 10-second `join(timeout=...)`, then continues writing terminal artifacts and releasing placement without checking whether the sampler actually exited. A slow or blocked sample/placement/DAMON operation can therefore race the terminal writer, corrupt or misstate the Summary, or release resources while an owner is still using them. The serial request loop also lets slow start/report work delay stop and status. Kill evidence currently lives in the in-memory watch tracker; orphan recovery can lose it and can overwrite a Summary already committed before a crash.

This is separate from CP-12, which fixed the earlier case where an enforced kill never set the session terminal event. Keep CP-12 closed.

## Required contract

- [D-33 in `DESIGN.md`](../../DESIGN.md#416-bounded-stop-and-sampler-owned-finalization-d-33) is the normative state, response, admission, kill, Summary, restart, watch, persistence, DAMON, and rollout contract. Keep it synchronized with both RG-55 interface-contract copies and `docs/PROTOCOL.md`; this backlog entry does not redefine those shapes.
- A published session has one finalization owner: its sampler after its current callback unwinds. `stop` and daemon shutdown request stopping; neither concurrently writes terminal records, releases placement, closes DAMON, or frees capacity. Every stop that observes nonterminal state can wait up to 20 seconds on its own request, without creating a second finalizer or resetting the first trigger.
- A nonterminal stop response always includes `kill`: exact `killed` evidence for a durable applied receipt, exact `unknown` evidence for durable intent without a receipt, and `null` only when there is no intent or a proven pre-write refusal. This applies to both `stop-pending` and `finalization-failed`.
- Admission is bounded and has no application queue: 16 control handlers, 32 watch streams, 32 request-line readers, and the existing listen backlog of 16. After reading a complete request line, a saturated handler returns exit-2 `busy`; when no reader slot exists, pause acceptance and do not claim the request received `busy`. A partial or oversized line is closed without dispatch.
- Start accepts an optional positive integer `deadline_monotonic_ns` on the socket and through `ctl start --deadline-monotonic-ns`. `ctl` sends `null` when the option is omitted; socket clients may omit the key or send `null`, and both retain legacy behavior without a deadline guarantee. Expiry returns `start-deadline-expired`; a deadline more than 60 seconds in the future returns `bad-argument`, both with exit 2 and no publication. Expired deadlines are rejected before reservation lookup; a valid deadline checks all same-key reservations before new placement or DAMON setup. A same-key `preparing` reservation returns `session-starting`; `stopping`, `finalizing`, or `recovery-required` returns `session-stopping`, including a journal-only reservation with no public session ID. Disconnect before publication cannot leave an unattended session; a failed reply after publication requests sampler-owned cleanup with `start-reply-failed`.
- The sampler takes the session lock only to linearize the final stop check and claim its one kill attempt, then releases the lock before intent fsync, the kernel write, and receipt fsync. No filesystem, kernel, process, or other blocking I/O runs while the session lock is held. If stop wins that short lock, write no intent and leave `kill:null`; if the sampler's claim wins, a later stop cannot cancel that attempt and waits outside the lock. Persist kill intent before the kernel write and an immutable applied receipt after a successful write, before publishing `killed`. The shared public kill object is `{attempt_id, verdict, reason, via, cgroup, detail}` with closed `verdict`, `reason`, and `via` values. A session makes at most one kernel kill attempt. A crash or ambiguous write result after intent but before receipt is `unknown`; never infer success, classify it as a proven refusal, or replay the kill. Summary `kill` always preserves durable evidence; a live-finalization `watch.reason` preserves `kill.detail`. A crash-recovered Summary omits `watch` because its tracker snapshot is not persisted. `unknown` is a watch verdict, leaves the sampler running, and is never the `killed` end reason; only `killed` can authorize Run-Gate to report `STALLED`.
- On startup, rebuild unfinished sessions and reservations before accepting requests; finalize published sessions as `daemon-crash-recovery` rather than resuming sampling, unless a durable applied-kill receipt proves the session finished by kill; retain capacity and identity until terminal manifest commit; do not overwrite a committed Summary. Published-session Summary causes use the stable D-33 vocabulary: `start-reply-failed`, `session-error`, `daemon-shutdown`, and `daemon-crash-recovery`; sampler exception text remains in logs. A newly synthesized recovery Summary omits the optional `liveness` and `watch` blocks because CP-24 does not persist tracker snapshots; a committed Summary is adopted byte-for-byte. A durable applied-kill receipt that precedes a later shutdown trigger or daemon crash wins Summary/watch precedence; a shutdown that wins the final kill check prevents intent and the kernel write. If cleanup ownership cannot be proved, keep the session `recovery-required` without publishing a terminal Summary. Each tick is the rows in `samples.jsonl.gz`, `host.jsonl`, optional `damon.jsonl`, and one `tick-commits.jsonl` record. Tick appends are not individually fsynced; recovery validates each committed gzip/JSON range and offset, truncates only uncommitted suffixes, and retains corrupt committed data as `recovery-required`. Fsync sample zero and its commit before publishing `live`; every later CP-24 non-preparing session must have at least one valid tick commit. Terminal publication fsyncs all series and commit files, then Summary and manifest in order. `events.jsonl` is independent and is not truncated with a tick.
- Before placement, DAMON setup, or sampling, durably write `manifest.json` as a CP-24 preparation record with `session_format:"cp24"`, session ID, container ID, nullable token, and `status:"preparing"`. New placement journals also persist `session_format`, container ID, and token before scope creation. Recovery classifies by this marker; it does not infer the new format from a field or file that may not exist yet. An unknown marker version refuses daemon admission.
- Cleanup proof is the terminal boundary. Failed PID restoration, leaf removal, placement-completion journal write, or unconfirmed DAMON stop is `recovery-required`, whether or not a DAMON slot was quarantined. Do not create a new Summary or terminal manifest; keep the slot/token, return `finalization-failed`, emit no watch `end`, and refuse `gc`/`report`. A Summary or its directory-sync failure has no committed Summary. If Summary was durably committed but manifest write/sync fails, preserve its bytes exactly, keep capacity, and complete the manifest after restart only after cleanup is re-proved. Only a committed terminal manifest after cleanup proof frees capacity.
- Upgrade compatibility is explicit. A valid legacy terminal Summary with complete placement cleanup remains terminal and does not consume session capacity even when its old DAMON stop is ambiguous. After complete inventory classification, one read-only startup `nr_kdamonds` read gates new DAMON acquisition. A zero count permits recovery of a legacy live owner after placement proof; a nonzero or unreadable count leaves possible live owners `recovery-required` and disables new DAMON acquisition without blocking ordinary sessions. A nonempty legacy session directory with no manifest—including one with a placement journal or `events.jsonl`—blocks admission before any DAMON read because the old daemon could acquire DAMON before writing its manifest. Preserve all bytes. A legacy live manifest is never resumed or assigned inferred kill evidence; strictly parse aligned old rows, then synthesize `aborted`/`daemon-crash-recovery` with `kill:null` only after the startup pool count proves no sysfs kdamond is running and placement cleanup is proved. Malformed, misaligned, or zero-sample legacy state is recovery-required. A terminal manifest without Summary is recovery-required; rejected pre-publication records remain refusal records. For a classifiable legacy manifest, a placement journal with a valid token but no container ID reserves that token across all containers; a CP-24 preparing marker may reserve its full key before publication. New successful stop responses carry outer `summary_format:"cp24"` or `"legacy"`; the CLI rejects missing CP-24 fields when the marker says `cp24` and accepts the old Summary shape only when classified `legacy` (or when talking to an older daemon that lacks the marker).
- Watch keeps cadence while stopping, then emits exactly one terminal `end` after durable terminal commit. D-33 defines `unknown` verdict semantics, end precedence, `start-reply-failed` mapping, and the `finalization-failed` error event. Recovery-required stop fails immediately; startup retries identity-proven cleanup once before accepting requests. Restarted unresolved state remains visible and consumes capacity; CP-24 adds no public DAMON recovery verb. The contract-2 observer socket remains unchanged. CP-24 owner records include the host boot ID: on a host-local sessions volume, a different current boot proves an old active monitor is gone; on the same boot, a zero startup `nr_kdamonds` count proves no sysfs kdamond is running and durably transitions the owner to `off-confirmed`; a nonzero or unreadable count disables new DAMON acquisition and keeps that active session reserved. Startup performs no DAMON read/write before complete inventory classification; afterward it performs one read-only pool-count read and no per-slot probe. Pool residue remains untouched; CP-26 owns durable global-pool provenance and reset, while CP-25 owns session quarantine. Preserve the journal, stop new profiling work, verify host placement/DAMON state, and restart the singleton through CIU only after host state is safe; never delete session state or clear a slot manually. If recovery still fails, leave capacity reserved and escalate to the host operator.
- Shutdown has a bounded 45-second daemon budget and a 60-second Compose stop grace. Release the CGProfile artifact before Run-Gate, but do not install the new daemon until the compatible released Run-Gate client is installed in every cockpit using this host singleton. Candidate replacement is supervised and lane-quiesced. Use a disposable sessions volume for acceptance that must retain rollback capability. Before stopping a candidate for rollback, quiesce callers, query `version` while it is running, and require ready admission with all counters zero; then stop through CIU and confirm exit. After stop, inspect the preserved volume read-only. Restore the previous daemon only if the complete inventory is readable and contains no CP-24 marker or other state the old daemon cannot parse; a CP-24 terminal record also forbids rollback. Otherwise leave the singleton stopped and preserve the volume; never start the old daemon against incompatible state. This item does not change Run-Gate executable code.

## Acceptance oracles

- Barriers hold intent persistence and the kernel write while concurrent stop and status requests prove they can acquire the session lock and respond; do not test only a blocked sample callback. If stop wins the final locked check, no kill intent or write occurs. If the sampler's kill claim wins, a later stop cannot cancel that attempt. `killed` is never published without a durable receipt; an ambiguous write or receipt failure returns `unknown`, never retries, and keeps the sampler running. Saturated control/watch slots return exact `busy` responses after line parsing; all readers occupied pauses acceptance without spawning unbounded threads.
- Deadline-expired starts return `start-deadline-expired`, and more-than-60-seconds-future starts return `bad-argument`; both refuse before publication. Disconnected clients are refused before publication; a reply lost after publication becomes `start-reply-failed` and cleans up. A same-key request racing `preparing` returns `session-starting` without duplicate placement or DAMON ownership.
- Applied kill plus manifest-write failure plus restart preserves the same receipt and Summary; a kill write followed by a crash before receipt commit recovers as `unknown` and is never retried. Unknown watch verdicts do not emit `end.reason = killed`, and a later threshold cannot cause a second kernel kill attempt; later tracker updates cannot rewrite the frozen kill detail or `summary.watch.reason`.
- A committed Summary is byte-for-byte preserved during recovery. Fault injection before/after every row and commit boundary proves only complete offset-valid, parseable ticks contribute to the Summary; interrupted uncommitted suffixes are truncated, while corrupt committed ranges become `recovery-required` and cannot inflate or silently reduce the Summary.
- Fault-inject PID restoration, leaf removal, placement-completion journal write, an actual `DamonSession` using a fake pool/sysfs that cannot confirm `kdamond_off`, Summary write/directory sync, and terminal-manifest write/directory sync. Cleanup failures produce `recovery-required` without a new Summary. A previously committed Summary survives a manifest failure byte-for-byte, but stop remains failed and capacity stays occupied until cleanup is re-proved and the manifest commits. Assert `stop`, `status`, `version`, `gc`, `report`, and watch `end` before and after restart.
- Every stop that sees nonterminal state may wait up to 20 seconds and returns the exact pending/failure shape when still nonterminal. `already_stopped` reflects the state at request entry, and repeated stop never creates another finalizer.
- Attached/new watches keep cadence, emit each durable verdict once, and send exactly one `end` only after terminal manifest commit. Check sampler-error/kill/shutdown precedence, the recovery `error` event without `end`, and exit codes through both carriers.
- Restart reconstruction includes token/capacity reservations, finalizes rather than resumes sampling, and adopts a previously committed Summary byte-for-byte. `version`, `status`, `stop`, `gc`, `report`, and DAMON quarantine agree for `recovery-required`. Duplicate stop, same-key start, and shutdown reclaim capacity only after durable cleanup.
- Upgrade fixtures cover legacy terminal Summary with old abort cause and DAMON disabled, legacy terminal/live state with possible DAMON ownership, legacy DAMON-unavailable state, legacy live manifest with aligned rows, legacy Summary plus incomplete cleanup, terminal manifest without Summary, unmanifested placement journal, unreadable session root, and malformed session-shaped directory. Legacy token-only state under a valid manifest blocks matching tokens across all container IDs; a nonempty unmanifested legacy directory blocks admission. CP-24 active owners use boot-ID match/mismatch and zero/nonzero/unreadable pool-count cases. Blocked inventory performs no DAMON read/write; classifiable inventory performs one read-only pool-count read and no per-slot access or pool mutation. New session format markers and placement journals persist their format and full identity before any host side effect.
- Literal request/response goldens authored independently of the serializer, both carriers, verb-aware response/docs validation, all three user-facing docs, registered unit/coverage/canary gates, and the mirrored Run-Gate interface-contract copy agree with the public protocol.
