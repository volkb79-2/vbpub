Never kill by pattern: no `pkill`, no `killall`, no `pgrep`-then-kill, no shell loop over `/proc`, and no signal to a group, a negative pid or any pid you did not start. Signal and TERM-trap tests (`kill`, `trap`, `wait`, process and signal behaviour) run ONLY inside a capped container with a private PID namespace, against the exact PIDs that the test spawned and recorded itself; this devcontainer is shared with live controller and production sessions, and a pattern kill here ends other people's work. Run no shell experiment in the devcontainer to try out signal, trap, wait or process behaviour: reason from the code and the bash manual, and let the gate container prove it. If a task appears to need a signal outside such a container, stop and report that instead of experimenting.
