Never kill by pattern: no `pkill`, no `killall`, no `pgrep`-then-kill, no shell loop over `/proc`, and no signal to a group, a negative pid or any pid you did not start. Pi implementer bash and user `!`/`!!` commands run in a fresh user namespace and private PID namespace while the tracked guard files are unchanged. `/proc` remains the host procfs, so the shell can see outer PIDs; the PID namespace prevents the current command from signaling those processes by PID. Namespace PID 1 is `bwrap`, so `kill -0 1` succeeds by design. A `trap` changes only the shell's local signal handling. This guard prevents accidental signal commands through the current launch path; it is not tamper-resistant because a same-user agent can edit the tracked extension, wrapper, worker, or launcher and change how a later command starts (CTL-65). This isolation does not authorize signal experiments in the devcontainer. Signal and TERM-trap tests (`kill`, `trap`, `wait`, process and signal behaviour) run ONLY inside a capped container with a private PID namespace, against the exact PIDs that the test spawned and recorded itself; this devcontainer is shared with live controller and production sessions, and a pattern kill here ends other people's work. Run no shell experiment in the devcontainer to try out signal, trap, wait or process behaviour: reason from the code and the bash manual, and let the gate container prove it. If a task appears to need a signal outside such a container, stop and report that instead of experimenting.
