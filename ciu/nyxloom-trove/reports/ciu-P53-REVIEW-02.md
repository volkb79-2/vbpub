1. **High — retry can discard staged deletions.** [worktree.py](/workspaces/vbpub/.worktrees/ciu-overlay-intent-20261013/ciu/src/ciu/worktree.py:4176) treats `D ` for every tracked path as proof of an untouched `--no-checkout` worktree. The same status results if the first reset completed, CIU was interrupted before saving the fork point, and an operator ran `git rm -r .`. `ensure` then runs `reset --hard` and discards that work. Persist a checkout-attempt phase before reset and refuse automatic reset once an attempt may have occurred. Update the “never resets” retry guidance in [CONSUMERS.md](/workspaces/vbpub/.worktrees/ciu-overlay-intent-20261013/ciu/docs/CONSUMERS.md:133) and [DESIGN-GUIDE.md](/workspaces/vbpub/.worktrees/ciu-overlay-intent-20261013/ciu/docs/DESIGN-GUIDE.md:236).

2. **High — `--profile` can succeed without affecting any CIU root.** The CLI resolves worktree commands to the Git root, while [worktree.py](/workspaces/vbpub/.worktrees/ciu-overlay-intent-20261013/ciu/src/ciu/worktree.py:4421) publishes the requested overlay at the record’s root. When the Git root has only nested CIU roots, as this repository does, [root preparation](/workspaces/vbpub/.worktrees/ciu-overlay-intent-20261013/ciu/src/ciu/worktree.py:4482) prepares those nested roots and returns `ready`; none reads the Git-root overlay. An adopter’s selected profiles are silently absent. Before allocation, require an explicit target CIU root for overlay options or refuse when the selected record root is not a committed CIU root.

3. **High — an existing network’s name is accepted as ownership evidence.** [worktree.py](/workspaces/vbpub/.worktrees/ciu-overlay-intent-20261013/ciu/src/ciu/worktree.py:4854) permits network reuse for an adopted or previously ready record, and [the preflight](/workspaces/vbpub/.worktrees/ciu-overlay-intent-20261013/ciu/src/ciu/worktree.py:4444) then skips the Docker existence check. If that network was removed and another owner created one with the same name before a root repair, `ensure` returns `ready` and a later `up` can use the foreign network. Adoption has the same ambiguity for a pre-existing network. Verify the actual network’s owner, using durable object identity or trustworthy labels; refuse reuse when ownership cannot be proved.

4. **High — the new network-retry oracle is red before reaching its claim.** In [test_ciu_worktree.py](/workspaces/vbpub/.worktrees/ciu-overlay-intent-20261013/ciu/tests/tests/test_ciu_worktree.py:1213), the replacement generator returns success for identity-only generation without writing the facts that `_runtime_identity` immediately reads, so the expected full-generation failure is unreachable. After correcting that fake, [line 1235](/workspaces/vbpub/.worktrees/ciu-overlay-intent-20261013/ciu/tests/tests/test_ciu_worktree.py:1235) still looks for `logical-one`, which this test never creates. Have the fake write identity facts, then assert against `network-retry`.

5. **Medium — `ensure` ignores explicit base and directory constraints.** [worktree.py](/workspaces/vbpub/.worktrees/ciu-overlay-intent-20261013/ciu/src/ciu/worktree.py:4776) compares name, branch, and path, but not the supplied `--base` or `--worktree-dir`. Automation can run `ensure NAME --base <new SHA>` and receive an older ready checkout as an “exact” match. Preserve whether those options were explicit in [the parser](/workspaces/vbpub/.worktrees/ciu-overlay-intent-20261013/ciu/src/ciu/cli.py:1757), then compare them with the recorded allocation commit and path or refuse an unprovable comparison.

6. **Medium — an explicitly empty profile is silently treated as no request.** [worktree.py](/workspaces/vbpub/.worktrees/ciu-overlay-intent-20261013/ciu/src/ciu/worktree.py:1131) bypasses its non-empty-list validator when `profile=""`. Thus `create`, `adopt`, or an absent-record `ensure` with `--profile ""` can return `ready` with no profile overlay. Validate whenever the option is present (`profile is not None`) so the existing blank-list refusal applies.
