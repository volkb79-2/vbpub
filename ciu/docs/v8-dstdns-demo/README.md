# v8-dstdns-demo — dstdns recreated in CIU v8 notation (draft.5)

This directory is a **worked example**, not a deployment: dstdns's real configuration (27 realizations, the global config, the host inventory, the gate) rewritten in the v8 notation of `../SPEC-V8.md` (normative, **8.0.0-draft.5**) and `../CIU-V8-TESTING-GATE-PROPOSAL.md` (rationale, **rev 3.2**). **Header convention:** a per-file header comment such as "v8 notation (plain TOML, draft.3)" names the draft that *introduced* that file's notation, not the draft the file is maintained at; every file here is maintained at the draft this README names, and the round-1/round-2 corrections are listed under D26–D37 below. Rewritten 2026-09-02 from the rev-2.1/draft.2 demo after the adversarial review (`../CIU-V8-ADVERSARIAL-REVIEW-2026-09-02.md`): every declaration file is now plain TOML (no Jinja), consumers declare **bindings** instead of reading **routes**, secrets are structured tables, and the contract of a LogicalService is derived. Every declaration file parses as TOML; the compose templates are Jinja. Hook scripts and application config templates (`config.toml.j2`, `nginx.conf.j2`, …) are referenced by name and not copied — they need the re-rooting listed under "Migration notes".

Start with `examples/minimal/` (one stack, one lane, four files) before reading the dstdns-scale files.

## The four layouts

`local` (everything on the devcontainer), `prod3` (gstammtisch: mesh/core/db/identity/worker-db · rs1002: mesh/apps/worker-io/observability · tsstammtisch: mesh/edge/global-services, public ingress), `staging2` (two of the same hosts, different bundles), and an `mtls-public` sketch (an `address` network with `tls = "mtls"` and a pki provider; nothing changes in any stack file). Cross-host reachability is derived per binding: controller's `binds.database` (`to = "main_db.sql"`, `delivery = "env"`) injects `POSTGRES_HOST=dstdns-98535c-db-core-postgres` on `local` and `POSTGRES_HOST=100.64.0.11` on `prod3` — the compose template carries no address at all.

## What v8 derives that dstdns typed by hand (counted in the v7 sources)

container/host names (70/68 template references), the `app_identity.*` registry (~45 tables + 41 inlined copies), `[topology.services.*]` routes (12) and — new in draft.3 — the per-consumer address mapping tables the rev-2 demo still carried in 17 stack files, `[deploy.phases]` ordering (9 phases), the `stack:infra/vault:healthy` self-declarations (4), the 30 spellings of the assay version, the hand-typed `contract` lists of rev 2 (14 facts on `main_db` alone), replica services `worker-io-1/-2` and `worker-db-1/-2`, secrets stanzas, `depends_on` conditions, healthcheck timing, `ports:` lines (from bindings with data only), labels, networks, cross-host port publication.

## Decisions taken while writing this demo (for review)

Design-level (also recorded in the proposal §4.3 and the spec):
- **D1** Declarations are data: `ciu.toml`, `ciu.site.toml`, `ciu.instance.toml`, `ciu.stack.toml` are plain TOML; render contexts exist only for `ciu.compose.yml.j2` and config-file templates: `project`, `instance`, `host`, `ciu_stack` (own services with `identity`/`health`/resolved `endpoints`/template-delivered `binds`), `realization` (merged view), `networks`, `state`, `stack_dir`, the stack's consumer tables, user tables, `registry`, `vault.paths`, `secret()` (S3.5.1). There is no two-pass render.
- **D2** ciu **injects** `container_name`, `hostname`, `networks`, the fixed `ciu.*` labels, `CIU_*` identity env, the variables of env-delivered bindings, `secrets`, `depends_on`, `ports`, config-DIRECTORY mounts, healthcheck timing (`interval`/`timeout`/`retries`/`start_period` — templates keep only `test:`) and cgroup fields into the rendered compose; templates that write them are refused (equal `container_name`/`hostname` tolerated). Consumer labels (`de.vxxu.volkb79.*`) are literal in templates; the v7 `managed-by=orchestrator` and per-replica `instance=<n>` labels are gone (ciu stamps `ciu.managed-by`, `ciu.replica`).
- **D3** `project.registry.namespace` is declared once; because a declaration file cannot reference it, project-built images are spelled `dstdns/<name>:<tag>` literally in stack files (the registry validator can cross-check the prefix).
- **D4** `project.health` is merged into every service's `health` table and injected; healthcheck stanzas need no conditionals and no timing lines.
- **D5** Identity elision: when a service key equals its realization name the service part is omitted (`dstdns-98535c-controller`). Uniqueness is checked, not structural (S4.2.5).
- **D6** One default realness level (`[realness] default = "live"`) plus per-service pins; the per-layout record is a constraint on later selections (S9.4.2).
- **D7** A variant may name which service of a multi-service stack carries the capability — the **variant service** (`object_store.live = { realized_by = "db_core", service = "minio" }`); the string form `live = "db_core"` is the 1:1 case.
- **D8** `from = "generate", store = "vault"` secrets derive `vault:secret/<path>` facts; hook-minted facts are declared on the hook entry (`{ run, service, provides }`); a `from = "vault"` secret derives an edge to its minter. `[vault.paths]` is read by ciu: secrets say `path = "<key>"`.
- **D9** `delivery` ∈ `file | env | configfile | native | hook | none`, mandatory; stack-level shared secrets under `[ciu_stack.secrets.<key>]`; host-scoped secrets consumed through `from = "host", entry = "<entry>"`.
- **D10** Endpoint names are unique per stack; fronted endpoints are `publish = "proxy"` with a `host_port` and an `allow_from` scoping the hosts that may reach them.
- **D11** `per_host = true` realizations (`tailscale_node`): deployed on every host of a layout that reaches them, the same identity on each, never a binding target with data.
- **D12** **Bindings replace `init_requires`/`uses`/`routes`.** `requires = ["x"]` is the ordering-only form; `binds.<local> = { to = "x.<endpoint>", wait, delivery, env_prefix, facts }` is the data form. `wait = "none"` marks the runtime-only dependencies that used to be `uses`: `tracing` for controller/worker-io/worker-db/webapp-server/otel-aggregator, `controller` for worker-db/webapp-server/test-runner, `identity_provider` + `otel_collector` for webapp-server, `otel_aggregator` for the node collector, `otel_collector` for docker-stats-exporter, `webapp_ui` for authentik, the four fronted backends for the reverse proxy, `webapp_server`/`browser_service` for test-runner. Every binding target must be selected by the bundles (S5.5.4), which is why the joined worktree example also joins `identity_provider`/`tracing`/`otel_collector`.
- **D13** The instance-file/generated-file split (S14.2): `ciu.instance.toml` is the operator's (plain TOML, appended by `ciu instance add`); `ciu.instance.generated.toml` is CIU-owned (identity, host facts incl. `hostname`, build facts, the realness records).
- **D14** Host-scoped secrets (S10.4): the reverse proxy consumes the edge host's `tls_cert_pem`/`tls_key_pem` as file-delivered `tls_cert`/`tls_key`; every host a layout places the stack on must declare both entries (S10.1.3), so `localhost` carries a `from = "file"` dev pair for the `local` layout. `[network.public]` has no `tls`: network-level `tls`/`mtls` means ciu-managed service TLS (S10.5), not proxy termination.
- **D15** DNS-safe identities (S4.2.1): `_` in realization/service names maps to `-` in every derived string.
- **D16** Derived cross-host publication (S7.4.1) follows **bindings with data only**: an instance-only endpoint is published on the provider host — bound to that host's address on network N — only when some cross-host binding with an endpoint resolves over N; a bare `requires = ["vault"]` (consul's ordering dependency) publishes nothing. `ciu check --layout prod3` lists every publication.
- **D17** **The contract is derived** (S5.3): consumers that own a database role list it on their binding (`facts = ["pg:db/dstdns", "pg:role/controller"]`), MinIO users list `minio:user/<name>`; every variant of `main_db` (live `db_core`, seeded `db_core_seeded`) is checked against the union. The rev-2 `[service.main_db] contract` (14 facts) is gone.
- **D18** Delivery choice: `env` when the compose template only needed HOST/PORT/URL as variables (most application stacks: `POSTGRES_*`, `REDIS_*`, `CONTROLLER_*`), `template` when the value is composed (a `host:port` string for the SkyWalking agent, `<url>/contract` for pwmcp, an OIDC issuer, nginx upstreams, config-file values).
- **D19** The rev-2 consumer mapping tables (`[ciu_stack.<svc>.database] host = "{{ routes… }}"`) are gone: addresses come from bindings, names from `registry.*`, and the workflow/pubsub keys from user tables, all read directly by templates.
- **D20** `[deploy.env.defaults]` (TZ, PYTHONUNBUFFERED, LANG) became the consumer user table `[env_defaults]`; templates loop over it as before (R-13).
- **D21** The v7 Jinja `{% set pubsub %}`/`queue_keys` maps became literal channel names in `[registry.redis.users.*].permissions` plus the `[pubsub]`/`[queue_keys]` user tables (one spelling each; the redis hook reads both from its context).
- **D22** `[testing.lanes.gate]` is a `sequence` lane (schema → unit → assay-dlq) — one process, no nested `ciu gate`.
- **D23** A second gate environment `clean` (`mode = "ephemeral"`, `image_from = "tester"`) carries `binds.db`/`binds.redis` with env delivery; the `sql-mutation` lane runs there and assay's `cw2b_schema` lane reads `POSTGRES_HOST`/`POSTGRES_PORT` as `required-env:` facts. The `tester` exec environment needs no `binds`: its container already has the runner's env-delivered bindings and `docker exec` inherits them.
- **D24** No built-ins: `[hosts.localhost]` and `[layouts.local]` are declared (written by `ciu init` in a fresh project); the minimal example shows the whole ceremony.
- **D25** `require_provenance = true` on the `sql-mutation` and `release` lanes: the containers under test must match `HEAD` (S16.5.6).

Changed by the third-party review round (draft.4, 2026-09-03; `../CIU-V8-THIRD-PARTY-REVIEW-RESPONSE-2026-09-03.md`):
- **D26** `[network.<n>] realized_by` names a **LogicalService** (`mesh_node`, `reverse_proxy`), whose selected variant service carries readiness (T-04).
- **D27** Project-built images declare `build = { context, dockerfile }` on the service (twelve services); ciu injects the compose `build:` stanza and templates no longer write it; there is no vendor-image list (T-29).
- **D28** Demo defects the review found and this round fixed: the tester's governance (`memory_max = "4G"`, at least the largest exec lane's cap, T-12), the `clean` environment forwards `SCHEMA_GATE_PG_DUMP` (T-12), the judge floor is `>=4.1` (ciu's own minimum, T-08), authentik's proxied endpoint moved to host port 9010 (it collided with MinIO's 9000 on gstammtisch's mesh address, T-13), and the site override that bound consul's API to 127.0.0.1 — unreachable for cross-host consumers — was replaced by a pgAdmin setting override (T-13).
- **D29** The resolved example's waves are now derived by the S8.4.1 rule (five waves, all 22 prod3 Realizations); publications are socket claims; `[resolved.capabilities.*]` and the receipt shape are shown (T-14, T-26, T-33, T-35).
- **D30** `examples/minimal/` shows what `ciu init --stack web --image nginx:1.27` really writes (plus `.gitignore`) and marks the hand-added endpoint/healthcheck (T-06).
- **D31** Tester secrets stay `env`-delivered; per-service secret directories are mounted at `/run/secrets` (S10.7), so `*_FILE=/run/secrets/<key>` pointers are unchanged (T-24).

Gone with draft.3 (each file says so where it used to be): `routes.*` in any file; `init_requires`/`uses`/`after`/`init_provides`/`[hooks.provides]`; `directive = "ASK_VAULT:…"` strings, `consumed_by`, `produced_by`; `[service.<n>] contract`; `owned-seeded` (now `seeded`); `request_base`; `deploy.labels.prefix`; `deploy.env.defaults`; `public_fqdn` detection; `.j2` declaration files and the per-stack `ciu.toml.j2` override; the rendered-file lock and its closing `render` table.

## Known deviations and consumer-side findings

- `pg:role/workerdb_ddl` is in db-core's `provides` but `01-init-users.sh` never creates it (v7 data oddity, preserved); no binding lists it, so it is not in any derived contract.
- Consul's hook mints `consul/cmru/controller/token`, which no binding or secret consumes — an INFO under draft.3 (provided-but-unconsumed), not a WARN.
- `tools/admin-debug` was not converted (in no bundle; `ddcli` covers the admin use).
- Hook scripts must be rewritten on `ciu.hookkit` (S12.5): they read identities and resolved bindings from the hook context v2, emit `state`/`secrets`/`facts` through `emit()`, and use `wait_healthy`/`wait_tcp` instead of hand-rolled polls; the v7 scripts that read `config["<root>"]` or `topology.external.public_fqdn` need the same re-rooting as the templates (`host.fqdn`).
- Image names are literal `dstdns/<name>:<tag>` in stack files (D3).
- worker-io / worker-db secrets keep `env` delivery with every `${VAR}` referenced (S10.2.2); dstdns's real `config.toml.j2` for both workers calls `secret('postgres_password')`, which under draft.3 requires `delivery = "configfile"` on those keys (one secret, one delivery, S10.2.6) — the migration must pick one path per key.
- `[project.control] auth_enabled` replaces the rev-2 `[auth] enabled` switch (the `[auth]` user table keeps `service_user`-style consumer data): a secret's or binding's `enabled` may only name a control flag, and an auth-off site would otherwise materialize `DDCLI_AUTH_PASSWORD` without any compose reference.
- The secret-free scan of draft.2 would have refused `[workflow] work_stream_key = "dstdns:streams:…"` (a bare `_key` suffix); draft.3 S2.4.1 no longer treats a bare `key` as sensitive.

## Migration notes for the files not copied

`config.toml.j2` (controller, webapp-server, worker-io, worker-db, ddcli, docker-stats-exporter): root `webapp_server.*` → `ciu_stack.server.*`; `deploy.environment_tag` → `instance.id`; `app_identity.*`/`topology.*`/`routes.*` → `ciu_stack.<svc>.binds.<local>.*` (template-delivered bindings only — an env-delivered binding is not bound in templates, S3.5.4) or `registry.*`; every `secret()` call requires `delivery = "configfile"` on that secret. `nginx.conf.j2`/`nginx-tls.conf.j2`: upstreams from `ciu_stack.nginx.binds.<backend>.host/port/path`; listen ports from the endpoints; `ssl_certificate`/`ssl_certificate_key` from `/run/secrets/tls_cert`/`tls_key`. Rendered config files live under `<stack>/ciu.rendered/<svc>/<mirrored target path>` and are mounted by parent directory (S6.9).
