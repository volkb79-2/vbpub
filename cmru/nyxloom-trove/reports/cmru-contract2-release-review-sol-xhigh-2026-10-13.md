## Findings

1. **High — source release blocker: a newly created publisher secret can enter a tester lane.** CMRU inventories secret paths once, then runs several lanes under that inventory ([run_release_gate.py:699](cmru/tools/run_release_gate.py:699), [run_release_gate.py:706](cmru/tools/run_release_gate.py:706)). Run-Gate mounts the selected worktree with ignored files included ([run-gate.py:10393](run-gate-project/run-gate.py:10393)). If another writer creates a tester-readable `cmru.secret.toml` after inventory, the gate does not mask it, despite the documented “every” claim ([CONSUMERS.md:782](cmru/docs/CONSUMERS.md:782)). The lock serializes CMRU gates, not other writers. **Repair:** give lanes an immutable, secret-free view or enforce an equivalent exclusion throughout each lane; rescanning only between lanes leaves the exposure window open. **Oracle:** create a readable secret in a previously empty nested directory after inventory while a real mounted lane is active; its contents must be inaccessible, and the gate must not pass if that guarantee fails.

2. **High — exact-HEAD release qualification is unproved; this is an evidence blocker, not another demonstrated code defect.** The registered Assay gate includes the SQL qualification path ([assay/run-gate.toml:33](assay/run-gate.toml:33)); CMRU’s release step requires its full gate, including mutation ([cmru.toml:38](cmru/cmru.toml:38), [run-gate.toml:99](cmru/run-gate.toml:99)). The saved receipts and SQL hazard history identify earlier commits, not this HEAD. I found no committed receipt establishing an exact-HEAD pass. **Acceptance oracle:** retain revision-bound registered-gate results for Assay, Run-Gate, cgprofile, CMRU and the affected MDT checks; include the PostgreSQL hazard case, tester image identity, and live contract-2 candidate, sibling, shared-ancestor, cleanup and daemon-restart probes. This review ran none of them.

3. **Medium — host capacity is a conditional availability constraint, but the admission wording is unconditional.** The shipped host example caps `dev-gates.slice` at 1.5 GiB ([host-setup.env.example:196](modern-debian-tools-python-debug/host-setup/host-setup.env.example:196)); CMRU mutation declares 2 GiB ([cmru/run-gate.toml:132](cmru/run-gate.toml:132)). Run-Gate checks the named slice but admits with a warning when its cgroup files are hidden or unreadable, and does not establish ancestor or host headroom ([run-gate.py:4073](run-gate-project/run-gate.py:4073)). The statement that it *will refuse* an over-budget request is therefore too strong ([CONSUMERS.md:240](run-gate-project/CONSUMERS.md:240)). **Repair or oracle:** qualify that statement and record effective slice, ancestor and host capacity before serialized campaigns; if prelaunch refusal is the promised behavior, test it with a hidden cgroupfs and a 1.5 GiB effective cap. A capacity refusal is not a mutation result.

4. **Medium — deferrable tester image provenance gap.** The Assay launcher uses mutable `tester-unified:local` ([tester-unified-gate.sh:913](assay/tools/tester-unified-gate.sh:913)). A stale image can test current bind-mounted source with an older dependency closure. **Repair:** bind the image’s source revision to the gate receipt and refuse a mismatch. **Release acceptance alternative:** retain the image ID and exact-HEAD build provenance with each gate result; the regression oracle builds an image from commit A and requires a commit B gate to refuse it.
