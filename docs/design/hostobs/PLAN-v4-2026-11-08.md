## B. Wire protocol `hostobs/1`

### B.1 One framing, two encodings

- **Mode by first byte** (kept from v3): `{` = JSON lines for the whole connection (ctl, shell, launchers, debug);
  `HOB\x01` + `u16 major` + `u16 minor` = binary. Anything else: one JSON error line, close.
- **Frame header (12 B, LE):** `u32 len | u8 type | u8 flags | u16 0 | u32 corr`. Max frame 16 MiB; a partially
  written frame is finished or the stream is closed, never abandoned mid-frame.
- **Frame types:** `REQ/REP/EVT` = small JSON object (control envelope; errors are `REP ok:false`); `DICT` =
  dictionary delta or full generation; `BLOCK` = column block (live tick, series reply page, snapshot reply,
  procs page); `END` = end of a paged reply.
- **Decision (D4): fixed-width typed columns, not the sampler's varint TLV.** Reasons: raw u64 counters must be
  exact (f64 loses integers above 2^53 [K]); Python reads a column with one `memoryview` + `struct.unpack_from`
  (explicit LE) instead of a per-value varint loop; one codec serves live, history replies and disk segments.

| Alternative (astra C) | Verdict |
|---|---|
| sampler varint TLV (v3) | rejected: f64 values, per-value Python loop, no quality column |
| postcard / bincode | rejected on fit: Python still needs a schema-specific varint decoder |
| rkyv / Cap'n Proto | rejected: Rust- or machinery-centric, no stdlib Python path |
| FlatBuffers | **fallback** if SP-4 shows the custom codec's maintenance cost exceeds `flatc` + runtime dependency |
| Protobuf / MessagePack / CBOR | rejected for volume paths; JSON already covers low volume |
| Arrow IPC / Parquet | deferred: offline export only, never the live store |

### B.2 Column block

```
BLOCK   := u16 n_sec, u16 0, n_sec × SECDIR{u16 kind, u8 ver, u8 flags(bit0=required), u32 len}, bodies (8-byte aligned)
HDR     := boot_id[16], u64 epoch, u64 seq, u64 mono_start_ns, u64 mono_end_ns, u64 boot_ns, i64 real_ns,
           u32 dict_gen, u32 n_rows, u32 dropped, u32 flags
ROWS    := n_rows × u32 ent (dict index → inc), n_rows × u32 t_off_us
COL     := u32 metric (dict index), u8 type{1=u64,2=i64,3=f64}, u8 kind{gauge,counter,state}, u16 0,
           n_rows × 8 B value, n_rows × u8 quality, pad to 8
TIME    := (history) n × i64 bucket_real_ns, n × u32 covered_ms, n × u16 samples, n × u8 agg   [replaces ROWS]
```
- Live ticks are **full independent snapshots** of the selected fields (absolute counters). No delta encoding
  against a previous frame, so a dropped frame costs resolution, never decodability.
- History buckets carry `covered_ms`, `samples` and the aggregation kind; counters carry the raw value at bucket
  end plus the covered duration; gauges carry `min/max/mean` columns (sample-weighted, named as such).
- Unknown optional sections are skipped by `len`; an unknown **required** section fails the request
  (`unsupported-section`), never silently.

### B.3 Dictionaries and versioning

- Dictionary entries: `kind` (entity inc / metric / label / free string), bounded UTF-8 (≤ 256 B; cmdline is a
  separate bounded detail reply). Metric entries carry unit, kind, scope, source, permitted aggregation.
- **Generations:** indexes never change meaning within `(epoch, dict_gen)`; a new generation is sent complete
  before any value that uses it; clients drop caches on a generation or epoch change. Query replies and
  exported segments carry their own dictionary (self-contained).
- `hello` returns `proto` major/minor, `features[]` (`peak_reset`, `placement`, `damon`, `enrich`), `limits`,
  `quality_codes`, `boot_id`, `epoch`. Additive changes raise the minor; requests are strict (unknown key =
  `bad_request`, "defaults are hazards"). Payload schemas keep their own names: `summary/2`, `spans/1`,
  `resource-limits/1`, `window/1`, `host/1`.
- JSON integer policy: exact integers (Python, Rust parse them exactly); no JavaScript consumer is supported.

### B.4 Streams, polls, budgets

| Bound | Value (config keys, proposals) |
|---|---|
| clients per level | observe 16, operator 8, observer 128, control 64 |
| distinct live selections | 8; identical selections share one encoded immutable block |
| per-client queued bytes / global | 4 MiB / 32 MiB; full queue drops the oldest unsent `BLOCK`, counted in the next `HDR.dropped`; `DICT/REP/EVT` over budget → close with reason `slow-client` |
| outstanding requests per client | 4; history pages under a separate query budget |
| frame completion age | 5 s, then close (defeats the byte-dribbling client) |
| request size / deadline | control 1 MiB in 25 s (RG55 §8.1); observer/observe 4096 B in 5 s |

Sampling never waits for a client [V `S:docs/SAMPLER-PROTOCOL.md:16` per v3]. Control/observer verbs have
their own serving threads so a slow telemetry subscriber cannot delay them.

### B.5 Golden fixtures (shared Rust/Python, independent)

`hostobs/fixtures/wire/<case>.{json,bin}`: `.json` = decoded typed values written from `docs/WIRE.md`, `.bin` =
canonical bytes. Both the Rust encoder and an **independent stdlib Python reference encoder** (written from the
spec, not from the Rust code) must produce the identical `.bin`; both decoders must reproduce the `.json`.
Cases: u64 boundaries (2^53+1, 2^64-1), negative i64, empty selections, Unicode, missing vs zero, every quality
code, unknown optional section, required-section rejection, truncated/oversized frames, bad lengths, dangling
dictionary refs, generation rollover. Stream scenarios (dropped frames, reconnect/epoch change, dribbling
client) run as deterministic tests against a fake clock. Rust reads fixtures with `include_bytes!`; Python runs
them in the `conformance` lane.

## C. Data model

### C.1 Identity

| Concept | Key | Notes |
|---|---|---|
| boot | `/proc/sys/kernel/random/boot_id` | in hello, every HDR, every segment |
| daemon epoch | u64 at probe start | restart = new epoch; windows/sessions/open spans are lost |
| cgroup incarnation `inc` | daemon-assigned u64, minted on first observation of `(mount id, cgroup inode)`; path, parent inc, `first_seen`, `last_seen` are labels | a new inode at the same path = new inc; missing on one scan is not deletion (2 scans) |
| process | `(boot, pid, starttime ticks)`; pidfd only for targeted acts | never PID alone |
| labels (docker name, image, unit, origin) | bound to an inc with `source` and `observed_at`; expire with the inc | stale enrichment never relabels a replacement |

### C.2 Values and quality

Every value = (inc, metric, raw value, quality, interval). Quality u8: `0 ok`, `1 absent` (file/key not
present: controller off), `2 unreadable` (permission/error), `3 stale` (older than 2× interval),
`4 reset` (counter went backwards: new baseline, no rate), `5 not-sampled` (shed under load or decimated),
`6 unsupported` (kernel lacks it), `7 unknown-topology`. Zero is a value; absence is never zero (mdt_capacity's
zero substitution [V astra cites `mdt_capacity.py:824`] is a consumer bug to fix when it switches).

### C.3 Raw counters vs derived rates

- Wire and store keep cumulative counters as raw **u64** (CPU usec, io bytes per device key, PSI totals, faults).
- Rates are derived in `model` over the **actual** monotonic interval; zero dt gives no rate; a reset gives
  `quality=reset`; after missing samples the delta spans the whole real interval and is not assigned to the last
  nominal bucket. The same function is exposed to Python through fixtures (Python reimplements it, tested
  against the same expected rates), and the probe serves derived rates only on request (`derive: true`).
- Hierarchy: inclusive parent counters are never summed with descendants; host totals come from host files.

### C.4 Events and typed spans (operator idea 1)

| Field | Type / rule |
|---|---|
| `kind` | `begin \| end \| point` |
| `name` | `^[a-z][a-z0-9_.-]{0,63}$`; estate names: `run`, `lane`, `candidate`, `candidate.prep`, `candidate.build`, `candidate.run`, `txn`, `txn.step` |
| `key` | optional client key (≤ 64 B); default = `name`; unique among the issuer's open spans |
| `ctx` | `{run, lane, candidate, txn, session}`, each ≤ 128 B; the library fills them from `HOSTOBS_CTX_{RUN,LANE,CANDIDATE,TXN}` so nested tools inherit them |
| `outcome` (end) | `ok \| fail \| error \| skipped \| cancelled \| timeout \| abandoned`, plus `code` ≤ 64 B |
| `attrs` | ≤ 8 pairs, ≤ 256 B each |
| `t_mono_ns` | **stamped by the probe at receipt** (CLOCK_MONOTONIC); client time is never trusted. Socket latency (~ms [K]) is below the 1 s session resolution |
| `issuer` | kernel-derived: uid + cgroup inc of the peer (observer level) or uid (control level). Lanes can only annotate as themselves |

- `end` closes the issuer's innermost open span with that key; unknown key → `span-unknown`. When the issuer's
  cgroup inc disappears or the session seals, open spans close with `outcome: abandoned, inferred: true`.
- Bounds: 64 open spans per issuer, 4,096 global, 50 events/s per issuer (token bucket; refusal `rate-limited`).
- Spans go to the events store (host history, topos bands) **and**, when they fall inside a session (issuer inc
  inside the session target, or `ctx.session` = the id from a control issuer), into that session's span table.
- At span `begin`/`end` inside a session the subject scheduler takes an immediate **boundary read** of the
  pre-opened subject fds (a `pread`, µs [V v2 §2]), so per-span counter deltas are exact.
- **Recommendation D1: separate sealed document `spans/1`**, referenced from `summary/2` by
  `spans_ref: {count, refused, bytes, sha256}`. Reason: run-gate copies the summary into `resources` and
  `history.json` [V RG55 §3 "the object run-gate copies"]; an assay R2 lane can produce thousands of candidate
  spans (≈4 per mutant), which must not bloat history. Per span: `duration_s` (mono), `cpu_seconds`, pressure
  stall deltas, io bytes, `memory: {max, p50, p90, source: "sampled+boundary"}`, `outcome`, `ctx`, quality.
  run-gate stores `spans.json` as a lane artifact.

### C.5 Host history tiers (decided; confirmations)

Tiers as in `S:sampler.example.toml` [V]: hot 1 s × 60 s and warm 5 s × 300 s on tmpfs, cold 60 s steps on disk
capped at 1 GiB, writer queue 8 MiB with counted drops, all in `/etc/hostobs/hostobsd.toml` (every key required,
as the sampler already enforces [V file header]). **D3 recommendation:** keep hot/warm on **tmpfs** (reviewed
code, survives a probe restart; the pages count against the probe's cgroup [K]) and set cold `keep_s` = 14 d
with the 1 GiB cap binding first. Estimate [K, measure M7]: 60 s raw rollups ≈ 26 KB/step uncompressed at 84
cgroups [V v3 §3.5 derived] → ≈ 37 MB/day before zstd, so 14 d fits 1 GiB at today's size; at ~500 cgroups the
cap evicts first. Segments are self-contained (dictionary, boot/epoch, mono↔real correlation, CRC per block,
small time index, zstd per block).

### C.6 Session evidence (operator idea 2)

| Item | Decision |
|---|---|
| Resolution | default `interval_s = 1` (allowed 0.25-30 s); exact boundary reads at start, stop and span edges |
| Exact percentiles | nearest-rank (RG55 §7 [V]) over **all samples at the session interval**. Kept as a plain `Vec<u64>` per percentile metric (memory.current + 4 DAMON classes), `select_nth_unstable` at seal. A count-per-distinct-value map is **not** cheaper here: memory.current changes almost every sample, so distinct ≈ samples, and a map entry costs more than 8 B [K]. Per-span percentiles use index ranges of the same vectors |
| Bounded length | client declares `max_duration_s` at start (≤ `session_max_duration_s`, proposal 24 h); at the bound the session **seals itself** with `ended_reason: "max-duration"`, `truncated: true`; the workload is untouched |
| RAM reservation | `ceil(max_duration_s / interval_s) × 5 × 8 B` + span table (`session_max_spans` × 192 B, proposal 16,384) from `sessions_ram_bytes`; 24 h @ 1 s ≈ 3.5 MB + 3 MB |
| Stored series | best-effort spool of column blocks; `store_step_s = max(interval_s, max_duration_s / session_max_points)` (proposal 7,200 points); counters decimate losslessly (raw value at bucket end), gauges as min/max/mean/last; disk reservation = points × row bytes (≈ 360 B → ≈ 2.6 MB) from `sessions_cap_bytes` |
| Admission | refuse `start` with `budget` naming the pool when either reservation fails; sealed sessions may be evicted oldest-first to make room; **an admitted session never loses data later** (spool writes are synchronous to its own reserved file; a disk-full is an explicit `quality` and `stop` reply error, not a silent drop) |
| Seal | `stop` (or max-duration) computes `summary/2` + `spans/1` from RAM, writes them, frees RAM; restart before seal = `session-lost` |
| summary/2 | RG55 §3 keys + §8.7 keys; fixes: `duration_seconds` from CLOCK_MONOTONIC (RG55 §7 says wall clock [V]); `target.inc`, `boot_id`, `epoch`; per-field `quality` map; `spans_ref`; scope `container` keeps RW-21 absolute counters [V RG55 §7] |

### D.2 Optional library and `require_profiling`

`hostobs_client` is an optional dependency of every Python tool. One helper returns one of five states, shown
verbatim in the tool's notice:

| State | Meaning | `require_profiling` unset | `= true` |
|---|---|---|---|
| `absent` | package not importable | run, one visible notice | refuse before work, name the package |
| `unconfigured` | `HOSTOBS_<LEVEL>_SOCKET` unset | run + notice | refuse, name the variable and `hostobsd install` remedy |
| `unreachable` | connect/hello failed | run + notice | refuse, name the socket and errno |
| `refused` | capability missing (`peak_reset`, level) | run + notice | refuse, name the feature |
| `lost` | epoch change / `session-lost` / `window-lost` after start | record `profile_error` | outcome **`EVIDENCE_INVALID`**, workload verdict kept separately (D6) |

`hostobs-mark` is a console script of the same wheel (stdlib, JSON mode, observer socket); it exits 0 with a
stderr notice when hostobs is unavailable, unless `--require`.

## E. Install and rollout (hostcfg rulings applied; tool name `augeaswrap`)

- **hostobs installs itself.** `python3 -m hostobs.front install` (zipimport from the wheel, P-7 stdlib +
  cli-extended only) with `--binary-source <dir|url>` (tarball sha256 checked against `_pins.json` before and
  after the copy [V v2 §4]) and `--add-user LEVEL=USER`. It builds **one augeaswrap request** (`writer = "hostobsd install <ver>"`; no owner, no ownership) in
  memory and calls `augeaswrap` as a library: `plan` (shown; `--dry-run` stops here) → `apply` →
  `verify`. Layered resources carry the required `intent` (`authoritative` | `fallback`) [rev3 Q1/G5]. No
  automatic rollback: a failed apply stops and prints `augeaswrap revert <txn>` (ruling [V]).
- Request content: sysusers (user `hostobs`, groups `hostobs-{observe,operator,observer,control}` with
  `not_gid_of = ["docker"]`, `not_gid = [0]`), tmpfiles, units (`hostobs.slice`,
  `hostobs-probe.service`, `hostobs-act.service`, five `.socket` units), `/etc/hostobs/hostobsd.toml` (0640,
  rendered by the wizard, validated by `hostobs-probe check-config --json`, the Python wizard never duplicates
  Rust rules), optional sysctl `kernel.task_delayacct`, **endpoint** resource →
  `/etc/host-endpoints.d/hostobs.env` with `HOSTOBS_{OBSERVE,OPERATOR,OBSERVER,CONTROL}_{SOCKET,SOCKET_DIR,GID}`
  via `augeaswrap.endpoints` (`@gid:` references resolved after the group step [V hostcfg C.2]).
- Files outside augeaswrap: `/opt/hostobs/<ver>/{libexec,venv}`, `current` symlink, `/usr/local/bin/{hostobsd,
  hostobsctl,hostobs-mark,hostobs-tui}`; state dirs `/var/lib/hostobs/{probe,act}`.
- `hostobsd uninstall` withdraws the endpoint first, then units and files; `--purge` also deletes history and
  sealed evidence; `--remove-groups` deletes groups. It reports owned kernel state (DAMON slots, placements)
  that act could not clean instead of dropping the record.
- `hostobsd doctor --json` (cli-extended doctor registry): units, sockets, groups, endpoint record, kernel
  features (`peak_reset`, DAMON, PSI), tmpfs, act `cleanup-required`. Upgrade refuses while sessions are live
  (exit 3); `--force` aborts them.
- **No host-setup coupling:** no `[vbpub.service_installer]` entry point, no `--describe-inputs`. Whoever
  orchestrates a host (operator, debian-install-v2 stage; no profile runner exists) calls the plain
  `hostobsd install` command. hostobs needs nothing from that orchestrator.
- Consumers read the environment only. Lanes get the observer directory bound read-only at the same path,
  `--group-add $HOSTOBS_OBSERVER_GID`, `-e HOSTOBS_OBSERVER_SOCKET`, and the `HOSTOBS_CTX_*` variables.
- **Rollout:** fresh reinstall only; install refuses foreign `/run/hostobs` or `/etc/hostobs` state. VM empty
  guest first (every milestone from M3), then v1001, then r1002 (M7). Hosts can be reinstalled any time.

## H. Known issues / by design (documented in README and CONSUMERS from M3)

| ID | Issue | Why accepted / what covers it |
|---|---|---|
| K-CRASH | No crash safety: a probe restart loses active sessions, windows, open spans and partial spool segments (discarded); clients see the epoch change or `session-lost`/`window-lost` | operator ruling; `EVIDENCE_INVALID` + retry |
| K-KILL | No kill after a restart (clocks never resume) | lane wall timeout + local watchdog (FS-5) |
| K-POLL | 1 Hz polling misses short-lived cgroups; `first_seen` means observed, not born | BPF tracepoints later |
| K-PROC | Process scan is budgeted; coverage and scan age are reported; process history only for focus subjects and sessions; no retrospective arbitrary PID detail | astra B3; 50k PIDs |
| K-PEAK | Tier maxima of `memory.current` are sampled; span peaks are sampled + boundary reads; only windows/sessions in exclusive cgroups get kernel `memory.peak` | per-bucket read-reset is not atomic anyway [V astra B] |
| K-612 | Window peak reset needs kernel ≥ 6.12, else `PEAK_RESET_UNSUPPORTED` | estate runs 7.2.11 [V v2 §1] |
| K-LEN | Sessions have a declared maximum length; at the bound they seal as `truncated` | exact percentiles stay exact and bounded |
| K-SEAL | Sealed sessions are a cache evicted by quota; consumers keep durable copies | admission never displaces active evidence |
| K-SPAN | Span times are probe-stamped on receipt (socket latency, ~ms); emitters drop spans with a notice when hostobs is unavailable | below 1 s resolution |
| K-ENR | Enrichment is best-effort, allowlisted, expires with the inc | never relabels a replacement cgroup |
| K-DAMON | DAMON results are adaptive estimates, stat-only; failed cleanup quarantines the slot | astra B |
| K-CAP | A compromised probe can lie and open bounded private peak windows; it cannot kill or place | act confirm reads, closed verbs |
| K-CMD | Cmdline only at operator level; redaction is heuristic; operator membership is a trust grant | — |
| K-CFG | No runtime config verbs; SIGHUP reloads thresholds and retention only | edit `/etc/hostobs/hostobsd.toml` |
| K-EXP | No HTML, Perfetto, OpenMetrics, Parquet, offline replay in v1; `export` gives self-contained segments | client-side adapters later |
| K-BPF | No BPF in v1: `NET_*` and per-cgroup latency read `unsupported` | Track C later |
| K-JSON | JSON mode assumes exact-integer parsers (Python/Rust) | no JS consumers |
| K-ORPH | Placement leaves/scopes survive a restart until `gc` | gates slice bounds them |
| K-RUST | Branch coverage on stable, macro bodies, cfg'd-out code (assay K1-K14 [V assay design §H]) | crate region floor, R2 |
| K-SUSP | Suspend is only marked (BOOTTIME vs MONOTONIC gap → `stale`), not modelled | servers do not suspend |

## I. Operator decisions (max 6, recommendation first) and questions

1. **D1 Spans storage:** separate `spans/1` sealed document referenced by `summary/2.spans_ref` (recommended)
   vs a `spans` array inside the summary. Reason: the summary is copied into run-gate history; R2 lanes emit
   thousands of spans.
2. **D2 Long sessions:** exact nearest-rank percentiles with a declared `max_duration_s` (default cap 24 h,
   seal-as-truncated at the bound) (recommended) vs an approximate sketch with a changed, named statistic for
   unbounded sessions.
3. **D3 Tiers:** hot + warm on tmpfs as in the sampler (recommended; RAM-only would lose history on a probe
   restart for no gain); cold `keep_s` = 14 d with the 1 GiB cap binding first (recommended; iogovmon needs
   14 d) vs the sampler's 1 d.
4. **D4 Codec:** fixed-width typed columns for live, history and disk, replacing the sampler's varint codec
   (recommended), with FlatBuffers as the fallback only if SP-4 shows the custom codec costs more to own.
5. **D5 Control socket owner:** act serves `control` and relays bounded read verbs to the probe (recommended:
   the authority boundary sees the client's credentials directly) vs probe serves everything and forwards grants.
6. **D6 Lost required evidence:** a separate `EVIDENCE_INVALID` outcome that keeps the workload's own verdict
   (recommended) vs failing the lane.
