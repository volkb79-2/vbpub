## 0. Decisions

| # | Decision |
|---|---|
| S-1 | **host-setup** is a standalone project: top-level `host-setup/`, distribution `host-setup`, import package `host_setup`, console script `host-setup`, cmru id `host-setup`, tag prefix `host-setup-v`. It is a CLI plus a library. It is stdlib-only at runtime and depends on `cli-extended` only for CLI grammar (`CliRegistry`, `VerbSpec`, `CliFailure`, identity). It knows resource kinds and file formats, never services. |
| S-2 | It is a **guarded applier**. It takes a request, plans it (diff + guards), applies it after confirmation, verifies the result and writes a journal. It keeps **no ownership, no layers, no origins and no history**. The only state is per-transaction journals and pre-images, used by a manual `host-setup revert <txn>`. There is no automatic rollback and no tool-level uninstall. |
| S-3 | Every resource has `state = "present" \| "absent"`. `absent` deletes what the request names: a file, a unit, a drop-in, a JSON key, an edit-selected record, an endpoint fragment or a group. Callers implement their own uninstall as an `absent` request for the resources they created. |
| S-4 | **Shadowing is an error** unless the resource lists that exact shadowing source in `accept_shadow`. Shadowing means a later file or layer overrides a setting we set, or our setting overrides another file's. It is checked for sysctl keys, systemd drop-in directives, whole files in `*.d` precedence directories, tmpfiles paths, sysusers names and `/etc/environment` keys. |
| S-5 | **Augeas is the lens engine for in-place edits** (`edit` kind). It runs as `augtool` from stock trixie `augeas-tools` 1.14.1 on a staged copy, with an overlay lens directory shipped inside host-setup (`-I`). JSON is the one exception: the stdlib `json_key` kind refuses duplicate keys and writes canonical output. The bootstrap stage (zipimported wheels, before apt) never needs Augeas. |
| S-6 | The merged endpoints module moves to `host_setup.endpoints` now. **cli-extended 0.6.0 is dropped.** Every cli-extended commit since `cli-extended-v0.5.3` is endpoint work [V `git log cli-extended-v0.5.3..origin/main -- libraries/cli-extended`: b7cee28a2, 2dfe27d44, 64637ab29, d121458fb], so after the move cli-extended has nothing to release. Consumers keep `cli-extended>=0.5.3`. |
| S-7 | `mdt-cockpit/host-setup` (1,760-line `install.sh`, units, wizard, check.sh) becomes a **caller**. It keeps deciding what the mdt dev tier needs (slices, BuildKit, docker drop-ins, `cgroup-parent`, inotify, udev/BFQ, io-cost) and stops writing files itself (HS-2). Its directory is renamed `mdt-cockpit/dev-governance/` so that the repo does not hold two things called host-setup (decision G1). On-host names (`/etc/mdt/host-setup.env`, `mdt-*` units) stay as they are: renaming them would be a migration. |
| S-8 | First milestone **M1**: host-setup 0.1.0 = the endpoints module plus the project skeleton. It unblocks cgprofile 3.0.0 (REN-B'). The engine follows in 0.2.0, the `edit` kind in 0.3.0. |

## B. Request and state model (no ownership)

### B.1 Request

```toml
host-setup = 1                                   # schema; integer
writer = "cgprofiled install 3.0.0"              # required, one line; recorded in the journal only
[[unit]]   name="cgprofile-control.socket" state="present" text="…" enable=true on_change="restart"
[[unit]]   name="docker.socket" dropin="50-mdt-api.conf" state="present" text="…" on_change="pending"
[[sysctl]] file="60-cgprofile.conf" state="present" apply_now=true
           entries=[{key="kernel.task_delayacct", value="1", comment="cgprofile delay accounting"}]
           accept_shadow=["/etc/sysctl.d/99-vbpub-swap.conf#vm.dirty_ratio"]
[[edit]]   file="/etc/fstab" lens="Fstab" state="present" create=false validate="findmnt" on_change="daemon-reload"
           ops=[{records="*[vfstype='swap']", key="spec", exclusive=true, items=[{spec="PARTUUID=…", file="none", vfstype="swap", opt=["sw","pri=10"], dump="0", passno="0"}]}]
```

- Strict loading: unknown keys and missing fields are errors.
- There are no state-changing defaults. `on_change`, `state` and `mode` are always explicit.
- `accept_shadow` entries are `"<other file>#<key>"`, or `"<other file>"` for whole-file masking. There are no wildcards. A different shadowing source is an error again.
- Python callers build the same objects (`hs.Unit(...)`); `Request.to_toml()` renders the TOML for `--print-request`.

### B.3 Shadowing algorithm

1. **Effective order per target class.** It is computed in Python under `--root`, so it is the same on fake roots and live hosts. On a live root it is cross-checked against the native view.

   | Class | Directories, highest precedence first | Merge rule | Native cross-check |
   |---|---|---|---|
   | sysctl | `/etc/sysctl.d`, `/run/sysctl.d`, `/usr/local/lib/sysctl.d`, `/usr/lib/sysctl.d`, plus `/etc/sysctl.conf` | files sorted by basename across directories; the same basename in a higher directory masks the lower one; within the merged sequence the **last assignment wins** [K] | `systemd-sysctl --cat-config` |
   | units | `/etc/systemd/system`, `/run/systemd/system`, `/usr/lib/systemd/system` | unit file plus drop-ins from `<unit>.d/` and prefix/type drop-ins (`docker-.scope.d`, `service.d`) sorted by basename [K] | `systemctl cat` |
   | tmpfiles, sysusers, modules-load, udev `rules.d` | `/etc`, `/run`, `/usr/lib` variants | basename masking; tmpfiles and sysusers: **first** definition of a path or name wins [K] | |

2. **Setting level** (sysctl keys, unit directives, `/etc/environment` keys).
   - For every setting S we write, list every other assignment of S in the effective order.
   - **Error `shadow.later`:** a later assignment with a *different* value overrides ours.
   - **Error `shadow.earlier`:** ours overrides an earlier assignment (in another drop-in, or in another sysctl file) with a different value.
   - An assignment with an equal value is a `note`, not an error.
   - The vendor *unit file* is never a shadow source: overriding it is what a drop-in is for.
   - Unit directives that accumulate (`Environment=`, `Exec*=`, `After=`, `Wants=`, `Requires=`, `ReadWritePaths=` and similar; a small table, default *scalar*) shadow only through a later empty reset (`X=`).
   - Sysctl glob keys (`net.ipv4.conf.*.rp_filter`) overlap via `fnmatch` [K].
3. **File level.** Our `/etc/<x>.d/name` masking a `/usr/lib/<x>.d/name`, or a higher directory masking ours, is error `shadow.mask`.
4. **Acceptance.** An `accept_shadow` entry naming the exact other file (and the key) turns that one finding into a note, which is shown in the plan and recorded in the journal.
5. **Precondition.** The fingerprints of every file read for shadowing go into the plan's preconditions, so a change between plan and apply is a `StalePlan`.

### B.4 Pipeline

1. **load:** strict TOML or Python objects.
2. **plan** (shared lock): per resource, observe → diff → guards → shadow. The result is `Plan.changes` (change or noop, unified diff per file), `Plan.problems` and `preconditions` (sha256 or absence of every path read). Any error-severity problem raises `PlanRefused` (exit 2). The CLI `plan` stops here.
3. **confirm:** the CLI prints the plan, then a TTY prompt; with a non-TTY stdin, `--yes` is required. The library never prompts: `apply(plan)` *is* the acceptance.
4. **apply** (exclusive lock):
   1. re-check preconditions (`StalePlan`, exit 2);
   2. allocate `txn/<id>/`;
   3. **stage and validate everything first**; any failure discards the txn and writes nothing (exit 2);
   4. write the pre-images;
   5. commit per file: temp + fsync + rename + dir fsync [V `_fs.atomic_write`]; the journal is updated after each step;
   6. post-actions in fixed order: sysusers → tmpfiles → `daemon-reload` → sysctl → enable/start/restart in request order → `gpasswd` → endpoint publish.
5. **verify:** sha256 = staged; units active where enabled; sysctl read-back; `endpoints.verify`; optional `[[check]]`.
6. **failure after the first commit:** stop and write the journal (done / failed / not-run). The exit is 4 with the text `applied 3/7; failed: <step>: <why>; undo: host-setup revert <id>; or fix and re-run apply` [V `ApplyFailed`, `__init__.py:279-296`]. **Nothing is undone automatically.**
7. **Idempotence:** a second plan is all noop, so no txn, no write and no action (exit 0).
8. **Fake roots:** under `--root` the post-actions report `skipped(root)` [V engine.py:744-746], and so do validators that inspect live host state (`findmnt`, `sysctl` key existence, `dockerd`). Tests are fake-root only and independent of host load.

### B.5 Journal, pre-images, revert

- **`txn/<id>/journal.json`:**
  - writer, request sha256, root and timestamps;
  - per change: kind, path/address, `on_change`, enable state before, pre fingerprint, post fingerprint;
  - steps, actions and their results, pending actions, accepted shadows, irreversible effects (groups added or deleted, `gpasswd`, live sysctl values).
- **`txn/<id>/pre/`:** exact bytes + mode/uid/gid of each touched file, or the record "absent".
- **Retention:** the last 50 txns [V `_MAX_TRANSACTIONS`]. A revert of a pruned txn is refused.
- **`revert <txn>`:**
  1. plan-first, like apply;
  2. per file, newest first: refuse unless the current fingerprint equals the txn's post-image, naming the later txn found by scanning journals, or "changed outside host-setup";
  3. restore the pre-images as a **new txn** (`reverts=<id>`);
  4. re-run the post-actions recorded for those files (`daemon-reload`, the sysctl load of the restored file, the recorded `on_change`, enable state restored);
  5. list irreversible effects; they are not touched.
- **`journal [list|show <txn>|--pending]`:** `--pending` lists `pending` restarts whose unit has not entered `active` since the txn (`ActiveEnterTimestamp`).

## C. The Augeas `edit` kind

### C.1 Invocation (per resource, inside plan and again inside apply's stage)

1. `lstat` the real target: it must be a regular file, with no symlink in any component, inside the allowlist. A missing file is refused unless `create=true`, in which case staging starts from an empty file.
2. Copy it to `<tmp>/root/<same path>` and copy the overlay to `<tmp>/lenses/`.
3. **Observe run:**
   `augtool --root=<tmp>/root --noautoload --nostdinc -I <tmp>/lenses -I /usr/share/augeas/lenses/dist -t "<Lens> incl <file>" -f <observe.aug>`
   with `print /files<file>` plus `match <select>` per op, and `print /augeas//error`.
   - Explicit `-t` makes lens filter gaps irrelevant [V feasibility §2.3].
   - The overlay is searched before dist [V `augtool.pod:45-50`].
   - [U] the exact `-t` lens spelling (`Fstab` vs `Fstab.lns`), checked in HC-3.
4. **The plan turns ops into an `augtool` script** (§C.2) and runs it with `--new` (save mode newfile) [V rev 1 B.2].
   - No `<file>.augnew` written means no change: Augeas does not rewrite an unchanged tree [V].
   - Else the `.augnew` bytes are the staged result: diff them with difflib, then run the guards.
5. **Quoting:** every value is written double-quoted with `\` and `"` escaped. A value or selector containing a newline or NUL is refused (no script injection). Scripts go via `-f`, never through a shell. Timeout 30 s.
6. **Commit:** host-setup's own atomic write of the staged bytes, keeping the original mode/uid/gid. Augeas never saves onto the live path. It follows symlinks and creates files `0666&~umask` [V feasibility §3].

## F. Known issues / by design

1. **Shared files and settings are undecidable on uninstall.** host-setup cannot know whether a `daemon.json` key, an `/etc/environment` key, an fstab line or a sysctl value we changed was there before, or is still needed by someone else. A caller's `absent` deletes exactly what it names. Restoring a previous value is the caller's job (it re-applies what it wants) or the operator's (`revert <txn>` while the LIFO check allows it). Clean uninstall is guaranteed only for resources the caller created and names: its own units, drop-ins, files, fragments and groups.
2. **No automatic rollback.** A failed apply leaves the host partly applied. The journal names what was done and what was not run; the remedy is `revert <txn>` or fix and re-run. Restarts already done stay done.
3. **Revert is LIFO per file**: it refuses a file changed later and names the txn. It never reverts group creation or deletion, memberships, live sysctl values, tmpfiles-created paths, or the environment of running sessions. A revert re-runs the recorded post-actions, restarts included.
4. **No multi-file atomicity**: each file is atomic, a set of files is not. Augeas has none either [V feasibility §3].
5. **`accept_shadow` names one exact file (and key).** No wildcards; a new shadowing file is a new error. Equal-value overlaps are notes. Drop-ins overriding the vendor unit file are not shadowing.
6. **Shadow coverage is limited** to sysctl, units/drop-ins, `*.d` masking, tmpfiles, sysusers and `/etc/environment`. Shell `export`s in `profile.d`, `sshd -T` effective config and dockerd CLI flags versus `daemon.json` are not analysed.
7. **`pending` is not persistent state**: it lives in journals; `journal --pending` derives it. host-setup never restarts dockerd on its own.
8. **`edit` needs `augeas-tools`**: no fallback editor; the bootstrap stage uses whole-file kinds only. A file Augeas cannot parse is refused, never repaired. A `records` replace normalises the whitespace of that one line. In-place edits make dpkg conffiles "locally modified" (drop-ins are preferred where a `.d` exists).
9. **JSON is the one non-Augeas format.** The first `json_key` write reformats the whole file to canonical form; the plan shows that diff.
10. **Precondition model:** plan, then apply under the lock. Any change in between (including to shadow-relevant files) is a `StalePlan`; plan again. One host-wide flock, local only.
11. **cmru changelog:** the next cli-extended release range still contains the moved `feat` commits; release notes are hand-written.
12. **Release chain:** host-setup at L1 delays every L2+ release (cgprofile, run-gate, cmru, mdt-cockpit) by its own gate.
13. **Fake roots:** post-actions and live-state validators are `skipped(root)` in tests; only the `vm` lane exercises `systemctl`, `sysctl`, `gpasswd`, `findmnt` and udev.
14. **No legacy, no migrations:** on-host mdt names keep `host-setup.env`; endpoint files keep their paths; the `cli_extended.hostcfg` import path never shipped and gets no alias.
