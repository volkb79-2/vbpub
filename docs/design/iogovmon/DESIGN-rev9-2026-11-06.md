# iogovmon: the one self-contained host-IO-management project (DESIGN, rev 9)

Status: DESIGN ONLY (2026-11-06). Rev 9 resolves every finding of `iogovmon-DESIGN-REVIEW.md` (2 BLOCKER, 9 HIGH, 6 MEDIUM, 2 LOW) and applies the operator rulings (a) install benchmark undecided, investigate veryquick (IB-VQ), (b) actuation must stay simple, (c) the open-question recommendations. ## 0. The ruling, scope, and what is deferred

There is NO `host-tune` and no separate host-tuning library. **`iogovmon`** is the one project: **`iogovmond`** (the root daemon: observes, decides, applies bounded changes with its own revert journal), **`iogovmon-probe`** (the existing unprivileged recorder lanes `tick|bench|watch|cleanup`), **`iogovmonctl`** (CLI: `install`, `uninstall`, `doctor`, `status`, `stats`/`report`, `config`, `apply`, `revert`, `check`, `benchmark`, `prove`, `actuation`, `journal`, `plan`, `analyze`, `annotate`, `devices`, `prune`, `cleanup`, `preflight`). **`iobench`** stays a separate standalone project, called as a subprocess that wraps **`calibrate` only** (never `run`/`matrix`, which write knobs). Dependency direction: `iogovmon -> iobench`; consumers (debian-install-v2, mdt host-setup) call `iogovmonctl` and, at install, `iobench`.
Removed outright: request socket/protocol, `clients.d`, component registry, WP-REQ, `host-tune` verbs.
**Deferred (listed, designed only as far as needed to not block them; not scheduled):** swap borrow; scheduler A/B and any scheduler change (`auto` = kernel default); `io.weight` actuation (mdt-psi-guard owns tier `io.weight`); queue-knob actuation (`nr_requests`, `max_sectors_kb`; a queue write freezes the queue); tier-2 A/B (`prove --ab`) and the synthetic verification load with `iobench cells`; history-derived quiet-window prediction (only the live-threshold gate ships); `iogovmonctl export` compat projection for ciu (no consumer); per-knob actuation verbs and the mdt `IOGOVMON_ACTUATION_<KNOB>`/`WEIGHT_BAND` keys.
**Kept (carried rulings):** proven-only apply with the pinned-model hatch (plus the interim coarse rule, section 5); default-ON actuation within safe bounds with opt-out; `psi=1` cut (a `doctor`/`check` warning with the manual step); install benchmark on the planned raw partition; VM-only tests for anything touching core OS settings; no legacy and no backwards compatibility; first release gated on live acceptance (IG-ACC), installer key `services.iogovmon.install` (a NEW key) default `false` until the evidence exists. L1 of the review is accepted: `installer.py:3475` and `vendor/README.md:41` are accurate for the benchmark step (the io.cost unit is written by `_configure_iocost`), so there is no stale-text work package.

## 2. Module layout, process model, privilege

One distribution `iogovmon` (cmru tag `iogovmon-v*`, wheels + sha256 on GitHub Releases, never PyPI). Console scripts: `iogovmond` (root core), `iogovmon-probe`, `iogovmonctl`. The core is stdlib-only by import; only `iogovmon.ctl` imports `cli-extended` (a real wheel dependency; this reverses the extraction branch's "no first-party dependency" comment, so the daemon venv carries it too and the install bundle has three wheels: iogovmon, cli-extended, iobench). `iobench >= 0.2.0` (first release with `disk_scope`) and `fio >= 3.30` are external tools checked by `doctor`.
```
iogovmon/src/iogovmon/
  # existing recorder (extraction branch; keep names): rawread scratch bench collectors covariates episodes gating budget devices
  #   hostcheck recognizer journal report safeio state env config runner
  host.py        Host protocol; FakeHost (copied from shelved WP1); RealHost (NEW, on safeio primitives)
  fakekernel.py  FakeHost tier that models kernel semantics (read-back normalisation e.g. io.cost 95 -> 95.00, EINVAL on bad values,
                 files that appear/disappear, udev ordering)
  paths.py       all paths; ctl_dir is a constant, never a config key
  tuning/        registry.py render.py items/{vm_sysctl,min_free_floor,zswap,thp,ksm,oomd,cgroup_flags,io_scheduler,io_queue,io_writeback,io_cost}.py   (all NEW)
  apply/         engine.py (txn journal, prior capture, revert, recovery) writeguard.py bounds.py overlay.py locks.py
  store/         registry.py (role -> opaque id) binding.py proof.py
  benchmark/     iobench.py (subprocess wrapper of `calibrate`, `check`, `show`, `ceilings add|summary`)
  actuate/       knobs.py (registry + hard bounds) controller.py audit.py
  daemon.py      iogovmond: root core
  probe.py       iogovmon-probe: tick | bench | watch | cleanup (the existing lanes)
  ctl.py         iogovmonctl (cli-extended)
units/           iogovmon.slice  iogovmond.service  iogovmon-probe-{tick,bench}.{service,timer}  iogovmon-probe-watch.service
                 iogovmon-job@.service (template for transient root jobs)  99-iogovmon-raw-read.rules
```
**Process model.** (1) `iogovmon-probe-*`: the existing recorder, user `iogovmon`, sandboxed, writes only `/var/lib/iogovmon/probe/`. The unit names change from the branch's `iogovmond-tick|bench|...` so that `iogovmond` unambiguously means the root core. (2) `iogovmond.service`: root core, long-running (M2 onwards). (3) **Jobs** (benchmarks, anything that must write `/etc` or run `fio`): transient root units `iogovmon-job@<id>.service` started by `iogovmonctl` or, rarely, the core, each in `iogovmon.slice/iogovmon-job-<id>.service` with its own RW set, `RuntimeMaxSec` and a cgroup so `systemctl stop` kills the whole fio tree. The core never forks `fio`/`iobench` itself. (4) `iogovmonctl`: invoking user for read-only verbs; root for mutating verbs.
**Root core sandbox (H1).** `User=root`, `ProtectSystem=strict`, `ReadWritePaths=/sys /proc/sys /sys/fs/cgroup /var/lib/iogovmon /run/iogovmon` and nothing else (no `/etc/*`, no `/run/iobench`), `NoNewPrivileges`, `ProtectHome`, `PrivateNetwork`, `RestrictAddressFamilies=AF_UNIX`, `LockPersonality`, `RestrictRealtime`, `MemorySwapMax=0`, restart back-off and `StartLimit*` aligned with cgpd's `cgpd.service.in`; no bounding-set claim (the write guard is the boundary, tested as such). Rendering to `/etc` happens only in `iogovmonctl install|apply|revert` (a CLI process) and in jobs, never in the long-running core. Packaging: a root-owned versioned venv `/opt/iogovmon/<version>/venv` with a `current` symlink and absolute `ExecStart` (cgpd's pattern); NO `PYTHONPATH`, no copy under `/usr/local/lib` (`root:staff 2775` on Debian). `Host.run` resolves `iobench`, `fio`, `systemctl`, `udevadm`, `sysctl` to absolute paths and refuses any that is not root-owned and not group/world-writable.
**Why the split at all.** cgpd also parses tenant-influenced cgroup names as root, so parsing alone does not justify it; the justification is the raw-device reads and scratch-file writes of the recorder, which cgpd does not do. The root core imports no probe code except the read-only collectors.
**Write guard (the boundary).** `apply.writeguard` is the only writer outside `/var/lib/iogovmon`. It combines (a) an exact-path allowlist per registry item (sysctl `/proc/sys/vm/*` fixed names, zswap params, `/sys/class/block/<disk>/queue/<knob>` with the disk resolved by root from the registry, never from probe data, `/sys/fs/cgroup/io.cost.{model,qos}` with `MAJ:MIN` content validation, rendered files carrying the marker), (b) per-target value grammar and bounds in code, (c) `openat`/`O_NOFOLLOW`/post-open `fstat` writes with atomic replace + fsync for files. `validate_argv` is written per verb with an argument grammar (`systemctl`, `udevadm`, `sysctl`, `systemd-analyze`; any unit name must match `^[A-Za-z0-9_.@:-]+$` and not start with `-`). A static test (extending `tests/test_static.py`, per-call-site allow-list, not per-module) fails if any module outside `apply`/`host` calls a write or exec primitive, plus a mutation-style test (insert a write call in a temp copy, assert the lint fails).
**Asymmetric trust (H2) — the one rule.** Probe-written data may only make iogovmon LESS active: freeze, demote, mark stale, extend a cooldown, go observe-only. Anything that enables, raises, targets or schedules is computed from data the ROOT core collects itself (PSI, `io.pressure`, `io.stat`, `/sys/block/*/stat` through the same stdlib collectors, run in-process): distress detection, governed targets, stability counts that unlock `proven`. Governed cgroups/targets come only from root-owned TOML. Probe journals feed the recognizer's `capability_shift` (a freeze signal) and reports. A property test on FakeHost asserts: "mutating the probe journal to any content never increases the set or magnitude of proposals".

## 3. Ownership matrix and the single-writer rule (B2)

"Single writer" is a per-key fact, recorded in `manifest.json` (`owner: iogovmon|mdt|installer|external`) and enforced, not assumed.
| Other writer on real hosts | Rule |
|---|---|
| mdt reconcile (every minute: `_mdt_reassert_io_settings` for scheduler, queue, `vm.dirty_*`, io.cost against `host-setup.env`) | `IOGOVMON_MODE=adopt` = **no baseline writes and actuation forced off**. Only `managed` may write or actuate, and only after mdt's reconcile reads iogovmon's `overlay.json` or is stopped for iogovmon's keys (mdt has `/run/mdt/io-reassert.pause`). mdt `managed` (IG-15b) is therefore a prerequisite of actuation on mdt hosts. The daemon refuses to actuate a key whose owner is not iogovmon and `doctor` prints the conflict. |
| `mdt-psi-guard` (owns tier `io.weight`, sets 1 under pressure) | io.weight is not a knob of this design (deferred); psi-guard keeps ownership. |
| `iobench run`/`matrix` (write `dirty_*`, `nr_requests`, `max_sectors_kb` under their own journal in `/run/iobench/restore.json`) | iogovmon wraps `calibrate` only. During any iobench job the core takes `bench.lock`, reverts the overlay to baseline, and freezes the controller; `apply.lock` (seconds, transactions) and `bench.lock` (minutes to hours, jobs) are separate so a standard run never blocks kill-switch rollback. |
| Installer legacy files that stay on installed hosts: `/etc/sysctl.d/99-vbpub-swap.conf` (dirty 15/5, swappiness...), `zswap-config.service`, `vbpub-min-free-floor.service`, `/etc/tmpfiles.d/vbpub-{ksm,thp}.conf`, `cgroup2-flags.service`, `/etc/modules-load.d/vbpub-zstd.conf`, `vbpub-iocost.service` + `/etc/vbpub/iocost-model` + `/usr/local/sbin/vbpub-iocost-setup` | Rendered sysctl files use a name that sorts AFTER every known legacy one: **`/etc/sysctl.d/99-zz-iogovmon.conf`** (and per-item `99-zz-iogovmon-<item>.conf`), AND install removes, inside the same journalled txn, the legacy files of every item it takes over. Items it does not take over keep their old owner. `doctor` lists every key defined in more than one place (`/etc/sysctl.d/*`, `/usr/lib/sysctl.d`, udev rule order via `udevadm test`). |
Installer and mdt old steps are made mutually exclusive with `services.iogovmon.install=true` (IG-14b), otherwise acceptance runs have two writers.

## 4. Paths, trees, formats

Two sibling trees under a root-owned parent (B1). `/var/lib/iogovmon/` is `root:root 0755`, created by `install`, never by systemd `StateDirectory`; the probe leaf is `/var/lib/iogovmon/probe/` `iogovmon:iogovmon 0700` (units use `StateDirectory=iogovmon/probe`, which chowns only that leaf). `/run/iogovmon/` root 0755 (locks, runtime flags).
| Path | Owner | Content |
|---|---|---|
| `/etc/iogovmon/iogovmon.toml` | root 0644 | config (section 7) |
| `/etc/iogovmon/disabled` | root | kill switch |
| `/etc/sysctl.d/99-zz-iogovmon*.conf`, `/etc/udev/rules.d/60-iogovmon-scheduler.rules`, `61-iogovmon-queue.rules`, `/etc/tmpfiles.d/iogovmon-*.conf`, `/etc/modules-load.d/iogovmon-*.conf`, `/etc/systemd/system/iogovmon-*` | root | rendered baseline; first line `# managed-by: iogovmon item=<id> cfg-sha=<sha>` |
| `/var/lib/iogovmon/probe/` | iogovmon 0700 | `state.json`, monthly `journal/*.jsonl`, `scratch/`, `run.lock` (probe side) |
| `/var/lib/iogovmon/apply/{journal.jsonl,manifest.json,overlay.json}`, `registry.json`, `bench/<id>/`, `actuation.jsonl` | root | root side |
| `/run/iogovmon/{apply.lock,bench.lock,bench-state.json}` | root | locks; `bench-state` = running, pid, start |
**Journal (`iogovmon.apply-journal/1`).** Each txn stores `{txn, boot_id, ts, actor, item, state}` and **item ids only**: file and prior targets are re-derived from the registry's exact-path allowlist at replay; a txn whose recorded path is not allowed for its item is quarantined, never replayed. States: `planned` (fsynced BEFORE the first write) -> `applied` (after read-back) -> `verified` -> or `rolled_back`/`reverted`/`abandoned_by_reboot`. Append-only single-write bounded records with torn-last-line tolerance (the existing `journal.py` pattern).
**Reads of probe-owned files by root**: open every component with `O_NOFOLLOW|O_DIRECTORY` via `dir_fd`, `fstat` regular file with `st_uid == iogovmon uid`, size cap; never `Path.read_text`. The existing `any_owner` readers stay for the unprivileged `iogovmonctl` only; the core uses the strict-owner mode.
**Result store.** `bench/<id>/` is an iobench `--state-dir` (`result.json`, `calibration.json`, `ceilings.jsonl`, read only through `iobench check|show --json`), plus `binding.json` (`iogovmon.binding/1`: identity strength, queue at measure, `measured{by, kind raw|file, origin, grade, grade_reasons, iobench, profile, run_id}`, roles) and `proof.json` (`iogovmon.proof/1`). **`<id>` is opaque**, assigned at import. `registry.json` (`iogovmon.registry/1`) maps `role -> {state_dir id, stored_scope_key, name_hint}`; the live disk is matched through **`iobench check`** (it runs `identity_differs` against the stored scope), never by recomputing a key: an install benchmark made while `/etc/machine-id` is uninitialised has a weak scope that differs from the live key after first boot (iobench's own CHANGES says so). `iobench identity` is therefore not needed. Own-observation ingestion uses the existing sources: `iobench ceilings add --source governor --kind file` (scratch bench) and `--source probe --kind probe`; no iobench change. Profile names map: `veryquick|quick|standard|thorough` (the CLI flag `--profile full` of the earlier design is `standard`). Schemas: `schema` string + `schema_minor`; refuse a newer major, tolerate a newer minor. Legacy stores (`/var/lib/vbpub/bootstrap/io-benchmark.json`, `/etc/vbpub/iocost-model`, `/var/lib/mdt/io-baseline.env`, `/var/lib/ciu/io-baseline.env`) are not read.

## 5. Install-time benchmark: undecided, with an interim rule (operator ruling a)

**Interim rule (labelled INTERIM until IB-VQ reports):** the installer runs `iobench` `veryquick` on the planned raw partition (after the table write, before mkfs/mkswap; target created in this table write, never a preserved partition), then `iogovmonctl install --profile` applies the veryquick model as **`coarse`: `io.cost.model` only, QoS off** (`io.cost.qos` `enable=0`, so the controller stays inert and no weights/throttling change), state `coarse` in `proof.json`, plausibility `fail` writes nothing. No measured value is applied beyond that model; nothing is claimed `proven`. Refinement is operator-run (ruling c): `iogovmonctl benchmark run --profile quick|standard` replaces the coarse model; the daemon only demotes (`stale`) or suggests recalibration. This is stricter than today's installer (`vbpub-iocost.service` writes `enable=1 ctrl=user` with its model). Installs where the raw partition cannot be benchmarked skip the step and leave io.cost `unmanaged`.

### IB-VQ: how far does `veryquick` deviate from `quick`, and can it become `proven`? (analysis work package)
- **Data that exists:** three recorded real-world tables in `libraries/iobench/tests/fixtures/` (`r1002_model.json`, `r1002_recorded.json`, `gstammtisch_tables.json`, plus the synthetic `latency_curve_synthetic.json`, `two_tier_e1_good_but_wrong.json`), the <private-host> measurements (`scripts/<private-host>-guide/{HOST-IO-INTERFERENCE,MEASUREMENTS}.md`, the IO-stall guide section 11), two live `iocost_coef_gen` runs on that host (`/root/iocost-results/`, root-only, to be read by the controller), `io-baseline.env` files where mdt ran, and the controller program dir's benchmark reports (`iob-1-REPORT.md`, `mdt-testhost-io-REPORT.md`, `v1001-*`, `R1002-*`; none contains paired veryquick/quick runs; `IOBENCH-R2-R1002` is a mutation report). **No paired real-disk veryquick/quick/standard data exists**: `RealHost` has never run (IOB-ACC-01 pending). The fixtures give a replay-only sanity check of how the veryquick estimator behaves on recorded shapes (bursty, rate-limited, cache-inflated), not real deviation.
- **Experiment:** on >= 3 disks (v1001, r1002, a second netcup class; a local VM disk for plumbing only, excluded from statistics), in quiet windows (nights, live-threshold gate, protected cgroup, abort PSI), interleaved and order-randomised blocks `V Q V Q V Q ... S` per disk with **N = 5 repetitions of `veryquick` and `quick` and 2 of `standard` (reference)**, plus **10 repeated `veryquick`** alone for intra-profile variance, a raw partition or a file target of the same size on the same disk, all with the same `--state-dir` family so ceilings do not mix. Record every run's `result.json`, `calibration.json`, plausibility and `write_burst_seen`.
- **Statistics:** per disk and per coefficient (`rbps rseqiops rrandiops wbps wseqiops wrandiops`): relative deviation `|v - s_median| / s_median` (veryquick vs standard) and `quick` vs standard; coefficient of variation across veryquick repeats; bootstrap 90 % CI of the median deviation; Bland-Altman agreement; plausibility-verdict concordance; burst-detection concordance; separately the direction of error (over-estimate of sustained write is the dangerous direction: a 30 s series can mistake a burst for the plateau).
- **Promotion criteria (proposal):** veryquick may be classified `proven-coarse` for the **model only** if on >= 3 disks and >= 10 veryquick runs per disk, for every coefficient: median deviation <= 25 % and p90 <= 40 % against standard; veryquick CV <= 15 %; plausibility verdict concordant in 100 % of runs; `write_burst_seen` true in every case where standard shows a burst; no run over-estimates sustained write by > 25 %. It requires an iobench SPEC change (a status row between `unproven` and `proven`, tested in the IOB-STA-05 audit), because iobench's rule is structural: a `proven` write cap needs >= 120 s after the knee and >= 2x burst bytes, which 30 s cannot supply. If the criteria fail, veryquick stays `coarse` forever and `proven` comes only from `quick`/`standard`.
- **Cheap extra evidence within ~3 min** (variants VQ-B and VQ-C are included in the experiment): (1) VQ-B: 45 s write series and three grid cells instead of four (fill and cold probe trimmed to stay <= 180 s) so a burst ending inside 30 s is less likely to pass as plateau; (2) VQ-C: a second 20 s write series after a 10 s gap, detecting token-bucket credit exhaustion by the drop between series; (3) a knee check inside the existing series (early 10 s vs late 20 s window); (4) flat-line `rate_limited` detection over the series (CV < 1 %); (5) sysfs facts (`write_cache`, `nr_hw_queues`, discard) as covariates; (6) the daemon's first 6-hour mini write bench as an independent second observation.
- **Deliverable:** report `IB-VQ-REPORT.md` with the raw tables, the decision (promote / keep coarse / adopt VQ-B or VQ-C) and the SPEC patch if promoted. Until it lands the interim rule above applies.

## 6. Contracts of the main verbs, crash safety, boot ordering

- **`iogovmonctl install [--profile NAME|FILE] [--bench-result PATH] [--baseline-only] [--dry-run]`**: (1) `doctor` preflight, nothing written on failure; (2) import the iobench result by `iobench check` matching into `bench/<id>/` and write `registry.json`; (3) render the profile's baseline items and apply live through the engine (one journalled txn, prior values captured first, each item read back), removing the legacy files of taken-over items in the same txn (section 3); (4) io.cost: the coarse model with QoS off per the interim rule, or a `proven`/`pinned` model; (5) create user, dirs (trees of section 4), versioned venv link, `iogovmon.slice`, units; `systemd-analyze verify`; enable and start `iogovmond` unless `--baseline-only` (M1 ships `--baseline-only` only); (6) manifest with per-key owner; print a before/after table and what waits for proof. Idempotent; exit 0 ok, 1 error (rerun finishes it), 2 refused by preflight, 3 installed with warnings.
- **`revert [--all|--item ID]`**: restores prior values from the journal (targets re-derived from the allowlist), removes rendered files by marker, `daemon-reload`, `udevadm control --reload` and a trigger of only the affected disk. **`uninstall [--purge]`**: `revert --all`, remove units/slice/ACL rule/user; keeps data unless `--purge`.
- **`doctor`** (read-only): cgroup v2, PSI (missing: warning with the manual `psi=1` step, no editing), `io.cost` file presence, `fio >= 3.30`, `iobench >= 0.2.0`, systemd version, raw-read ACL, tree ownership and modes (B1), duplicate keys across files, stale `bench-state`/`/run/iobench/restore.json`, kill switch, units verify; remedy per finding; exit 0/1.
- **`check`**: drift = rendered vs expected, live vs `baseline + overlay`, ownership conflicts, bench staleness (`iobench check`), proof states; a missing overlay after boot is normal. Exit 0 ok / 1 drift / 3 stale / 4 absent. The daemon reports drift every 15 min; `drift.heal = report` is the default, `baseline` (opt-in) re-asserts the rendered baseline files only, never runtime overlay values, and must not be enabled where mdt reasserts.
- **Crash and reboot (H8).** Every txn records `/proc/sys/kernel/random/boot_id`. At start: txns from another boot are marked `abandoned_by_reboot` and NOT replayed for runtime kinds (sysctl, sysfs, cgroup); only persistent-file effects are reconciled (`sha_after` vs disk, keep or remove by marker). A txn left in `applied` is rolled back (verification never completed). The kill-switch rollback is itself a txn: `flock` with a timeout and a stale-holder rule (holder pid + start time from `/proc`). Boot ordering: the baseline units (sysctl, io.cost oneshot, udev) run first; `iogovmond.service` has `After=` them and an explicit `udevadm settle --timeout` step in the io.cost oneshot (mdt's pattern); overlay values are never re-applied at boot.

## 7. Config schema

`/etc/iogovmon/iogovmon.toml` is the single source after the first apply; installer JSON and mdt env only SEED it (a re-run with an operator-edited TOML prints a key diff and keeps the TOML unless `--force-seed`; `config set` is atomic and journalled). An absent file or `{}` means defaults; refusals name the key, the allowed set, why, and a "did you mean" for unknown keys; numeric limits are clamped by code with the existing `HARD_MIN`/`HARD_MAX` mechanism (tested). The recorder's flat keys are moved ONCE into the nested layout with no deprecation shims (the branch's `DEPRECATED_KEYS` are deleted).
Most operators set only `profile = "standard" | "conservative" | "minimal"` (named bundles of item toggles); per-item sections hold exceptions. `iogovmonctl config init --profile standard` writes a commented skeleton; `config show --effective` annotates each value `default|profile|file|pinned`. `roles`: `root` = the whole disk under `/` (`findmnt`, dm/LVM followed to the physical disk); `data` = the filesystem at the configured data mount (data-area-v2 first volume mount); several disks behind a role: refused for io.cost until each is listed.
```toml
schema_version = 1
profile = "standard"

[daemon]
enabled = true
tick_s = 60

[probes]            # the existing recorder keys, nested once: state_dir, scratch_dir, data_paths, protected_cgroups, containers, budgets, ...
governed_cgroups = []        # explicit list only; names validated; never taken from probe data

[baseline.vm_sysctl]
swappiness = 10
watermark_boost_factor = 0

[baseline.io_scheduler]
per_role = { root = "auto", data = "auto" }   # auto == kernel default, no rule, never live

[baseline.io_writeback]
mode = "auto"               # RAM <= 16 GiB: ratio 15/5; larger: bytes min(15% RAM, 1 GiB) / min(5% RAM, 256 MiB)

[baseline.io_cost]
model = "coarse"            # coarse (interim) | proven | pinned | off
model_pin = ""              # operator literal, refused when a measured plausibility verdict is "fail"
qos = "off"                 # off until the group is proven or accepted

[benchmark]
profile = "veryquick"       # install default (interim); quick | standard | thorough later, operator-run
target = "install-partition"   # installer only; fallback "file"

[proof]
min_observations = 8
```

## 8. Actuation (simplified; operator ruling b)

**Rule: a knob acts when its data/proof state qualifies and its safe bounds allow. No staged rollout, no counterfactual phase, no one-knob-first, no synthetic verification.** The essentials stay: bounds, cooldown, rollback on demonstrated regression, kill switch, opt-out, audit.
- **What qualifies (data):** the knob's group is `proven`, or `accepted`/`pinned` by the operator, and the capability lanes are stable (no `capability_shift`, baseline reset, or external settings change for `stable_days`; an external settings-epoch change is treated like a capability shift: freeze and re-baseline). On a standard install the QoS group qualifies only after IB-VQ promotes veryquick, an operator-run `quick|standard` calibration, or an explicit `prove --accept`; until then the effective mode is `observe-only` and `status` says why.
- **Only act on observed distress.** The root core measures, in-process, the protected cgroups' `io.pressure some avg60` and episode counts (the existing `episodes` logic on root-collected PSI). An idle host, or a host without protected workloads, has no distress signal and therefore **no action and nothing to verify**: no revert loops on idle hosts. `capability_shift` freezes the controller (a provider cap change is never tuned around).
- **Knobs (first release):** `io.cost.qos` latency targets/percentiles and vrate `min/max`, and `vm.dirty_bytes`/`dirty_background_bytes` inside the tier-1 caps. Hard bounds in code: qos latency baseline x [0.5, 2], pct +-5 pt, `max` <= baseline x 1.5, `min >= 1`, `min <= max`; dirty floor 32 MiB / 8 MiB, ceiling the tier-1 cap (`min(15 % RAM, 1 GiB)` / `min(5 % RAM, 256 MiB)`), `background < dirty`; max step 10 % (qos) / 25 % (dirty); cooldown 6 h / 2 h; max drift +-50 % / cap-floor. One knob per distress episode. The controller proposes `(knob, direction, steps)`; `apply.bounds` computes the value and refuses anything outside the bounds. Never touched: scheduler, kernel command line, swap/zswap, `vm.swappiness`/watermark/min_free, the io.cost model coefficients (drift past the band is a capability shift), `io.max`, `memory.*`, `io.weight`, queue knobs, unit/slice definitions.
- **Verification = the same distress metric.** After a step, compare the metric over the 2 h after against the 2 h before. **Regression** (worse by > 25 % and > 2 points absolute, or more episodes) -> automatic rollback through the journal, the group is demoted to `candidate`, notification. Anything else is kept (neutral and improved alike, so there is no revert churn); drift is bounded by the hard bounds and the knob decays toward baseline after 7 calm days. Rollbacks double the knob's cooldown (6 h, 12 h, ... 7 d); two rollbacks in 7 days freeze it until `iogovmonctl actuation on`.
- **Opt-out and audit:** `actuation.mode = on | observe-only | off` (`iogovmonctl actuation ...`), per-knob booleans in the TOML, the kill switch (stops decisions, rolls back an in-flight change). Every decision is one `iogovmon.audit/1` line in `actuation.jsonl` (before/after, reason, signal, evidence, gates, verdict, outcome). Actuated values are runtime-only (overlay); a reboot or `revert --all` returns to baseline. `status --json` gains `actuation{mode, effective_mode, frozen_reason, last_outcome, per_knob{state, proof_state, baseline, current, drift_pct, cooldown_until, changes_today}}`.

## 9. Proof lifecycle (reduced), quiet gate, tests

- **Proof groups:** `io_cost.model` and `io_cost.qos` only (queue/writeback tier-2 groups are deferred together with the A/B). States `none -> measured -> coarse -> candidate -> proven -> applied`, plus `demoted`, `accepted`, `pinned`, `stale`. Evidence classes as in the earlier design 4.1.1 (raw proves the value; file confirms write stability; probe confirms read stability). `candidate -> proven`: a `quick`/`standard` calibration that iobench grades `proven` for the group (QoS targets come from iobench's own derivation, so no A/B is needed), >= 8 observations over >= 48 h with median within +-25 %, spread <= 4x, none of `ceiling_moved`/`recalibrate_recommended`/`capability_shift`; the confirming observations come from root-collected samples and raw calibrations (asymmetric trust). On a file-kind-only host read keys cannot reach `proven`: `accepted`/`pinned` is the path. Demotion: identity mismatch (via `iobench check`), `recalibrate_recommended`, capability shift, a protected-side regression after an actuation, outside drift, expiry; `on_demote`: io.cost falls back to QoS off.
- **Quiet gate (live-threshold only):** before any operator-run calibration or job: io PSI `some avg60` < 10 %, memory < 5 %, CPU < 20 %, foreign writes < 5 MB/s for 3 samples 5 s apart, no production containers/units (iobench SAF-05) unless confirmed; re-check right before start; defer and say when it will retry. History-derived window prediction is deferred (the probe history accrues from M0 anyway).
- **Test strategy.** Pure unit tests with `FakeHost` and the `FakeKernel` tier (kernel semantics: normalised read-back, EINVAL, appearing/disappearing files, udev ordering, flock behaviour across processes): renderers (golden), config validator, registry/binding, proof state machine with an injected clock, controller gates, bounds clamp, flap/backoff, distress verdict, apply engine rollback at every step and boot_id replay rules, write-guard lint + mutation test, the asymmetric-trust property test. **VM-only** (thin set per item, the existing QEMU/TCG harness at `scripts/debian-install-v2/testing/vm/{vmctl,run-vm-tests.sh}` with `os_integration` and `VBPUB_REQUIRE_OS_INTEGRATION=1`; iogovmon's `run-gate.toml` VM lane invokes that installer-owned harness by documented path for now, moving it to `tester-base` is deferred): live equals rendered, after a hard power-off + boot (assert it is a power-off), `udevadm test` order, io.cost read-back after reboot (**first an early spike, IG-SPIKE: does virtio-blk under TCG accept `io.cost.qos enable=1`? if not, io.cost assertions move to a disposable real host**), `revert --all` restores captured originals, install idempotence, legacy-file removal, tree ownership (probe user cannot rename `/var/lib/iogovmon/apply`), `systemd-analyze security`. Limits stated: TCG shows no real vrate dynamics, provider throttling, or real timing (QMP `block_set_io_throttle` shows the mechanism only); real-host smoke on an operator-named disposable host is mandatory before any default flips.
- **IG-ACC scenarios** (VM, then a disposable real host with a 7-day soak and reviewed audit journal): (1) induced distress on a protected cgroup -> a bounded step within bounds and rate limits; (2) fault-injected regression -> rollback + demotion + notification; (3) simulated provider-cap change (mechanism only) -> `capability_shift` -> frozen, no action; (4) idle host -> no action; (5) opt-outs honoured; (6) kill switch mid-window -> rollback; (7) repeated rollbacks -> backoff and freeze; (8) poisoned probe journal -> no larger proposals; (9) reboot -> baseline; (10) root core killed mid-txn -> recovery.
