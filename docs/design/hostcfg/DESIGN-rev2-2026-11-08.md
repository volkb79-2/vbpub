## 0. Decisions

| # | Decision |
|---|---|
| R-1 | **hostcfg** is a generic desired-state engine, used as a library or as a CLI. It is the `cli_extended.hostcfg` package inside the cli-extended wheel: stdlib only, zipimportable, P-7. It knows resource kinds, never services. Every resource has `state = "present" \| "absent"`. |
| R-2 | **No orchestration in hostcfg.** A multi-service host is described by a **host profile** (pinned artifacts + ordered argv steps). A ~250-line generic runner, `cli_extended.hostprofile`, runs the profile. Option (i) of §A.3; debian-install-v2 INST-01 calls the same runner. |
| R-3 | Services install themselves: own `install`/`uninstall`/`doctor`, config in `/etc/<svc>`, optional wizard. They call `hostcfg.plan()`/`apply()` in-process, or they emit a request file (`--print-request`). There is no entry-point group, no `--describe-inputs` contract, and host-setup has no service loop. |
| R-4 | Failure model: plan first, always. Apply stops at the first failure and leaves a txn with pre-images. `hostcfg revert <txn>` is manual. **No automatic rollback**, by design (§F). |
| R-5 | Ownership is a **layered stack per address**: the origin (pre-hostcfg value), then owners, last writer on top. Withdrawing a layer restores the one below it. Two owners on one *whole* address (file, unit, sysusers/tmpfiles file, group spec) is refused. |
| R-6 | **In-place edits: build, do not adopt Augeas now.** The catalogue (§C) has exactly one generic in-place need on the hostcfg path: JSON keys in `daemon.json`. A ~150-line stdlib `json_key` provider covers it. Augeas (`augtool` subprocess, trixie 1.14.1) stays a documented provider seam, re-decided on the trigger in §D.3. |
| R-7 | `/etc/environment` gets **one writer**: the endpoints module. The `mdt-buildkit` block and the planned host-GID block become entries in the `mdt-host-setup` endpoint fragment, so no generic `block` provider is needed. |

## A. Architecture

### A.1 One picture

```
 operator / host agent                                   debian-install-v2 INST-01'
        |  hostprofile plan|apply|doctor PROFILE                 | same call, after stage 1
        v                                                        v
 host profile (per host, TOML): [[artifact]] url+sha256, [[step]] run/plan/doctor argv
        |
        v
 cli_extended.hostprofile: fetch+verify artifacts, run steps in order, stop on first failure,
        |                   then run every doctor. Knows argv and sha256, never services.
        |
        +--> hostcfg apply mdt-base.toml        (operator-owned requests: e.g. /etc/mdt/host-setup.env)
        +--> mdt host-setup install.sh          (mdt dev-tier governance; owner mdt-host-setup)
        +--> cgprofiled install --add-user ...  (its own verb; library calls into hostcfg)
        +--> hostobsd install ...               (later; library calls into hostcfg)
                         |   in-process: hostcfg.plan(req) -> Plan -> hostcfg.apply(plan)
                         v
 cli_extended.hostcfg   kinds: file unit sysctl sysusers group tmpfiles endpoint check (+json_key)
   plan -> stage/validate -> apply -> post-actions -> verify -> record | revert | remove | doctor
                         |
   OS-native backends: systemd-sysusers, systemd-tmpfiles, systemd-analyze, systemctl, sysctl, gpasswd
   state: /var/lib/hostcfg/{state.json, origins/, txn/<id>/}     lock: /run/lock/hostcfg.lock
```

### A.2 What hostcfg is, and is not

| hostcfg IS | hostcfg is NOT |
|---|---|
| A library (`plan`/`apply`/`remove`/`revert`/`doctor`) plus a CLI over the same functions | an installer of software: no wheels, venvs, `/opt` trees, binaries or drain logic. Those stay in the service |
| Persistent host configuration with present/absent per resource | a manager of runtime kernel or cgroup state (rev 1 H-3 stands: io.cost, `set-property --runtime` and live sysctl stay with their daemons) |
| An ownership record, pre-images, revert and drift doctor | an orchestrator: no step lists, no service names, no per-service contract |
| `--root DIR` everywhere (tests and staging) | a remote or multi-host tool; it is local and root only |
| Templating-free: it receives literal content | a template engine; callers render first (rev 1 C.4.1) |

| Caller | How | Owner name |
|---|---|---|
| Service installers (cgprofiled, toposd, mdtd, iogovmond, hostobsd) | library, in-process, from their own `install`/`uninstall`/`doctor` | the service (`cgprofile`, `hostobs`, ...) |
| Operator | `hostcfg plan\|apply REQ.toml`, `revert`, `show`, `doctor` | whatever the request says (`operator`, `mdt-base`) |
| mdt host-setup (remnant: slices, BuildKit, docker drop-ins, inotify, udev, `cgroup-parent`) | its own `install.sh`; it calls `python3 -m cli_extended.hostcfg apply` with rendered requests (HS-2) | `mdt-host-setup` |
| debian-install-v2 | **not** a hostcfg caller; it keeps `actions.write_file` (§C, Q3). Its only new link is INST-01' running the profile runner, which reaches hostcfg only through `hostcfg apply` steps | (none) |

### A.3 Orchestrating a multi-service host profile (v1001: slices, daemon.json, BuildKit, services X, Y)

| Option | How | Coupling | Re-run on a live host | Verdict |
|---|---|---|---|---|
| (i) profile = argv list run by a tiny separate runner | per-host TOML. The runner verifies artifacts, runs steps, stops on failure, runs doctors | none: the runner knows argv and sha256; hostcfg knows kinds | yes: same file, same command (upgrade = new pins) | **Recommended** |
| (ii) profile = directory of request files applied by hostcfg | `hostcfg apply profile.d/*.toml` in order | none, but incomplete: a service install needs code execution (venv, wheel fetch, config render, drain exit 3, `/opt/<svc>/<ver>`) | static part only | Rejected. Either it cannot install services, or hostcfg grows an `exec` kind, which is (i) inside hostcfg |
| (iii) debian-install-v2 custom script | INST-01 runs a command list | div2 learns the command list. `customscript.py` is the provider bootstrap bundle, not a post-install hook [V `customscript.py:1`] | no: div2 runs at reinstall only | Rejected as the owner; div2 instead calls the (i) runner once |

Profile example for v1001 (illustrative; the step argv belong to each tool):
```toml
profile = 1
host    = "v1001"
cache   = "/var/cache/vbpub/artifacts"
artifact = [
  { name = "cli-extended",   url = "…/cli-extended-v0.7.0/cli_extended-0.7.0-py3-none-any.whl", sha256 = "<64 hex>" },
  { name = "cgprofile",      url = "…", sha256 = "…" },
  { name = "mdt-host-setup", url = "…/mdt-cockpit-host-setup-<ver>.tar.gz", sha256 = "…" } ]
[[step]]   # operator-owned static config (e.g. /etc/mdt/host-setup.env), a plain hostcfg request
name = "base"
run  = ["python3", "-m", "cli_extended.hostcfg", "apply", "--yes", "/etc/vbpub/requests/base.toml"]
plan = ["python3", "-m", "cli_extended.hostcfg", "plan", "/etc/vbpub/requests/base.toml"]
env  = { PYTHONPATH = "{artifact:cli-extended}" }
[[step]]   # slices, BuildKit, docker drop-ins, cgroup-parent
name = "mdt-governance"
run  = ["{artifact:mdt-host-setup}/host-setup/install.sh", "--yes", "--config", "/etc/mdt/host-setup.env"]
doctor = ["/usr/local/sbin/mdt-host-check.sh", "--json"]
[[step]]
name = "cgprofile"
run  = ["python3", "-m", "cgprofile.cli.cgprofiled", "install", "--yes", "--wheel", "{artifact:cgprofile}",
        "--cli-extended-wheel", "{artifact:cli-extended}", "--add-user", "control=runner", "--enable"]
env  = { PYTHONPATH = "{artifact:cgprofile}:{artifact:cli-extended}" }
ok_exit = [0, 3]   # 3 = drain pending, recorded as pending
doctor = ["cgprofiled", "doctor", "--json"]
```

Runner rules:
- The only substitution is `{artifact:NAME}`, the verified cached path; `run` is argv, never a shell.
- `plan` verifies pins and runs each step's optional `plan` argv; `apply` stops at the first exit
  not in `ok_exit` and prints `--from-step NAME`; `doctor` aggregates every `doctor` argv's JSON.
- Log: `/var/log/vbpub/hostprofile/<ts>.jsonl`.

## B. Request and state model

### B.1 Request (TOML `hostcfg = 1`, or the same objects built in Python)

```toml
hostcfg = 1
owner   = "cgprofile"                  # ^[a-z][a-z0-9-]{0,62}$ (validate_owner, hostcfg/__init__.py:8-15) [V]
writer  = "cgprofiled install 3.0.0"
prune   = true                         # resources this owner held before and omits now are withdrawn
[[file]]      path="/etc/x/y.conf"  mode="0644"  text="…"  state="present"   # | create_only=true | takeover=true
[[unit]]      name="cgprofile-control.socket"  text="…"  enable=true  on_change="restart"
[[unit]]      name="docker.socket"  dropin="50-mdt-api.conf"  text="…"  on_change="pending"
[[sysctl]]    key="kernel.task_delayacct"  value="1"  apply_now=true
[[group]]     name="cgprofile-control"  level=true  not_gid_of=["docker"]  not_gid=[0]  members_add=["runner"]  members_absent=[]
[[tmpfiles]]  lines=["d /run/cgprofile/state 0700 root root -"]
[[endpoint]]  entries={ CGPROFILE_CONTROL_SOCKET="/run/cgprofile/control/cgprofile.sock", CGPROFILE_CONTROL_GID="@gid:cgprofile-control" }
[[check]]     path_mode={ path="/run/cgprofile/control", owner="root", group="root", mode="0755", if_exists="must-match" }
```
- Unknown keys are errors, and so are missing required fields. There are no state-changing
  defaults (AGENTS.md "defaults are hazards").
- TOML is parsed with stdlib `tomllib` (Python ≥3.11; cli-extended's `requires-python >=3.11`
  [V `pyproject.toml:9`]).

### B.2 Addresses, ownership stack, record

Every resource maps to **addresses**: `file:/etc/x`, `unit:/etc/systemd/system/docker.socket.d/50-mdt-api.conf`,
`sysctl:kernel.task_delayacct`, `group:cgprofile-control`, `member:cgprofile-control:runner`,
`tmpfiles:<owner>`, `sysusers:<owner>`, `endpoint:<owner>`, later `json:/etc/docker/daemon.json#/cgroup-parent`.
`/var/lib/hostcfg/state.json` (atomic, under the lock) holds per address an `origin` (absent, or
`origins/<sha256>`, captured at first touch) and `layers = [{owner, value|absent, txn, at}]`;
the effective value is the top layer.

| Address class | Second owner arrives | Owner withdraws (uninstall / prune / absent) |
|---|---|---|
| whole: file, unit, drop-in, sysusers/tmpfiles file | **refused**, naming both owners (ruling 5) | restore `origin` (file content or absence) |
| group spec | identical spec: shared (ref-counted); different spec: refused | `groupadd`ed by hostcfg and last holder gone: kept unless `remove --remove-groups` |
| member | ref-counted | `gpasswd -d` only if hostcfg added it and no holder remains |
| sysctl key, json key (HC-2) | **last writer wins**: new top layer, previous kept as history | the layer below becomes effective; none left: the origin value, or delete the key |
| endpoint | per-owner fragment; a key collision between owners is refused by the module [V `endpoints.py:537`] | `withdraw` [V `endpoints.py:959`] |

- **Unowned existing whole file.** Equal content is adopted silently. Different content is
  refused unless the resource says `takeover = true`; the origin is then kept, and withdraw
  restores it (decision G6).
- **Hand edits (drift).** `plan`/`doctor` show the diff from the recorded effective value. The
  next apply overwrites it (last writer wins) and the drifted bytes go into that txn's pre-image.
- **sysctl.** One aggregate `/etc/sysctl.d/90-hostcfg.conf`, rendered from every
  `sysctl:` stack, keys sorted, each with a `# <owner>: <comment>` line. Doctor warns when a
  lexically later file overrides a key (rev 1 finding A.3; G5).

### B.3 absent semantics per kind

| Kind | `state="absent"` (explicit) | Omitted from the request while `prune=true` | Runtime effect |
|---|---|---|---|
| file | owned file: delete. Unowned and present: refuse unless `takeover` (origin kept). Missing: no-op | withdraw: restore origin, or delete | none |
| unit | stop, disable, delete, `daemon-reload`, `reset-failed` | same | as stated |
| unit drop-in | delete the drop-in, `daemon-reload`, then the unit's `on_change` (`restart\|reload\|pending\|none`) | same | the restart, or a recorded pending |
| sysctl | push an `absent` layer. The key leaves the aggregate (or falls back to a lower layer) | pop the layer | **live value unchanged until reboot** (reported) unless the lower layer sets it and `apply_now` |
| group | drop this owner's hold. No `groupdel` without `--remove-groups` | same | never rolled back by revert |
| member | `members_absent=["u"]` → `gpasswd -d` (explicit deletion of a setting) | release the hold only | needs a new login |
| sysusers / tmpfiles | delete the owner's file | same | users and dirs already created stay (systemd never deletes them [K]) |
| endpoint | `withdraw` first, before any unit removal | same | new sessions lose the variables |
| json_key (HC-2) | push an `absent` layer: the key is deleted even if unowned (origin kept) | pop the layer | needs a dockerd restart: recorded `pending`, never done |
| check | n/a | n/a | read-only |

### B.4 Pipeline, idempotence, revert

1. **plan** (read-only, shared lock): observe → diff → ownership → problems; a `Plan` carries
   preconditions (sha256 or absence of each address read).
2. **apply(plan)** (exclusive lock): re-check preconditions (`StalePlan`) → stage into
   `txn/<id>/stage/` and validate there (`systemd-analyze verify --root` [V flag, systemd 257],
   rev 1 C.2 exec-check, `preflight` argv, `json.loads`, group constraints) → pre-images into
   `txn/<id>/pre/` → atomic writes (`_fs.atomic_write` [V `_fs.py:154`]) → post-actions once each
   (sysusers, tmpfiles, `daemon-reload`, sysctl, enable/start/restart, gpasswd) → verify →
   record `state.json` + `journal.json`.
3. **Failure**: stop and write `journal.json` (done / failed / not run). Exit 4 with the text
   `applied 3/7; failed: <step>: <why>; undo: hostcfg revert <id>; or fix and re-run apply`.
4. **Idempotence**: the second plan is all `noop`, so apply writes nothing, runs no action
   and creates no txn (exit 0).
5. **revert <txn>**: per file only if its sha256 equals the txn's post-image, else refuse and name
   the later txn (LIFO per file); restore pre-images and `state.json` entries; same post-action
   rules as apply; groups/memberships listed as irreversible; a revert is itself a txn.
6. **Retention**: last 50 txns. Origins live in `origins/` while any layer holds the address, so
   pruning a txn never loses an uninstall's restore value.

Under `--root`: `systemd-sysusers`/`-tmpfiles` run with `--root` ([V] locally: `systemd-sysusers
--root=<scratch> --dry-run` printed "Would write /etc/group" unprivileged); `systemctl`, `sysctl`,
`gpasswd`, `udevadm` are reported `skipped(root)`. Fake roots, no timing: tests are host-load independent.

### B.5 Library API (service-installer view)

```python
from cli_extended import hostcfg as hc
req = hc.Request(owner="cgprofile", writer=f"cgprofiled install {ver}", prune=True, resources=(
    hc.Group("cgprofile-control", level=True, not_gid_of=("docker",), not_gid=(0,), members_add=tuple(users)),
    hc.Unit("cgprofile-control.socket", text=socket_text, enable=True, on_change="restart"),
    hc.Unit("cgprofiled.service", text=unit_text, enable=True, on_change="restart",
            preflight=(bin_path, "config", "check", "--config", cfg)),
    hc.Endpoint({"CGPROFILE_CONTROL_SOCKET": sock, "CGPROFILE_CONTROL_GID": hc.gid_of("cgprofile-control")}),
))
plan: hc.Plan = hc.plan(req, root="/")       # never writes; Plan.changes, .problems, .render(), .as_dict()
if args.dry_run: print(plan.render()); return 10 if plan.has_changes else 0
result: hc.Result = hc.apply(plan)           # Result.txn, .changed, .actions, .pending
hc.remove("cgprofile", remove_groups=False)  # = plan+apply of an empty request with prune
hc.revert("20261108T101500Z-3f2a")           # -> Result
problems: list[hc.Problem] = hc.doctor(owner="cgprofile")
req2 = hc.load_request(path)                 # TOML -> Request; Request.to_toml() for --print-request
```

| Error | When | CLI exit |
|---|---|---|
| `ValueError` | bad Request construction (programmer error) | 2 |
| `hc.PlanRefused(CliFailure)` with `.problems: list[Problem]` | ownership conflict, unowned file without takeover, validation | 2 |
| `hc.StalePlan(CliFailure)` | preconditions changed between plan and apply | 2 |
| `hc.ApplyFailed(CliFailure)` with `.txn`, `.done`, `.failed`, `.remedy` | partway failure, nothing undone | 4 |
| doctor findings | drift, shadowed keys, pending restarts, foreign files in managed dirs | 1 |

- `Problem` is the existing dataclass (`code`/`message`/`path`/`owner`/`key`)
  [V `hostcfg/__init__.py:20-58`].
- Internal resource protocol, frozen in HC-1a so HC-1b can work in parallel:
  `kind`, `addresses()`, `observe(ctx)`, `diff(ctx, observed) -> list[Change]`,
  `stage(ctx, change)`, `commit(ctx, staged)`, `post_actions(changes)`, `verify(ctx)`.

## F. Known issues and by-design behaviour

1. **No automatic rollback.** A failed apply leaves the host part-applied; the journal names what
   was done; the operator runs `revert <txn>` or fixes the cause and re-runs `apply`.
2. Restarts requested by `on_change` happen during apply; a later failure does not undo them.
3. Revert is LIFO per file (refuses a file changed by a later txn, naming it), never removes
   groups or memberships, and never resets runtime state (live sysctl values, tmpfiles-made dirs,
   running sessions' environments). Removing a sysctl key leaves the live value until reboot.
4. sysctl aggregate `90-hostcfg.conf` loses to lexically later files (`99-vbpub-swap.conf`);
   doctor warns, does not fix.
5. In-place keys are last-writer-wins: a shadowed layer is silent at apply, visible in
   `show --history` and doctor. No per-key `refuse|warn` knob (the HANDOFF:151 note is superseded
   by the 2026-11-08 rulings). Hand edits are drift: reported, overwritten by the next apply, kept
   in the txn pre-image.
6. **daemon.json has a writer outside hostcfg** (div2): profile step order serialises them, no
   shared lock. Every daemon.json change is `pending` until a human restarts dockerd.
7. fstab, `authorized_keys`, `.bashrc` and apt sources stay div2 code paths (bootstrap and
   partition owner).
8. No Augeas: in-place edits of non-JSON foreign files without a drop-in directory are
   unsupported until the §D.3 trigger fires.
9. Txn retention 50; reverting a pruned txn is refused; origins kept while any layer holds them.
10. One host-wide flock (a second run blocks, printing the holder's pid); local only, no remote mode.
11. Post-actions are skipped under `--root`; only VM lanes exercise `systemctl`/`gpasswd`/`sysctl`/udev.
12. Group and endpoint changes reach users only after a new login (and a VS Code server restart).
13. `create_only` files are never updated (doctor shows the diff to the shipped content).
14. No legacy layouts, no migrations; a foreign pre-existing whole file is refused unless `takeover`.
