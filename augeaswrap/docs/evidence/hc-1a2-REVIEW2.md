## (2) B2/B3: revert contract, registry, follow-on kinds

- **Contract is implementable from outside the engine.** I wrote a toy non-`file` kind (`sysctlish`, in
  `<controller-scratch>/rv-hc1a2/probe/toy.py`) that registers one `KindSpec(parse, to_toml, revert=RevertHooks(snapshot, restore))` and
  uses only `augeaswrap._fs`, `Change`, `PostAction`, `Problem` and `kinds.require_keys`. Result: plan prints the change and
  `plan --json` has `revertible: true`; apply writes; `Request.to_toml()` round-trips through `load_request`; `preview_revert`
  and `revert` restore the old content and replay the recorded `sysctl -p` post-action; absent->absent restore removes the file;
  a second revert is refused ("already reverted"); a revert of the first of two later-touched addresses is refused naming the
  later txn. So unit, sysctl, sysusers/tmpfiles, endpoint, json_key and edit can each add one module with a snapshot/restore pair
  and `revert=None` where the effect is not file content. The only friction is conceptual, not a defect: `restore.observe` must
  return the same observation shape that `commit` returns (SPEC says so), and file-backed kinds have to reuse `file`'s private
  `_snapshot`-style helpers or write their own (`_fs` is the shared public-in-practice module).
- **`plan` states `revert: unsupported` before apply**: `render_plan` prints it for each *changed* address of a kind with no hooks or
  no registration (`engine.py` render loop), `plan --json` has `"revertible"`; a later `revert` of such a txn refuses with
  `revert.unsupported`. Mutants N6e/N6f/N6g (below) all killed.
- **Registry from TOML**: the loader only resolves names that are registered (`allowed = {augeaswrap, writer, *registered}`), and
  each `[[kind]]` is typed strictly. Probed `[[File]]` (unregistered case variant), `[[file.x]]`, `["a.b"]`, `[[__proto__]]`,
  `[[a.b]]`: all refused (`unknown request key`, `must be an array of tables`). A TOML file cannot reach a parser it did not name,
  and cannot register anything.
- **`register_kind` name validation is thin (finding R1, non-blocking).** It refuses empty, non-string, `writer`, `augeaswrap` and
  exact duplicates, but not case variants, dots, spaces, quotes, newlines, brackets or length. Probed: `FILE`, `File`, `a.b`,
  `has space`, `x]]\n[[file`, `q"q`, `check ` (trailing space), a 500-char name all registered. `request_to_toml` writes
  `[[{kind}]]` raw, so a kind named `x]]\n[[file` emits an injected `[[file]]` table and `a.b` emits a nested table the loader
  cannot read back. Not reachable from a request file (names come from code that imports a module), and the tests' title
  "names_are_validated" only covers the empty/reserved/non-string cases, so this is an overstated claim rather than an open hole.
  Fix: `re.fullmatch(r"[a-z][a-z0-9_]{0,31}", kind)` in `register_kind` (and compare names case-insensitively for duplicates), one
  test with `a.b`, `File`, `x]]`.
- **Revert behaviour unchanged for `file`**: content, mode (0640) and absent->absent restored, owner passed to `fchown` (mutants S2/S3
  killed), stale revert, double revert, tampered/injected ids refused (re-ran the round-1 scenarios: all as before; full suite
  includes them).

## (4) Non-blocking items: fixed or honestly deferred

Checked against the code, not only the report. Fixed and verified: NB1 interrupt (`BaseException` caught, status `interrupted`,
revertible, valid later-status, SIGTERM turned into `SystemExit` only on the main thread with the default handler, handler
restored: read `transactions.py` `_sigterm_as_exit` and the `run_steps` wrapper), NB2 wedged listing (skip + `RuntimeWarning`,
CLI prints a warning; a *present but unreadable* journal is still refused, correct), NB3 fingerprint = argv + exit code,
NB5 `stdin=DEVNULL` in validator/check/post-action (diffs read), NB6 chown-then-chmod (`_fs.py`), NB8 DEL escaped, NB12 CHANGES
lists the removed names, NB13 assay comments, NB15 plan/changes address check, NB17 only the state dir is private.
Deferred with reasons in SPEC and BACKLOG: NB4 root-bound journals, NB7 setuid bits and no size cap, NB9 post-action order
(documented as a deliberate difference from design B.4.6, `PostAction.phase` listed for HC-1b), NB10/NB11 limits, NB16 no lock
timeout. **The reasons are honest and none is a correctness defect on the evidence path** (these are limits of a root-only
tool, each documented). Remaining items worth stating plainly:

- **R2 (minor, deferred correctly but under-documented): a hard kill leaves `applying`, which `revert` refuses AND which still
  blocks the revert of earlier transactions on the same addresses** (`_later_transaction` treats `applying` as touching). SPEC and
  BACKLOG say only that revert refuses it. Add "and blocks earlier reverts of the same addresses until it is pruned (50 txns)" so an
  operator is not surprised. The pre-images stay on disk for a manual restore.
- **R3 (nit, reasoned, not reproduced): window in the interrupt handler.** `fail()` indexes `steps[step_index]`; an interrupt that
  lands after the last `finish_step()` incremented `step_index` to `len(steps)` and before `journal status = done` would raise
  `IndexError` inside the `except BaseException` block, masking the interruption and leaving `applying`. The window is a few
  bytecodes and harmless in effect (same as a hard kill), so not blocking; clamp the index (`min(step_index, len(steps)-1)`) when
  convenient.
- **R4 (nit):** `_prepare_revert` indexes `resource.observe(...)[address]` unguarded; a restore resource that violates the
  contract (observe without the address) surfaces as a raw `KeyError`. Wrap it in the same `ValueError` -> `revert.preimage.invalid`
  path. Contract violations by a kind author only.
