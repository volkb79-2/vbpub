# rigor-record backlog (RRK)

Entries use the id sequence `RRK-NN`. Check the highest existing id before adding one.

* **RRK-01 CLI (partly done in RR-2, RR-3).** FIXED for `assemble`, `render`, `check` (RR-2) and `sync`, `update` (RR-3): the `rigor-record` console script is built on `cli-extended` (`cli-extended>=0.3.0` runtime dependency; library modules stay stdlib-only). OPEN: `queue`, `base`, `adopt`, `note` arrive with RR-4 and GN-1 and register on the same registry.
* **RRK-09 R2 shapes `update` does not take yet.** Partly lifted in RR-2a: several R2 lanes in one update and 201-500 survivors (the fragment is the sidecar) are accepted; OPEN: (a) exactly one R2 lane per project (several R2 lanes and the `partial` status, dstdns until ciu v8); (b) more than 500 survivors (per-file counts need the assay sidecar list); (c) `deviations` are always empty (a config digest differing from the tag's needs the tag's file digests as an input); (d) an `error` campaign must still carry assay R2 candidate counts. Each refuses with a named cause instead of guessing.
* **RRK-10 transition table.** OPEN for review: `survivors -> pass` (every open survivor resolved by a later campaign, nothing waived) and `error -> {pass|survivors|incomplete|error}` are additions to memo 3.4's table; `update` fragments are refused on any final status, so a rerun after `survivors` is a later release's campaign marking `resolved_by`.
* **RRK-02 index schema.** FIXED in RR-2: `rigor-index-1.json` plus `golden/project/rigor/index.json`.
* **RRK-04 cli-extended surface lifecycle.** OPEN: cmru-style `[tool.cli-extended]` registration with a reviewed surface manifest (`docs/cli-surface.json`, review and findings files) is not set up for `rigor-record`; add it when the verb set is complete (after RR-4).
* **RRK-05 policy.toml scope.** FIXED in RR-2a: `policy.toml` and the `rigor-policy-1` schema are removed (the release sequence comes from the composite fragment, R2 lanes from `assemble --r2-lane`).
* **RRK-06 toolset components.** OPEN: `assemble` derives the assay, run-gate and tester-image components from fragments. Project-specific components (cgprofile daemon and contract versions) are not in any fragment; the pilot adoption (AD-cgroup-profiler) decides how they reach the record (extra input file or a producer-side fragment field).
* **RRK-07 online and commit checks.** The commit check is FIXED in RR-3 (`check --commits RANGE --repo R`). OPEN: `check --published` (published tags without a record) needs `gh` listing and arrives with RR-4/RR-5; it is deliberately absent from the offline `check`.
* **RRK-08 privacy config default location.** OPEN: the operator's host/user denylist is read only from `--privacy-config` or `$RIGOR_RECORD_PRIVACY_CONFIG`; with neither, only the built-in rules run. Decide whether a fixed per-user path should be read by default (a silent default is a hazard, an unset one silently weakens the lint).
* **RRK-03 assay outcome vocabulary.** The fragment `outcome` is the closed set `PASS | FAIL | ERROR`; A-1 (`assay analyze export`) maps assay's verdict outcomes onto it. If assay's real vocabulary needs more members, bump the fragment minor additively (new enum member is a meaning change: a hard cut per the SPEC versioning rule).
* **RRK-11 assay-only R2 fragment set.** FIXED in the review-fix pass: `update --fragments` refuses an assay R2 fragment without its run-gate half (no tool identity, machine class or perf would be recorded). Lifts when the run-gate fragment writer (RG-a) lands and a pair is always produced.
* **RRK-12 unreachable defensive branches.** OPEN: `update._r2_result` "no campaign times" and machine-class conflict refusals in `plan_r2`/`plan_qualification` are unreachable behind fragment schema validation; remove or cover them when the fragment schema is next revised.
* **RRK-13 `RepoGit.published` assumes pushed tags.** FIXED in the review-fix pass: a commit is published when it is reachable from `refs/remotes/origin/main` or from a tag that `git ls-remote --tags origin` reports (a local, unpushed tag is no evidence; no origin or an unreachable one is "not published"; a non-object-id is refused). `check --published` (RRK-07) stays the online listing of tags without a record.
* **RRK-14 generator for the project golden.** OPEN: `golden/project/` and `golden/records/` are produced by a scratchpad script (assemble + plan_r2/plan_reconcile/plan_qualification/plan_withdraw + render_views); commit the generator so the goldens are reproducible.
* **RRK-15 cmru inventory kind.** FIXED here (consumer side): `assemble --artifacts` accepts both `cmru-local-build` (`build.json`, `publication: eligible`) and `cmru-release-inventory` (what cmru's `record_step.write_inventory` hands over as `CMRU_BUILD_INVENTORY`: no `publication` key, a `tag` that must equal the release tag). OPEN, cmru side (not edited from this package): add one cross-package fixture test in cmru that feeds `write_inventory` output to `rigor-record assemble`.
* **RRK-16 untracked inputs.** FIXED (recorded, not dropped): a declared assay input git cannot resolve is stored in the result's `unresolved_inputs`; such a result is valid only at its own commit and cannot be attributed to another commit. OPEN: a content digest for link paths would let such a result carry across commits (needs an assay-side `inputs` digest, A-1a follow-up).
* **RRK-17 R0 of an unlabelled commit.** OPEN: an unlabelled commit has no release sequence of its own, so its R0 reads `not-judged`; a "newest sequence valid at that commit" rule needs a sequence identity that survives lane changes.
