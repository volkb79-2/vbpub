* **TP-12 leftover-children guard (P11 semantics).** FIXED 2026-11-24 (P-core-04a, 31e14e208; released in 0.1.0). Upstream the strongest of the estate's three test-descendant guards, `libraries/cli-extended/tests/conftest.py` (P11), into the plugin, replacing the snapshot-diff children part of `resource-leak`. Semantics: the pytest process is made a child subreaper (`PR_SET_CHILD_SUBREAPER`; abort loudly when `prctl` fails); direct children of the pytest process, zombies included, are recorded per test as `(pid, starttime)`; each new one is pinned by `pidfd_open`, re-checked (same parent, same start time), killed through `pidfd_send_signal` and reaped through `waitid(P_PIDFD)`, never by pid or name; the test FAILS even after the cleanup succeeded. Adopted in cli-extended (P-core-04, which deletes its own guard) and cmru (KI-195, which deletes `cmru/src/cmru/process_guard.py`). Source: .controller-state/design-review-2026-11-24/cmru-cli-extended.md H2/H5
* **TP-13 `requires_contained_cgroup` marker.** FIXED 2026-11-24 (P-core-04a, 31e14e208; released in 0.1.0). A test that signals or kills processes runs only when this process is contained. That means a finite effective cgroup v2 `memory.max` and `pids.max` (walked up the cgroup chain) AND a private PID namespace: every pid in `/proc` other than PID 1 lies in the subtree of the test's top-level ancestor under PID 1, that ancestor descends from PID 1 (not from a `docker exec`), with a settle re-scan, and `/proc` is not mounted `hidepid`. `/proc` and `/sys/fs/cgroup` roots are injectable; cgroup v1 and unreadable files refuse. The mode is `fail` (setup fails), `warn` (skipped with a distinctive reason) or `off` (inert); the body never runs when refused; there is no per-rule override. Host backstop caps count as finite. It relies on TP-12's pytest subreaper, so TP-12 lands with or before it. Projects carrying the marker set `estate_policy = fail` and `required_plugins = estate-test-policy` in their pytest ini config. No lane identity, image identity or allowlist. Contract and test oracle: `docs/DESIGN-CONTAINMENT-MARKER.md`. Supersedes RG-293. Source: .controller-state/design-review-2026-11-24/cmru-cli-extended.md H2/H5
* **TP-14 D-state child cleanup retries an unreaped identity (Minor). FIXED 2026-11-26.** An identity is `(pid, start_time)`; once reported unreaped it is excluded from later settle and cleanup passes. A reused pid with a new start time remains eligible.
* **TP-15 EACCES on a hidden child stat errors every teardown (Minor). FIXED 2026-11-26.** Under procfs `hidepid=1`, a process whose credentials differ can be unreadable, including our own child. On `EACCES`, `waitid(P_PID, ..., WEXITED|WNOHANG|WNOWAIT)` identifies our child, alive or waitable (fail loudly); `ECHILD` or `ESRCH` permits skipping; failure of that ownership check also fails loudly. Other stat errors keep their existing behavior. Under `hidepid=2`, another user's process directory is omitted from `/proc` enumeration, so an invisible child is not detected; see TP-19. See `README.md` and proc(5).
* **TP-16 PIDFD tests patch global `os.close` (Minor). FIXED 2026-11-26.** `PidfdOps` injects pidfd open and close operations for tests; unrelated descriptor closes are never intercepted.
* **TP-17 the installed wheel's entry point breaks this library's own suite, so the wheel is not in tester-unified (Minor, OPEN 2026-11-24).** With the wheel installed, the `estate_test_policy` pytest11 entry point registers the plugin at startup. This library's suite also loads it through `-p estate_test_policy.plugin`, so the plugin registers twice and the run fails. It is also imported before coverage starts, so the module-level lines go unmeasured (the same mechanism as TP-10(b)). For that reason tester-unified (P-core-05) does not install the wheel. Consumers load the plugin FROM SOURCE: their conftest puts `libraries/test-policy/src` on `sys.path`, sets `pytest_plugins = ["estate_test_policy.plugin"]`, and adds `-p no:estate_test_policy` to `addopts`, so an installed entry point can never register it a second time (cli-extended does this since P-core-04b; cmru does it with P-core-06). Needed: the plugin tolerates a second registration, or the library's own suite runs with `-p no:estate_test_policy` and a coverage start order that measures module-level lines. Then add the wheel to tester-unified and record the per-project mode in the image contract (TP-01, TP-10).
* **TP-18 `analyze_source` crashes on a method with column-0 string-literal lines (Minor). FIXED 2026-11-26.** The plugin selects the exact function by definition line, including nested classes and same-named methods, from a bounded 64-entry whole-source parse cache; fragment analysis has an `IndentationError` fallback that preserves multiline string and f-string contents. A missing function match is reported once; lambda test bodies remain unsupported. Existing ciu and cmru conftest shims stay until the release that consumes this fix.
* **TP-19 hidepid=2 hides a child from the `/proc` scan (Minor, OPEN 2026-11-27).** Under procfs `hidepid=2` or `hidepid=invisible`, another user's `/proc/<pid>` directory is absent from `/proc` enumeration. Since `direct_children` enumerates `/proc`, a child that becomes invisible is not detected. Investigate an alternate enumeration source, with `/proc/<pid>/task/<tid>/children` as a candidate; do not implement it as part of TP-15 without a verified ownership and visibility contract.
