* **TP-07 flakehunt follow-ups.** KNOWN GAP: order and shared-state dependence is neither flagged by the plugin nor found by flakehunt. A test that passes only in file order is "stable" when the whole file runs and fails with exit 1 when run alone, which looks like a deterministic failure. Needed: an `order-shared` profile (random order seeds, xdist, each failing test alone), a `none` baseline so a one-run failure can be told from a stress-induced one, per-test-id x profile counts across several selections, `--pass-m` default per profile.
* **TP-08 cli-extended adoption.** `flakehunt` is plain argparse with ad hoc printing and exit codes, deliberately stdlib-only for now. Estate convention (iobench, rigor-record, cmru) is a cli-extended shell; adopting it makes the wheel require `cli-extended`, adds the orchestration edge (`depends_on = ["cli-extended"]`, level L1) and the release-notes install line, and gives `--json`/`--help` conventions. Decide with the cli-extended adoption program.
* **TP-09 plugin detection misses (quiet false negatives, documented in README Limits).** Aliased clock imports (`from time import perf_counter as pc`; `d = pc() - t; assert d < .05`) and `datetime.now()`/`datetime.utcnow()` deltas are not recognised by the `wall-time-assert` rule (`policy._is_clock_call` matches only `time.<name>` and bare `<name>`). Needed: import-alias resolution for the clock names and `datetime` clock calls; keep the TP-04 helper-call and `/proc` rules in the same pass.

Needed: a coverage start order that works with the plugin, markers with this backlog id, then enable it.
