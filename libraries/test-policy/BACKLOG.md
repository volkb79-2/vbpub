* **TP-07 flakehunt follow-ups.** KNOWN GAP: order and shared-state dependence is neither flagged by the plugin nor found by flakehunt. A test that passes only in file order is "stable" when the whole file runs and fails with exit 1 when run alone, which looks like a deterministic failure. Needed: an `order-shared` profile (random order seeds, xdist, each failing test alone), a `none` baseline so a one-run failure can be told from a stress-induced one, per-test-id x profile counts across several selections, `--pass-m` default per profile.

Estate convention (iobench, rigor-record, cmru) is a cli-extended shell; adopting it makes the wheel require `cli-extended`, adds the orchestration edge (`depends_on = ["cli-extended"]`, level L1) and the release-notes install line, and gives `--json`/`--help` conventions. * **TP-09 plugin detection misses (quiet false negatives, documented in README Limits).** Aliased clock imports (`from time import perf_counter as pc`; `d = pc() - t; assert d < .05`) and `datetime.now()`/`datetime.utcnow()` deltas are not recognised by the `wall-time-assert` rule (`policy._is_clock_call` matches only `time.<name>` and bare `<name>`). Needed: import-alias resolution for the clock names and `datetime` clock calls; keep the TP-04 helper-call and `/proc` rules in the same pass.
* **TP-10 plugin rollout and self-hosting.** (a) The wheel enables `--estate-policy=fail` for every test in an image that installs it; the image contract needs an explicit per-project mode or opt-in. Decided 2026-11-24 (amended): the entry point defaults to `off`; a project opts in through its `pytest.ini` (ini `estate_policy`, and the CLI `--estate-policy` overrides it), so installing the wheel into an image changes nothing for a project that has not opted in. (b) The library's own tests do not run under its own plugin: `-p estate_test_policy.plugin` in `addopts` imports it before coverage starts (module-level lines unmeasured) and the policy tests carry `timeout N` literals as test data that need `estate_allow` markers. Needed: a coverage start order that works with the plugin, markers with this backlog id, then enable it.
* **TP-11 live validation of the remaining recipes.** Only `slow-cpu` (container mode) has been validated against real docker. `cpu-contended` container mode (lane and stressor pinned to cpuset 0, which must be inside the cpuset the parent slice allows), `slow-disk`, `mem-pressure` (separate stressor container: host/slice level pressure, not pressure inside the lane cgroup) and `combo` are covered by the fake runner and the dry-run plan only. Validate each on a test host, or mark it experimental in the README until then. Also: heavy-swap and OOM start/stop signals are not read by the PSI gate (memory some and io full only).
* **TP-12 leftover-children guard (P11 semantics).** Upstream the strongest of the estate's three test-descendant guards, `libraries/cli-extended/tests/conftest.py` (P11), into the plugin, replacing the snapshot-diff children part of `resource-leak`. Semantics: the pytest process is made a child subreaper (`PR_SET_CHILD_SUBREAPER`; abort loudly when `prctl` fails); direct children of the pytest process, zombies included, are recorded per test as `(pid, starttime)`; each new one is pinned by `pidfd_open`, re-checked (same parent, same start time), killed through `pidfd_send_signal` and reaped through `waitid(P_PIDFD)`, never by pid or name; the test FAILS even after the cleanup succeeded. Adopted in cli-extended (P-core-04, which deletes its own guard) and cmru (KI-195, which deletes `cmru/src/cmru/process_guard.py`). Source: .controller-state/design-review-2026-11-24/cmru-cli-extended.md H2/H5
* **TP-13 `requires_contained_cgroup` marker.** A test that signals or kills processes runs only when this process is contained. That means a finite effective cgroup v2 `memory.max` and `pids.max` (walked up the cgroup chain) AND a private PID namespace: every pid in `/proc` other than PID 1 lies in the subtree of the test's top-level ancestor under PID 1, that ancestor descends from PID 1 (not from a `docker exec`), with a settle re-scan, and `/proc` is not mounted `hidepid`. `/proc` and `/sys/fs/cgroup` roots are injectable; cgroup v1 and unreadable files refuse. The mode is `fail` (setup fails), `warn` (skipped) or `off` (inert); the body never runs when refused. No lane identity, image identity or allowlist. Contract and test oracle: `docs/DESIGN-CONTAINMENT-MARKER.md`. Supersedes RG-293. Source: .controller-state/design-review-2026-11-24/cmru-cli-extended.md H2/H5
